# 三套参数工作流独立草稿

这组草稿保留 FireWorksLab 已认可的蓝灰/青绿主题和库、画布、检视器的大布局，比较三种参数组织方式。它们不是正式项目替换版，不迁移、覆盖或清理旧稿和原配方。

## 入口

先从仓库根目录运行本机 HTTP 预检：

```powershell
python -X utf8 tool/local_http/preflight.py --tool baker --start
```

确认返回服务对应当前 F 盘副本，再打开 [三套方案比较入口](http://127.0.0.1:8034/design-system/drafts/v4-workflows-20261029/review.html)。不要用身份不明的旧服务替代本次验证。

| 方案 | 可操作页面 | 信息组织 | 主要取舍 |
| --- | --- | --- | --- |
| A · 连续检视 | [a.html](a.html) | 沿模块连续阅读和调整 | 模块关系容易接续，纵向滚动较长 |
| B · 分组聚焦 | [b.html](b.html) | 外形、运动、光色、输出分组 | 当前任务集中，跨组联调需要切换 |
| C · 参数对照 | [c.html](c.html) | 原值、当前值、状态并列 | 便于核对改动，连续编辑多一次定位 |

**本轮推荐 B · 分组聚焦，待用户选择。** 这是本轮设计判断与AI自检后的推荐，不代表用户已认可。保留的 [V3 原稿](../v3-unified/demo.html) 可随时对照。

比较页截图使用 `screenshots/a-1920.png`、`b-1920.png`、`c-1920.png`，只展示各页面的实际截图。缺图时明确显示“待生成”，不使用生成图或模拟窗口冒充真实页面。

## 真实数据与可操作边界

- 40 个代表字段来自 GLB-S1「金曜菊-B · 疏点游闪」第 2 层金锦的原配方、生产 SCHEMA 和命名表；默认值、单位与原字段 ID 保留。[parameters.json](parameters.json) 内保存完整原 P/M 及三层上下文。
- 金锦层可以编辑。橙引线层、点灭星使用各自真实原值，只读但可单独观察；不会把金锦的当前值套在其他层上。整体入口用于层次概览，不创建虚构全局参数。
- 外形、运动、光色、输出是草稿中的任务分组，原“层 → 发射器 → 模块”归属仍可追溯。四组不改变参数物理含义。
- 每米火花数与每秒密度分别保留，在相应生成方式下生效。星头亮度为 0 时，星头大小显示无效原因；用户可以通过原星头亮度字段启用，草稿不会自动开灯。
- 常用滑杆区间与合法边界分开。原 SCHEMA 的 `min/max/step`用于常用拖动范围；未知硬边界标为 `null`，不能把手输值静默夹到滑杆边缘。
- 原引擎预览显示当前观察的单层，金锦可编辑，另两层只读但可单独观察；按该层自身秒数运行。内部画布固定540×540、DPR1，窗口变化仅CSS等比缩放；这是实时参考解析度，不是烘焙单格。例如原组合中金锦层 `rate=1.5`，本轮没有据此假装整朵三层同步。
- 输出字段属于待烘焙配置。当前没有真正烘焙、贴图流转、引擎回放、素材导出、目录交付或 UE 写入；不能把草稿保存或预览成功显示为素材包已更新。

交付预检在预览旁显示约 320 px 的窄清单，进入时收起参数栏，关闭后返回原编辑上下文。手机与短高窗口使用效果库、预览、结构、参数、交付窗格切换；这些是草稿界面组织，交付区不会执行真实烘焙或 UE 操作。

建议用同一个任务比较三套方案：选金锦层，把颗粒大小从 0.75 改到 1.5 m，拖到本层 2.3 s，观察变化，再找到改动并撤销。继续核对跨组/跨层接续、保存与刷新后的恢复。以上是比较体验的统一路径；实际检查范围与结果见本轮QA报告。

## 预览连接

[engine-bridge.js](engine-bridge.js) 在 `sandbox="allow-scripts"` 的 opaque-origin iframe中加载原本机烘焙器的内存副本，调用原 `resolve`、`importParams`、`thumbNow` 和实时渲染核。没有自制近似烟花模拟器。

父页与沙箱不共用生产存储；沙箱使用内存 storage、禁用网络/目录能力，并校验 nonce、消息来源与 origin。它不使用用户浏览器 profile，不访问个人生产页存档。桥接仅在已经预检的8034本机草稿入口运行。host需可见且有宽高；不可 `display:none` 或放到视口外，否则浏览器可能暂停帧循环。

桥接的实际能力、软件渲染卡顿限制和隔离测试证据见 [engine-notes.md](engine-notes.md)。三套整页可用性、无障碍与用户认可，不能由这份独立桥接测试推定为通过。

## 本轮共用改进

- 观察内容只在画布上方的选择器调整；树上层名负责编辑、眼睛负责草稿输出。去掉重复的靶心入口，保留单层观察能力。
- 交付清单留在预览旁约320px的窄栏；短高/窄屏用窗格切换。进入与返回继续保留编辑上下文。
- B的参数行从初轮约175px收敛至约81px，简化可见路径和标签，保留完整字段、单位、条件与帮助。三方案继续共享同一套数据和能力。
- 真实核改为固定540×540内部目标、按需绘制与相同参数去重；GPU失效及时反馈，保持错误状态并允许手动重试，避免坏图仍被描述为实时预览。

设计原则见 [design-language.md](design-language.md)。[同尺度参数面板对照](screenshots/inspector-comparison.png) 比较三种信息密度；同视口的B方案前后迭代图见 [design-qa.md](design-qa.md) 引用的结果证据。缺图时比较入口明确提示等待，不用示意图替代。

## 参考原则与适配判断

资料核对日期：2026-10-29。借鉴官方行为原则，不直接套用其配色、圆角或组件包；本项目的既定画风与参数宪章优先。

- [Spectrum Slider](https://spectrum.adobe.com/web/rsp/components/slider)：参考快速拖动与精确输入的组合，保留清楚标签及不可用状态。本项目另明确常用滑杆区间，避免将其误当原业务硬界。
- [Spectrum Number field](https://opensource.adobe.com/spectrum-web-components/components/number-field/)：参考数字输入、可选步进与键盘调整；物理单位继续单独可读，长标签允许换行。
- [Fluent Toolbar](https://fluent2.microsoft.design/components/web/react/core/toolbar/usage)：参考相关动作归组、清楚名称与空间不足时的溢出组织；草稿的保存作用范围须与画布操作区分。
- [Carbon Forms](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)：参考字段对齐、持久标签、帮助/错误及只读状态；本项目不为追求固定行高而挤掉中文名称与单位。
- [Carbon Number input](https://www.carbondesignsystem.com/building-blocks/core/components/number-input/guidelines)：参考小步增减与输入状态；大范围连续物理量仍允许精确手输，不强制反复点击步进。

A/B/C 的取舍是本轮对制作任务的设计判断，不能由引用官方资料就推定设计适合、无障碍达标或用户验收通过。

参数分组与条件审查见 [workflow-audit.md](workflow-audit.md)。
