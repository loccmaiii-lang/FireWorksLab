# 烘焙器改动记录

## 4.2.16 · 按需烘焙：自动烘焙开关、烘焙可中断、收紧取景只在手动烘 / 导出（2026-10-03，对话框2）

- 用户 10-03 12:27 #1「现在每动一个参数，就自动重新渲染一次，特别影响效率」，12:59「abc 一起做，d 不用」。以前：停手 0.38 s 整条序列烘一遍，再停 0.7 s 收紧取景再烘一遍，烘的过程不能中断（中途又改要等烘完再烘），连续调参会排着烘 2–3 次。
- **A 自动烘焙开关**（工具栏「烘焙」按钮旁的「自动」，记在浏览器里，默认关）：关 = 改参数只更新实时模拟，贴图标「旧」（按钮变成琥珀色「烘焙 ●」；引擎回放 / 贴图视图上方出横条「贴图还是旧参数」）；按 **B**、点「烘焙」、切到引擎回放 / 贴图、导出时才烘。打开效果 / 换版本 / 恢复 / 导入照常烘。开 = 和以前一样停手自动烘（但不收紧，见 C）。
- **B 烘焙可中断**：烘到一半参数又变了，这次在下一个进度点直接作废（`BAKE_ABORT`，不算失败、不弹错），按最新参数接着烘；`bakeFrames` 作废时放掉三张工作贴图。手动烘「烘到最新为止」：烘的时候又改了，接着烘到最新。
- **C 收紧取景只在手动烘、打开效果、导出时做**：手动烘一次就把收紧做完，引擎回放看到的就是导出的样子；自动烘只烘预览。
- 多层导出（`comboLayerBakes`）先把攒着的改动烘完（`bakeFlush`），不会拿旧贴图；每层记 `bakeRev`（贴图对应的参数版本）判断旧不旧。
- 自动化（Playwright，`navigator.webdriver`）和 node 检查默认自动烘焙开：本机任务、检查脚本按「打开 → 等烘完」走，不受影响；网址 `?autobake=0 / 1` 可强制。
- 顺手修：多层里对一层点「恢复到打开时」，被接力带动的另一层（引线火花停 = 锦点火）也跟着回去（10-03 复现：以前第 2 层的延时点火停在被带动的位置）。
- **检查**（先写后修）：`界面状态检查.py` K1（假烘焙：关时改参数不烘、标旧、实时模拟视图不出横条；切到引擎回放烘一次并收紧；引擎回放里改参数出横条；按 B 烘到最新；开时烘到一半又改 → 作废一次、只完整烘一次、不收紧；多层关时改一层不烘、导出拿到新参数；开关记住）、K2（真烘焙，只在 --real：本机 SMOKE13）、R1（恢复带上接力层）。改之前 K1、R1 都不过。其余 A1–A7、P1、U1、B1、V1、X1、G1 照旧全过。

## 4.2.15 · 光点按模拟里每颗星来定：只出会亮的星、出生在亮起那一刻、分布对上；光点大小 / 亮度可调（2026-10-03，对话框2，XD2 试导）

- XD2（鸿巢红点层 PC 光点，4.2.14）烘焙回放：红点比实时模拟早 0.5–1 s 出现，9.32 s 时又密、又大、又亮、球也偏大。查下来四个原因：
  1. 红点层 `keepFrac 0.2`（800 颗里只有 160 颗会亮），光点出了 800 颗；
  2. 轨迹拟合的是「星的最远半径」，光点都放在外壳上（中位距离大 26%）；
  3. 亮起时刻按「时刻 ÷ 寿命」平均被抹开（早亮）；
  4. 光点直径 × 1.7、亮度按中位数归一（点灭星的亮灭平均被抵掉）。
- **现在 `dotVis` 跑一遍模拟（步长 × 4，差 < 1%），每颗星记第一次亮 a、最后亮着 b、亮起那一刻的位置 / 速度**：
  - 个数 = 会亮的星数；按亮起时刻分 ≤ 5 批出生（Burst 列表），层延迟 = 第一批；寿命 = b − a（10%–90% 分位）；
  - 出生位置 = 球面，半径取亮起时相对整体中心的半径（均值 ± √3σ 均匀 → `StartRadius` 随机范围）；速度 = 半径 × `VelocityScale`；整体的下坠和下坠速度写进 `InitialLocation` / `InitialVelocity`；
  - 之后的运动：按「亮起后的时间」对齐，平均半径和中心高度拟合成线性阻力 + 等效重力，外扩速度也按最小二乘取（照搬亮起时的速度，在平方阻力的高速段会前段偏大 15%）；
  - 亮度 = 星头亮度 ÷ 标称亮度，按相对寿命平均：点灭星按亮灭平均（光点不会闪，总亮度和模拟一致）。
  - 结果按参数缓存（改光点大小 / 亮度、层的位置不重跑）；`dotFit`（拟合最远半径）删了。
- **层页头「导出方案」选光点时多两根滑杆**：光点大小（× 炭头，默认 1，以前固定 1.7）、光点亮度（×，默认 1）；改回 1 时层里不留字段（没动过的层和以前逐字一样）。
- 层页头 / 交付页的光点个数改成「约 N 颗」（星数 × keepFrac；炭头亮度 0 → 0 颗，并提示「星头不发光，光点什么都出不来」——引菊 → 锦两层就是这样）。
- 粒子发射器组（46_emitset.js）：`sphere.r` 可以是 `[lo, hi]`，`sphere.vs` = VelocityScale（和 Cascade 一样速度 = 半径 × vs）；修了出生位置曲线只有一个键时被球面偏移就地改坏的问题（`esCurve` 返回的是键本身）。
- `spec/cascade_params_v1.md` 10.F 按上面改写。版本指纹（`OUTPUT_VER`）不变：目前没有条目用光点方案。
- **检查**（先写后修）：`combo_pack_check.mjs` 三个光点用例（牡丹主段、第二段、鸿巢红点层）逐时刻比「模拟里亮着的星 vs 光点出生表」——个数 ±15%、离爆点距离中位数 / 90 分位 ±10%、平均高度 ±（10% 半径 + 2.5 倍抽样误差）、总亮度 ±30%；红点层再查缩放 / 倍率换算。改之前三个都不过（距离差 26%、个数 800 vs 131）。`界面状态检查.py` X1 加光点大小 / 亮度（只在选光点时出现、改了导出跟着变、改回 1 不留字段）和「光点个数 = 模拟里会亮的星」。
- 排 XD3（鸿巢红点层 PC 光点，4.2.15）在本机再试导。

## 4.2.11 · 收紧取景的碰边判据和回放检查一致（2026-10-03，对话框2）

- QN11E6（4.2.9 导出）尾层还是末帧碰内圈 21.6%，产物和 E5 完全一样：4.2.8 的复查没触发。原因：回放检查的「留边」是**每张贴图里所有帧都为 0 的最外圈数（最多 8）**，「内圈」是再往里两圈——不是烘焙器的格子留边。默认格子留边 2 像素时，收紧给内容留的边约 9 像素，正好在回放检查的第 8–9 圈；几乎全黑的末帧只剩几颗暗点就在那一圈。4.2.8 按格子留边（第 2–3 圈）量，看不到。

- 没碰边的效果产物不变（只有原来会不过回放检查的才重算），大面片输出版本仍是 4.2.7。
- **检查**：`motion_plan_check.mjs` 加「碰边判据和回放检查一致」（留边按每张贴图量、最多 8、内圈两圈；只有几乎全黑的末帧被判；`edgePx` 12 时 512 格离边 ≥ 12 像素）。云端真烘焙试了「第一次复查假装碰边」的路径：重算后取景放宽、内圈占比 < 0.5%。
