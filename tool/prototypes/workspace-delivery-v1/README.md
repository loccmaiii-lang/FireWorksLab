# 烘焙器交付与导入草稿 v1

用户 2026-10-10 要求一版草稿：解释“时长收口”“配表”，并翻新合并后需要整页滚动才能导入的界面。

本稿是独立、可点击的布局与状态演示，生产仍为 4.9.60。只在内存操作，无 UE 调用、无文件/配表写入、无生产存储改动。唯一宪章仍是 `协作/交互宪章.md`，直接消费 `tool/design-system/` v0.1.0 的 tokens、组件与离线 Tabler 图标。

从仓库根目录运行 Python 静态服务后访问 `/tool/prototypes/workspace-delivery-v1/`；当前预览 `http://127.0.0.1:8035/tool/prototypes/workspace-delivery-v1/`。直接打开 index.html 也可演示，相对共享文件需保留。

## 布局为什么这样改

当前生产交付区在1280×720下内容高度977px，内部又嵌入640px导入页，两套头部/身份/导航挤占首屏，资产区也有局部滚动。固定整个工作区高度、单一工具身份/资源上下文/流程提示即可给业务区留出稳定空间。

| 区域 | 草稿安排 | 沿用原导入器的能力 |
| --- | --- | --- |
| 顶部 | 工具身份、制作/交付、当前固定修订、目录入口 | 当前对象/版本保持；目录不每次重填 |
| 左栏 | 同修订缩略图、PC/手机包、选择、历史修订 | 批次队列、平台选择、外部资源接入、GPU待办 |
| 中栏 | 当前包命名/处理方式/粒子设置/时长/登记说明 | 新建/同名更新，系统与GPU设置；变更作废确认 |
| 右栏 | 当前包逐资产清单与去重/依赖/覆盖说明 | 勾选、目标、真实动作计划、名称冲突、复用/跳过 |
| 底部 | 选中范围、检查/确认状态、检查、确认、导入/包间停止 | 用户点击才执行，部分完成保留，重试失败包 |
| 操作记录 | 常驻最新一条，展开区域在动作栏上方 | 日志可读，不遮住按钮、不抢阅读滚动 |

三栏各自局部滚动，常驻区域占真实空间。窄屏切换队列/设置/清单窗格，不改变对象或确认；详细目录、时间口径、资源登记通过可关闭详情展示。保持可读字体和点击尺寸，避免只靠缩小控件解决首屏问题。

## “时长收口”具体指什么

实际修订 `3c9894a05bfe46574643` 的源配方 duration=5.5，trimTail=1，cutIn=cutOut=0；PC/手机母版 t0=0、duration=4.8333333333；两份 Cascade 发射器 delay_s=0、duration_s/Lifetime=4.8333。尾部全黑帧裁除在 `50_bake.js` 中按实际编码图判定并重新分帧；最后一帧采样4.7s不是整段结束时间。

这三个口径不能混用：

1. **制作设定** 5.500s：制作时间轴范围，继续保留，不为元数据一致而改效果。
2. **最终产物区间** 当前两平台均0–4.8333s：编排预览占用与资源引用需读取同修订的最终配置/母版。新索引应分别记录PC/手机起止、裁帧偏移及时间来源。
3. **演出锚点**：发射、开花和结束分别标记；根据最终层延迟/倍率对齐，必要时以UE实播核对，不靠资源名推算。

单层有限序列可按最终 t0+duration核对；多层要核对各层真实输出的起止、延迟和倍率；GPU持续发射还涉及最后出生时间与寿命；循环需标“循环/需停止条件”，不能统一用一个Required.Duration替代可见占用时长。

**生产剩余工作：** 旧回执 metadata.duration 仍是5.5，编排适配在缺artifactDuration时会回退到它；新导出已有单值artifactDuration，但尚未分别校验全部平台/多层/循环。下一轮从最终发布包生成分平台时间元数据，编排消费一致，并记录缺字段/估算/实播状态。不可变旧修订不原地改写；用可追踪的补充解释或新索引版本迁移。此草稿的4.833是只读核对结果，不表示生产已修复。

## “配表”换成用户能理解的话

就是**演出资源登记**：演出或蓝图使用稳定ID，经ResourceFX记录找到实际PC/手机粒子资产，并带上工程要求的尺度、延迟、生命周期等字段。导入只创建资产，不自动保证演出能找到它；表字段的含义必须按当前蓝图契约核对，不能把资源产物时长随意写进同名字段。

现有目录例子：`P_EFX_FireWorks_Small_Yellow` 对应既有“小_Yellow”的两平台路径。它不是新金芒菊的登记。当前编排输入只是检查英文ID格式，尚未对登记行与真实新资产完成读回核对；不能用任意既有行名顶替。

建议后续：真实导入回执成功→读取实际PC/手机资产→准备新建/更新登记方案→用户核对资源名/平台/固定修订与范围→写表并读回→编排引用固定修订→UE实播。界面优先显示中文资源名，技术ID/完整路径放详情；“准备方案”“已登记”“已实播”分别标记。本稿候选`FWL_GoldChrysanthemum`只是演示，未写表。

## 草稿可以怎样检查

- 默认检查通过待确认：PC确认后自动看手机；两包确认后导入按钮可用。
- 修改名称、处理方式、资产或平台选择使确认失效；取消依赖项会取消引用它的粒子，共用项同步。
- 顶栏“状态演示”可切未检查、冲突、UE离线、部分完成与执行失败。
- 模拟执行可在包间停止；失败仅重试未完成包。改变完成后的方案会保留旧日志，但重新检查新方案。
- 时长、目标目录、系统设置与演出资源登记详情可展开；日志/提示放在动作栏上方。

外部目录读取、历史修订真正切入、原导入器全部系统/GPU字段、保存恢复和原执行接线仍属生产翻新；草稿为它们保留位置与解释，没有宣称全部原功能已搬入此原型。
