## 2. 命名

- PC 粒子：`P_EFX_FireWorks_<名>_HD`（现状，不改）。
- 手游粒子：`P_EFX_FireWorks_<名>_H` / `_M` 👤。
  - `<名>` 和 PC 粒子名相同，例如 `RiseTrail_L_H`、`GoldSpark_M` 👤。
  - 不带 `_HD` / `_Mobile`；**不做 `_L`** 👤。
- 手游材质实例：PC 名去掉 `_HD`（`MI_EFX_FireWorks_<名>_<段>_01`），`_H` 和 `_M` 共用 👤。
- 贴图：烘焙器 10-02 规则不变。
  - PC 序列带 `_HD`；手游序列不带 `_HD`，`_H` 和 `_M` 共用。
  - `_C` / `_R` / `_D` 端手共用一张 👤。
- 派生资源（例如主角尾缀之于 L 尾缀）**不新开贴图**，直接引用原资源的那一套 👤。
- 注意：粒子名和表里的 ResourceId 不一定对得上，以 PC 表为准 ✅。例如：
  - 「金芒菊」行 ResourceId `GoldRayChry` → 粒子 `GoldSpark_HD`；
  - 「金锦菊」行 ResourceId `GoldSpark` → 粒子 `GoldRay_HD`；
  - 「点灭星」行 → 粒子 `GreenPeony_HD`。

  手游粒子按 **PC 粒子名**起名，手游表按 **ResourceId** 对行。

## 6. 档位与预算

- 手游粒子**不能有 LOD**：`LODDistances` 只有 1 项，每个发射器只有 1 个 LOD 👤✅。
- 发射器数（只算 LOD0 启用的）：
  - `_M` ≤ 3 👤（2.0 的 `_M` 都是 3 ✅）；
  - `_H` 上限 ❓（2.0 烟花类 `_H` 是 4–6，道具类最多 16 ✅）。暂按 ≤ 6，用户改。
- 关着的发射器在手游资产里直接删掉，不留。
- 不能有 GPU 发射器 ✅；每个发射器同时活着的粒子 ≤ 50（宪章 §5）。
- 烟花中低配只用一张大序列帧 👤。
- 尾缀中低配：只能 1 层 overdraw（大面片不叠），可以有 2–3 个发射器 👤。
- `_H` 可以用 Mesh / Ribbon，按 2.0 已通过资源的用法 👤✅（阈值待用户确认 ❓）：
  - **Ribbon**：1 条拖尾、1 个 Sheet、每条最多 40 个粒子、细分 25（`Trail_01_H`、`Merge_*_H`）；
  - **Mesh**：平面片 8 顶点（`SM_EFX_Plane_10/17`）、24 顶点（`GunFire_02`），都用 `MeshFaceCameraWithRoll`。例外：257（红包）、1180（`SM_EFX_Plane_FireWork_Hero`，大金系列）；
  - 建议门槛：Mesh ≤ 24 顶点；超过要写明理由并经用户点头。
- **记录**：导入后读回 UE，写进 `FXtools/节目/NewYearFireWorks_v01/资源发射器数.json`（平台、档位、启用数、GPU 数、LOD 数、Mesh 顶点 / Ribbon 段数）。没写就不算完成。

## 7. 尾缀朝向（用户 10-12 要改）

- 远段改成 `PSA_Rectangle` + `OrientationAxisLock`（`EPAL_ROTATE_Z`）。参考：
  - 红彗星 `FanComet_01_HD` 的 `Trail_Main` / `Particle Emitter` 是 Rectangle + 锁 Z ✅；
  - 银扇 `FanSilver_01_HD` 的 `Central_L` 是 Velocity + 锁 Z ✅。
- 原因（我的推断）：4.9.68 的远段 `TrailFar` 是 Velocity 朝向，但初速只有 0.39 m/s（S 包 `InitialVelocity` Z = 39.48 cm/s）。速度这么小，朝向不稳，整根一倾斜就会抽搐。
- **随机角度要固化**，不能用引擎随机：开花条目是另一条，引擎随机不会跟着改爆点位置。要像现在的 `coupledVariation` 那样，编译时定好每个角度，同时算好爆点偏移。
