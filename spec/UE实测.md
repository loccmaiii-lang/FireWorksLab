## 2026-10-04 · Pivot 配置与历史保留资产的核对

`emitters[].required.pivot_offset`是素材包的二维数据，按数组顺序写入独立`ParticleModulePivotOffset.PivotOffset`的X、Y，并将模块挂接到LOD的Modules；不直接写Required原生属性。当前私有工作台v2.7实际生成HTML含这条转换，原包与字段转换6组隔离检查通过；旧v2.5缺少此转换。升级网页不会自动重写已导入资产，保留手调发射器的恢复路径也不会按新配置重写原模块。

本轮只读当前资产：循环层无Pivot引用，消散层仍有手动值(0,-0.5)，与包中(-0.5,-0.0154)不一致。上次恢复执行前后，两层都有手动Pivot且受保护对象一致；当前循环层同一LOD的其余模块路径保留，Pivot引用已不在列表。快照能确认前后状态差异，不能确定后来哪一步移除了引用。补齐时应只新增/校正对应Pivot，保护其它手调参数；本轮未写入原生资产，未做真实播放画质验收。原始路径、模块快照及证据留本机。

## 2026-10-04 · 新建/同名重建粒子的编辑器状态缓存

独立测试中，Emitters、LODDistances、LODSettings及必要模块的写入/读回均通过，打开Cascade仍触发Array越界（0 from size 0）。崩溃地址在实际引擎导出符号TurnOffSoloing内。仅保证顶层LOD非空不足以保证可以打开；重建后还需同步每个发射器/LOD的独奏状态缓存SoloTracking。该字段在默认原生属性列表和Python常规属性访问中不展示，显式请求原生属性才可读到LODSoloTrack.SoloEnableSetting。

本机4.24实测：整块文本导入SoloTracking会返回“写入成功”，但Transient的SoloEnableSetting实际为空；JSON数组写入也不能据返回成功确认结果。已有原生嵌套容器操作可逐项追加/移除该设置。先追加有效的新设置再移除旧值，替换发射器前保证所有活跃索引有缓存；发射器减少后移除多余缓存，显式读回数量及逐LOD启用状态。更新只覆盖完整单级LOD的系统，多级/缺失LOD在依赖写入前停止。

修复后独立1→3（含GPU）、3→1、新建2个发射器、组装失败保留旧列表四条路径均成功在当前会话打开并关闭Cascade，不依赖重启刷新缓存。贴图同对象路径16×16→32×16、材质实例旧标量覆盖清除并恢复示例值也已验证。旧GPU待办继续兼容；本轮没有把复杂烟花画质、全模块GPU兼容性、长期运行或用户验收标为通过。只写独立测试资源，当前用户资产保持原样；原始符号、崩溃、参数和文件证据留本机私有记录。

### 2026-10-02 · 导入保存判据：内存成功与磁盘成功需分别验证

本机真实导入发现：新资产包保存成功后，资源表行新增和内存读回仍可成功，但只读源文件的SavePackage失败。调用结果未提供原执行器所检查的saved=False字段，不能把字段缺失当成保存成功；编辑器随后停在迁出资源弹窗。

本机工具已补充磁盘验证：每次新增后核对文件内容变化且含对应ResourceId；子模板保存核对文件变化且包含全部新增模板名。原生属性/结构读回仍保留，两个证据均通过才记录完成。隔离检查覆盖接口成功但文件未变、文件变化但缺目标ID、空文件与正常保存。当前首行仍需补存，真实实播和重启验证未完成。

### 2026-10-04 · 模块说明、部分导入与版本管理状态

真实素材包的模块含`note`说明文字；它不是原生粒子模块属性。旧解析器把全部键发送为属性，停在第三个发射器的说明字段。`m`是模块标识，`note`/`_note`是说明元数据，转换时不能发给反射写入；其它未知真实参数仍应报错，不能一并静默跳过。局部空间原生字段为`bUseInLocalSpace`，`required.pivot_offset`通过`ParticleModulePivotOffset.PivotOffset`及Modules链接表达。

本次还实测了保存差异：自动贴图导入任务的save=False会只留内存；复制材质实例会提前保存并自动标记添加。若粒子组装失败而最终统一保存未执行，会出现材质已添加、贴图未保存/未纳管、粒子仅部分链接。已改为依赖分阶段保存；核对实际非空.uasset，再通过当前`unreal.SourceControl`的`mark_file_for_add`和`query_file_state`确认`is_valid && is_added`。未启用版本管理、服务不可用、添加被拒绝和缺文件应分别显示。

按用户要求保留已手调的前两个发射器，仅补后8个。10个发射器及5贴图/2实例/1粒子的磁盘保存和P4添加状态已确认，新增模块与完整曲线读回通过。空Burst数组文本可能留下Count=0的中性条目，不能按条目数误判为额外发射。此轮是结构、参数、文件和版本管理核对；真实播放画质、重启加载仍未验收，不能据此更改效果验收状态。

### 2026-10-04 14:58 · 升空尾缀 RT4L 进引擎（用户截图，对话框15 记录）

- **Acceleration 模块在 GPU Sprites 上不可用**（Cascade 里标红）。RT1–RT4 每个 GPU 火花发射器写了 3 个 Acceleration（空气乱流：大涡按发射器时间的曲线 + 小涡两个均匀分布相加），一直标的是「未经 UE 验证（⚪）」→ 现在 ❌。以后 GPU 发射器不写 Acceleration；乱流放进贴图（烘焙器里算），GPU 粒子只靠 Initial Velocity 的随机散开。Const Acceleration（重力）可用。
- **RiseLoop 上没有 Pivot Offset 模块**：cascade.json 写了 `required.pivot_offset = [-0.5, -0.0154]`（星头在面片上端），但截图里 RiseLoop 的模块是 Required / Spawn / Lifetime / Initial Size / Initial Velocity / Drag / Const Acceleration / Size By Life / Dynamic / Color Over Life，没有 Pivot Offset → 面片按中心放在粒子上，贴图里的星头比真实星头高半个面片，GPU 火花（从真实星头出生）看起来在贴图中段 / 尾部。导入器 10-04 说支持 `ParticleModulePivotOffset`，这个发射器是不是走的那条路还没对上（可能是之前手调保留的发射器）。
- **同屏粒子数**：RT4L 一条尾缀 GPU 粒子同时活着约 1 万（UE 统计 SparksFine 3528、SparksMid 4751、SparksCoarse 1327…；烘焙器估 7282）。用户要求：**一条尾缀的拖尾粒子同时活着不超过 800**（同屏还有很多别的粒子）；做法是密的、会闪的火花进贴图，Cascade 只留少量粒子和贴图错开、让闪烁明显。
