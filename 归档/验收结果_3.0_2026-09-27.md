# FireWorksLab 3.0 验收结果

- 验收日期：2026-09-27
- 验收依据：[验收清单.md](验收清单.md)
- 受测版本：`bb5f14f`（`3.0：补齐 v3 提示词全部事项；源码拆分模块；验收清单`）
- 环境：Windows、Chrome、WebGL2；实机显卡为 NVIDIA GeForce RTX 5080。部分批量检查使用较小贴图和软件渲染器，已在下文注明。

## 总结

**功能技术验收：有条件通过。最终验收：未完成。** 页面、主要模拟路径、各花型的基础烘焙、ZIP 导出、迭代和组合功能能够运行；但清单中的若干预期与实测不符。花型与实拍的一致性需要人工逐帧评审，单元序列还需要在 Unreal 中验证。因此，不能把“能烘焙”理解为“视觉还原已经达标”。本次只检查和记录，没有改动程序源码。

## 0. 显卡测速

在 RTX 5080 的 Chrome 中运行内置测速：

| 同屏火花数 | 内置测试耗时 |
| ---: | ---: |
| 3 万 | 约 0.63 ms/帧 |
| 10 万 | 约 0.66 ms/帧 |
| 30 万 | 约 0.95 ms/帧 |
| 100 万 | 约 1.44 ms/帧 |
| 300 万 | 约 5.69 ms/帧 |

当前菊的 2K 母版完整烘焙约 0.61 秒。此数值只反映工具内的该次测试，不能直接当作 Unreal 场景帧率。测速开始时“当前预览帧率”曾显示 0 fps，随后可出现有效数值；这项显示需要再检查采样时机。

## 1. 物理

| 条目 | 结果 | 证据与限制 |

| 1.2 参数锁定 | 通过 | 锁住初速后切换号数及随机微调，初速保持 150，其他参数仍改变。 |

| 1.4 燃烧减质量 | 功能通过，画面待评 | 锦冠把 0.3 调至 0.8 后，归一化下垂指标约 0.064→0.283。 |
| 1.5 自旋与竖直残余速度 | 功能通过，画面待评 | 自旋 40、竖直残余速度 15 改变星点坐标；同一时刻平均纵向位置约 -6.14 m→-0.80 m。 |

## 2. 花型

26 个可选花型均完成 **512×512、4×4 帧、小尺寸基础烘焙**，未遇到页面报错；包括清单 2.1–2.12 涉及的变色菊、点灭星、辉星、爆裂星、松叶、分裂、椰子、落叶、时差、环、土星、型物和水中花火。型物的心形、笑脸、五角星、文字路径也能完成小尺寸烘焙。抽看了部分特殊花型，但**没有完成逐个花型的全尺寸视觉对照**，因此 V11 还原程度、闪烁节奏、分裂形状、水面倒影等艺术预期均标为**待人工验收**。小尺寸通过只说明基础流程可运行。

## 3. 产物

| 条目 | 结果 | 证据与限制 |
| --- | --- | --- |
| 3.1 分段母版 | 通过 | 锦冠导出 ZIP 含 `_A`、`_B` 两张 PNG、两段参数和段 B 的 Emitter Delay；ZIP 可打开且 CRC 正常。 |
| 3.2 单元序列 | 文件与参数通过 | 菊的单元 ZIP 包含序列贴图和 Sphere、Drag、Const Acceleration、Size By Life X/Y、Pivot Offset、overdraw 对比参数；选 150 颗星时参数对应 150。实际引擎表现见 3.3。 |
| 3.3 Unreal 发射器 | **待验** | 本次没有在 Unreal 中搭建发射器；Pivot Offset、速度对齐后星头方向以及实际 overdraw 未确认。 |
| 3.4 种子变体 | 通过 | V1–V3 导出 ZIP 含三张有效 PNG 和一份参数表。 |
| 3.5 按画面变化取帧 | 通过 | 开关前后都生成 256 帧，采样时间键不同；合并近似帧由约 10 对降为 0。 |
| 3.6 自检 | **部分通过** | 过曝等提示可出现；但 2K 菊把格子留边设为 0 后仍提示“边缘渗色：无（留边 0 像素）”，与清单预期不符。 |
| 3.7 LOD、烟、声音 | 通过 | 参数表和导出包中可找到相应建议、参数和带时刻的声音事件。 |

实际下载并检查过 2K 菊母版 ZIP：2048×2048 PNG、256×8 色带以及参数 JSON、参数文字、曲线 CSV、声音节点 JSON 均存在；所查 ZIP 均能打开且文件校验通过。分段、单元和变体主要用 1024×1024 配置检查结构，不代表其 2K 画质已经验收。

## 4. 上升

金色、银竜、暗升、昇り小花、分砲、笛、螺旋七种曲导均能完成小尺寸烘焙。模拟事件中能看到银竜较密的尾迹、暗升无明显尾迹、昇り小花的开花事件、分砲的分裂事件和笛的哨音事件；参数表中的弹体、星头循环、尾迹及开花衔接结构已检查。默认上升拟合误差约 0.00776，循环接缝多数接近 1；笛约 **1.33**，建议进一步目测循环点。4.1–4.4 的具体视觉表现和 Unreal 中的衔接仍需人工确认。

## 5. 地面循环

喷泉、瀑布、转轮、扇形、连发、仕掛け六种均完成小尺寸循环烘焙；1024 配置的接缝比分别约为 0.909、0.943、0.882、1.063、0.962、1.012，均低于清单给出的 1.3。仕掛け文字路径可以烘焙，循环参数字段也已检查。连续播放是否“完全不跳”仍以人工目测为准。

**自动选格子未达预期：**喷泉与瀑布在默认 2048×1024 条件下都选到 8×4 布局，即 256×256 方格；清单要求喷泉高格子、瀑布宽格子。

## 7. 组合

“五段变色三重芯（V11）”“点灭菊·红芯（V14 末期）”“四尺玉（主层 + 两层芯）”三个预设能载入和播放；对应图层数分别为 3、2、3。图层内分段颜色可以编辑。组合的节奏、遮挡和实拍匹配程度仍需美术评审。

## 待处理问题与下一步

1. **修正或说明 40 号菊规格**：统计约 1147 m，与验收目标约 900 m 不符；同时复查过曝和该配置的最低帧率。
2. **修正格子留边为 0 时的自检**：目前仍报“无边缘渗色”。
3. **修正地面花型的自动格子方向**：喷泉应偏高，瀑布应偏宽。
4. **核对数值参考口径**：解释或修正 V06 t50 的两处数据；避免把归一化指标的 ✓ 误读为花径、消え口等整体匹配。
5. **完成引擎与视觉验收**：按 3.3 在 Unreal 中检查 Pivot Offset、星头方向和 overdraw；逐项对照 2、4、5、7 的实拍或目标画面，并检查视频对齐与循环点。

本报告使用的自动化脚本、测试下载和临时依赖均留在仓库外的临时目录；仓库中只保存验收结论。
