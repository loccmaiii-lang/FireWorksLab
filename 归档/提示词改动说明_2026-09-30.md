# 提示词重写：改了什么、为什么（草案 · 2026-09-30）

新提示词由两份文件组成：

- `CLAUDE.md`：怎么做事。
- `标准.md`：做到什么程度才算完。

用户同意后替换正式文件，同时把旧版放进 `归档/`。现在正在跑的对话和定时会话，读的仍然是旧版。

## 1. 旧提示词的问题

### 1.1 互相冲突

| 旧规则 A | 旧规则 B | 新写法 |
| --- | --- | --- |
| 「下发前用 compare.py 跑起点，确认 10% / 50% / 90% 的结构」（按燃烧百分比） | 「自检按开花后同一秒对照，百分比会掩盖时间线错误」 | 统一按「开花后同一秒」 |
| 「拟合 `fit.camera=true`，相机模糊 `_psf` 和曝光一起拟合」 | 「不许用模糊画面降低误差」；「细节不能超过来源」 | 相机模型只用于测量，不用来「调得像」；验收只看引擎回放 |
| 「分辨率最大化、四通道用满」（默认 8×8×4 = 256 格，每格 256 px） | 画面清晰、不抖 | 改成可量的指标：屏幕放大 ≤ 2 倍、30 fps 下能显示 ≥ 90% 的帧；格子数按指标自动选 |
| 「硬约束：只导出 2K」 | 「需要时先出 4K 母版」 | 2K 是交付物；4K 只在用户要求时出 |
| 「取景：烘焙器默认还是紧凑，待改（交接 T3）」 | 默认已经是 Zoom，紧凑已禁用（T4 完成） | 删掉过时句 |
| 「旧命名 `T_EFX_…` 改完导出后作废」 | 已经改完 | 删掉 |
| 「交接.md 是唯一的当前状态」（早期） | 「效果状态以状态清单为准」 | 状态只记在状态清单；交接只写日志 |
| 「迭代区」（旧叫法） | 左栏已改成「待我验收 / 制作中 / 已通过 / 历史」 | 统一新叫法 |
| 「不写代码」 | 大量烘焙器源码修改 | 写明是「引擎里不写代码」 |

### 1.2 重复

同一套规则写在 4 个地方，改了一处其他地方就过时：

- `CLAUDE.md`
- `协作/给其他AI的执行说明.md`（整段复述硬约束和方法）
- `协作/接续.md`
- `协作/金芒菊复盘.md`

每做完一步要改 6 处：状态清单、交接第 1–3 节、交接第 5 节、更新记录、PROGRESS.md、对话记录。PROGRESS.md 的「复刻进度表」和状态清单是重复的。

### 1.3 缺的东西（这次问题的根源）

- **没有「完成」的客观标准。** 条目该有什么、画质要到多少都没写死，所以尾缀有流转动画，球形 ABCD 没有；花型库的配方清晰度和亮度也参差不齐。
- **没有「以引擎回放为准」。** 结果是按拟合分数和带相机模糊的对照图判断，而这两样都不代表导出的贴图。
- **没有代码标准。** 能力按效果一个个补，没有版本号和回归，底层问题没人管，版本一直停在 3.7。
- **没有 UE 实测回路。** 预览里对引擎的假设从来没核对过。

### 1.4 太长

旧 `CLAUDE.md` 161 行、19 KB，其中约一半是「某月某日用户说过」的来历、反例和过时说明。新版只写现在要做什么，来历留在 `对话记录/` 和 `归档/`。

## 5. 烘焙器 4.0：从「缝缝补补」到「有标准」

对应用户 23:15 的意见：做一半、说了才做、品质参差不齐、一直停在 3.7、变成屎山。

**做法**：不推倒重写，按 `标准.md` 第 3 节把底层整理成分层结构。按下面的顺序逐步做，每一步都有回归和标准检查。

| 阶段 | 做什么 | 做完的样子 |
| --- | --- | --- |
| 4.0-a | 一个渲染核：实时、引擎回放、定帧、对照、拟合共用；光点改成「亮核 + 光晕」；快门统一；曝光锁 | 调尺寸一定有反应；实时和导出一个样 |
| 4.0-b | 帧预算按引擎帧率；自动选格子；首尾裁帧；防混叠 | 30 fps 下不频闪、不顿挫；放大不超过 2 倍 |
| 4.0-c | 一个条目查看器：多层效果也有引擎回放、流转动画、完整参数、一个素材包（多发射器 + 延迟） | 球形 ABCD、大组合和尾缀一样齐 |
| 4.0-d | 标准检查 + 回放检查及格线 + UE 实测包 | 左栏每条 ✅ / ❌；不达标交不出去 |
| 4.0-e | 模拟稳定：随机数脱钩、NaN、上限报警、版本指纹、烘焙失败处理 | 滑杆不再「一动全变」 |
| 4.0-f | 花型库全部模板按标准重调一遍，写成基准 | 模板的清晰度、亮度统一 |

之后，正在做的效果在 4.0 上迁移、重新导出，再进「待我验收」。
