用户要求（原话要点）：
- 「现在所有的参数名称，能按照虚幻 Niagara 的命名风格改一遍吗？默认是中文，悬停后第一行是英文 + 中文描述解释……我的目的是为了更好让我理解这些参数的用途」
- 「只有小部分参数是有解释的，还有非常多参数都没有解释，可以全部加上去吗？」

- `en_niagara`：英文名是 Niagara 里真有的模块 / 参数（或几乎一模一样）= true；是照 Niagara 风格起的（Niagara 里没有这个东西）= false。
- `tag`：
  - **通用** = Niagara / Cascade 里有对应概念（数量、寿命、速度、阻力、重力、大小、颜色、随机…）；
  - **烘焙器专有** = 烘焙器用物理 / 渲染算出来的东西，UE 里没有直接对应（黑体温度冷却、平方阻力、尾迹梭形、线间底光、快门…）；
  - **烟花特性** = 烟花特有的行为（点灭、辉星、爆裂、松叶分叉、第二段、分层星前段压暗、千轮 / 分裂子花、蜂、曲导…）；
  - **烘焙输出** = 帧数、格子、贴图、取景、入出点、曝光、画质、导出选项。

## 中文名的写法

- 跟着英文的意思，用 UE 中文用户熟悉的说法：生成数量 / 寿命 / 初速 / 阻力 / 重力 / 大小 / 亮度 / 颜色 / 随机 / 继承速度。
- 烟花术语保留但要好懂：「消え口」放进说明（「熄灭时刻」），中文名用「寿命随机」；「引き」「錦」「千輪」等在说明里解释。
- 随机类一律「××随机」，单位写在 unit（% / °），说明里写 ± 和分布。
- 同一个概念全表用同一个词（例如所有「火花」都叫「火花」，不要一处「火星」一处「火粉」——除非确实是两种东西，那就在说明里分清）。
- 不要和别的参数重名（同一节里不能有两个一样的中文名）。

## 说明的写法

- 给 UE 特效师看：先说是什么，再说画面会怎样。少用内部实现词（不要写 uniform / hash / shader）。
- 数值例子用这个参数的默认值或常见值举例（例如「8% = 大约 2/3 的星速度在 ±8% 内」）。
- 只写代码里真的这样做的事；拿不准就在 check 里写「不确定」，不要编。
- `note` 写联动和「什么时候不起作用」（例如：星头不发光时，燃烧时间超过「火花只在前几秒」看不出变化）。

## 核对方法

- 参数定义：`tool/src/js/10_types.js`（BASE 默认值、SCHEMA 节和条目，第 7 个元素是显示条件）。
- 用法：在 `tool/src/js/` 里 grep 字段名（`P.key` / `P[key]` / `uXxx` uniform），主要文件：20_sim.js（CPU 模拟：星、火花、上升、子花）、40_gl.js（GPU 火花 shader、尾迹外形、地面发射器）、41_particles40.js（4.0 光点）、42_trail.js（尾缀序列）、43_phystrail.js / 44_physrecipes.js / 45_physbody.js（物理尾缀）、46_emitset.js / 47_risetail.js（尾缀循环层 + 粒子）、48_render40.js（4.0 快门 / 曝光）、05_quality.js（画质）、30_plan.js / 31_plan40.js（取景、帧计划）、50_bake.js（烘焙）、60_export.js / 61_naming.js / 65_cascade.js / 66_fwlcascade.js / 67_fwlcombo.js（导出、cascade.json）。
- 每一行的 check 字段写你看到的依据。

- 把你负责的节的所有条目（schema_sections.json 里这些节的每一个 item，一个不漏、顺序不变）写成一个 JSON 数组，存到指定路径。
- 只写文件，不改仓库里的任何文件，不提交。
