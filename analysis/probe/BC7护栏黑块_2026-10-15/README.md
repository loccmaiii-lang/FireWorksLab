# BC7 压缩 × Ramp 末格黑护栏 → 最亮处一块块黑、逐帧闪（2026-10-15，导出（23））

用户 10-15 01:40：好多贴图导入 UE 后，最亮的地方出现黑色马赛克在闪（截图：橙色光团中间一块台阶状的黑块）。

## 机制（云端模拟复现，未经 UE 验证）

- 4.9.31 起：序列编码封顶 253/255，Ramp（256 × 8）最后一格（第 255 格）是黑的护栏（防 Ramp 按 Wrap 读时 v≈0 混进白热色）。
- 材质按 u = v 双线性查 Ramp：v ≥ 254 时就和黑格混（254 → 一半黑，255 → 全黑）。**余量只有 1 个色阶。**
- UE 里序列图是 BC7（对话框5 10-07 读回：TC_BC7、sRGB 关）。BC7 按 4×4 像素一块压缩，RGBA 接力时四个通道是不同的帧，一块里要同时拟合四个通道，封顶 253 的平顶区解码出来常常 +1、+2 → 254 / 255 → 查到黑格 → 一块块黑；每一帧内容不同、压缩误差不同，所以黑块逐帧换位置 = 「在闪」。

## 模拟结果（`sim.py` / `sim2.py` / `sim3.py`，编码器 bc7enc_rdo b9438627 的 bc7enc，线性权重）

512² 合成图，每个通道 260 个高斯光团、按烘焙器编码（1 − e^−x，封顶）：

| 情形 | 封顶像素里解码 ≥ 254 的 | 发黑 ≥ 25 % 的像素 |
|---|---|---|
| RGBA 接力（四通道不同帧），封顶 253，Ramp 256 宽 | 15–20 % | 3.5–4.2 %（全图） |
| 只用 R 通道 | 4 % | 0.9 % |
| 封顶 251 / 250 / 248 / 245（Ramp 256） | 1.6 / — / — / 0.04 % | 0.39 / 0.11 / 0.06 / 0.01 % |
| 封顶 253，Ramp 4096 宽（只有 255 才黑） | — | 1.43 % |
| 封顶 250，Ramp 4096 宽 | — | 0.08 %（只剩锐边上的单个点） |

`黑块示意.png`：左 = 原图（Ramp 上色），中 = BC7 后（封顶 253、Ramp 256，和用户截图同一种台阶状黑块），右 = 封顶 250 + Ramp 4096。

UE 4.24 的 BC7 是 ISPC 快速档，误差多半比这里的 bc7enc 大，所以 UE 里只会更多。

## 怎么在 UE 里确认（要用户做，各几下点击、不保存）

1. 挑一张会闪的序列贴图 → Compression Settings 临时改 `VectorDisplacementmap (RGBA8)`（不压缩）→ 黑块没了 = 压缩造成的。
2. 或者只换 Ramp：用末格不黑的 Ramp（第 255 格 = 第 254 格的颜色）→ 黑块没了 = 查到护栏格；同时看光晕外缘有没有一圈白细线（10-07 那个问题回来没有）。
3. 拖动镜头：黑块跟着贴图走、对齐贴图像素 = 这个问题；黑块钉在屏幕上、一格格是 2 的幂大小 = Bloom 里的 NaN / Inf，另一回事。

## 修法候选（等用户定，见 `协作/渲染基础问题清单.md` I1）

- C：Ramp 末格不放黑（只换 Ramp、序列不用重导）——黑块完全没有；前提是第 2 步看不到白细线（UE 读回是 Clamp，护栏可能本来就用不着）。
- A：Ramp 加宽到 4096 + 封顶 253 → 248–250（所有序列重导，最亮处暗约 1–2 %）——黑块只剩锐边上偶尔一个点。
- 另外：Ramp 贴图本身也是 BC7，末格黑和白热挤在同一个 4×4 块里，建议 Ramp 用不压缩（UserInterface2D / VectorDisplacementmap），它只有 256 × 8。
