## 2. 根因

### 2.1 主因：FC7R-1 的参数（`analysis/原理/条目_扇形彗星.json`）

- `headSize 3.5`（m）、`coreProfile` 用默认 0：一个直径 3.5 m 的**实心圆盘**（`diskCoverage` 精确覆盖，边缘只有 1 像素过渡）。50 mm 彗星的火焰本体不到 0.5 m。
- `haloFrac 0.85`（`05_quality.js` 夹在 0.85，滑杆已经推到顶），光晕能量是亮核的 5.7 倍；`haloR 3.5` 让 σ = 1.75 × 3.5 ≈ 6.1 m，画到 4σ ≈ 24 m 半径。相邻两星相距约 14.8 m，所以连成了带。
  - 对照：实拍光晕能量 0.05–0.12（`18_multitypes.js` 注释），用户通过的 RT6 / V5 用 0.04。
- **复现对得上**：`核模型模拟.py` 按烘焙器链路复现（光点核 → `1−e^−x` 编码 → `Ramp(v)·v·4` → 显示 `1−e^−x` + γ2.2）。复现得到 r50 9.4 px、星间雾 0.078，截图实测 9.5 px、0.082。复现的断崖比截图更陡，因为模拟里没做快门拖影和截图缩放。
- 来历：用户 07:43 要「星头一层很大的玫红光晕」，FC4 → FC7 每一轮都把光晕调得更大、更软，最后把滑杆推满。实际上是把「照片里看起来大的光晕」做成了「空中一个大的发光物体」。

## 3. 现在缺的物理 / 视觉因素

1. **点光源**：星本身才几厘米。照片里看到的「星头大小」几乎全部来自镜头 PSF 和传感器削顶，所以星越亮看起来越大。现在的做法是把大小写死成一个圆盘直径。
2. **PSF 形状**：亮核 + 幂律尾巴（像差、散射、衍射；天文上用 Moffat 拟合星像）。实拍拟合 β 在 1.8–3.4。高斯的尾巴掉得太快，σ 一大就成了「雾球」。
3. **光带是烟**：参考 B 里那片红光，是被星照亮的烟，有丝缕、有滞后，不是每颗星自带的光晕。要光带就单独做烟层，把高斯调大做不出来。
4. **星芒和六边形**：衍射星芒只在单反小光圈下出现，参考里没有。六边形是失焦散景（bokeh）的形状，在焦的星头应该是圆的，所以 4.9.50 的 `headHex` 不适合这类星头。
5. **颜色**：锶红在手机里 R 通道削顶，呈「白芯 + 正红边」，色相约 0°。现在的 Ramp（`#e8205e` / `#ff7aa6`）是 −24° 的玫红。如果要贴新参考就改正红，如果还要悉尼那张的粉色就保留。**要你定。**
6. **燃尽**：亮度一降，星头看起来就该变小（PSF 模型下这是自然结果）。现在是 `fade 0.12` 直接消失。
7. 运动模糊：快门 0.6，星头 40–70 m/s，1/30 s 拉长 1.3–2.3 m，已经有了，不缺。

### 7.3 FC9R 怎么补

- **② 近晕 + 远晕**：烘焙器 4.9.55 加了「光晕形状 = 多层柔光」：四个高斯，宽度为 0.6 / 1.5 / 3 / 5.5 × 光晕半径，能量份额 0.12 / 0.30 / 0.33 / 0.25，按万彩千轮 V11 各层能量折算；总光量和单高斯一样。缺省关，基准回归 7 个逐像素相同。
- **① 光晕是饱和的红**：星头层 Ramp 改成从黑直接起到饱和红（#d8060e / #ff0a1c / #ffd0dc），编码改 γ2.2。材质的 v·Ramp(v) 在暗部 ∝ v²，γ2.2 编码正好抵掉，光晕亮度跟光量成正比、颜色不变。
- **③ 白只在小芯**：曝光 6 → 2，亮核 1.4 → 0.8 m，光晕占比 0.6、半径 × 1.0。
- **④ 软泪滴**：星头拉长 0.5，沿运动方向。
- **头最亮、尾在后**：尾巴回到 FC8R 那套量对了颜色的炭金（线性编码），亮肩 1.0 → 0.3、亮肩亮点 2.0 → 0.4。v1–v7 里尾巴也开过 γ2.2，结果尾比头亮、偏红，所以撤掉了。

### 7.4 没补的、为什么

- **显示的色调映射**（每通道 → 按最大分量，或 AgX）：会改所有效果的预览和引擎回放，而且 UE 有自己的色调映射。FC9R 用 Ramp 往蓝偏一点抵消。要改得先做 P1 的 UE 标定，再定预览跟哪套。
- **屏幕空间辉光**（Blender 的 Fog Glow）：烘焙器把光晕烘进贴图；UE 的 Bloom 开多少不知道（P1），叠上去会变成两层。
- **星头和火花各自的光晕**（FanGold 10-09 审查第 5 条）：现在靠拆层实现（第 1 层星头、第 2 层尾巴），没有加参数。

## 8. 火花：发光强、边缘锐利、不规则多边形（用户 10-09 23:20，FC10R）

用户原话：「当前的光晕效果已经达到预期，请保持不变。接下来请优化火花粒子：每个火花粒子都要有强烈的发光感，同时边缘锐利、轮廓清晰，不能模糊发散。粒子形状为不规则多边形（每个粒子形态各异）」。参考是 FanSilver R3 / R4 头部对照（Blender）。

### 8.1 Blender R4 的火花是怎么做出来的（读 `src/fxlab/nodes/visual_controls.py`、`src/fxlab/blender/nodes.py`、FanComet R4 参数和 .blend）

| 环节 | Blender R4 | 烘焙器 FC9R |
| --- | --- | --- |
| 形状 | 每粒一个**实例网格**：icosphere（一次细分，20 面）或细长锥，沿速度对齐，大小在 0.45–1.6 倍里随机 → 投影轮廓是随机朝向的多边形，每粒不同 | 光点核里的**圆盘**（像素覆盖精确积分） |
| 发光 | 平面自发光，只亮正面，**增益 8–17、强度 0.3–1.8 倍随机** → 核心远超 1、一片削顶白 | 亮度 2.6，核心峰值 0.55（不削顶），火花是金色而不发白 |
| 边缘 | 几何边 + Blackman-Harris 1.5 像素过滤 → 1 像素过渡 | 圆盘边本来就锐，但被下面三样糊掉 |
| 辉光 | 合成器两层 Fog Glow，**有阈值**（0.45 / 1.0）：只有削顶的像素外面才长一圈光，暗的火花不糊 | 每粒火花自带高斯光晕：占比 0.22、半径 × 3（σ ≈ 3 纹素），亮暗火花一律糊 |
| 运动模糊 | **没有**（Geometry Nodes 拓扑在变，Blender 自动关掉） | 快门 0.6：每粒沿运动拖成一小段 |
| 密度 | 单根彗星的近景，约 34 像素 / 米，火花彼此分开 | 整排扇，约 4.2 纹素 / 米，每秒 300 粒挤在 1–2 m 宽的线上 → 连成一根金线 |
| 输出 | 直接按显示像素渲染 | 烘进 512 单格贴图，引擎回放按双线性放大显示 |

量（`火花量.py`，原像素、只取孤立火花）：R4 孤立火花 747 颗、100 % 削顶、边缘 0.75 像素、外裙 0.19；FC9R 只量到 4 颗孤立火花，没有一颗削顶，边缘 1.2 像素。

### 8.2 之前那次（4.9.50，导出（23））效果一般的原因

1. 只做了**星头**的形状（六边形、边缘起伏、双核），火花只有「拉长」，火花本身还是圆。
2. 六边形是**整层同一个朝向**，看起来像镜头光圈，不像每粒不同的碎片。
3. 亮核半径小于 1.5 像素时退回圆盘，而火花只有 1–2 纹素，所以几乎全部是圆。
4. 真正让火花发糊的三样都没动：每粒自带的宽光晕（× 3）、快门 0.6 的运动模糊、火花太密连成线。核心也没有削顶，所以不「发光」。

### 8.3 需求重新梳理（补上的）

- **发光感 = 核心削顶发白 + 外面一圈弱光**；锐利 = 削顶区和光圈之间要有一个台阶，光圈不能盖过边缘。所以亮度要提、光晕要收。
- **每粒不同**：形状（边数、顶点远近）、朝向、翻转速度、大小、亮度都按粒子固定随机，不随帧乱跳（随帧跳是闪烁，另有「火花闪烁」）。
- **分得开**：少而亮，比多而暗更像 R4；线要宽一点让火花之间有黑缝。
- **运动拖尾**：R4 没有拖尾，所以默认不拖；需要时用已有的「火花拉长」（拉长的多边形，试过 0.35，整体差别不大，没用）。
- **颜色随寿命**：沿用温度 → 亮度 → Ramp：新火花削顶发白，冷下来变金、橙、暗红；Ramp 亮端改淡金白。
- **刚出生的火花先暗**（烧旺时间 0.15 s）：否则星头附近的新火花堆成白条，压过已经认可的红光晕。
- **分辨率上限**：整排扇约 4 纹素 / 米，多边形要 ≥ 3–4 纹素才看得出棱角。v12 把颗粒放到 1.15 m 棱角很清楚，但整条尾巴变成白色粗条，压过红光晕，所以退回到 0.85 m。要放大近看也有棱角，得让火花层用 2 × 2（单格 1024）——贴图张数 1 → 4，**没做，等你定**。

### 8.4 改了什么（烘焙器 4.9.57，缺省逐像素不变）

- **火花 › 形状**「不规则多边形」（`sparkShape`）+ 不规则程度（`sparkShapeIrr`）+ 翻转（`sparkShapeSpin`）：每粒 4–7 边，顶点角度和半径按粒子编号随机，按年龄翻转；像素里 4 × 4 取样，边缘抗锯齿；总光量和同直径圆盘一样。实现在 `41_particles40.js` 的 `polyVS40` / `polyCov40` / `spkPolyProgram40`，可以和光晕形状、火花拉长叠用。
- **火花亮度随机**（`sparkBrightJit`）：每粒一个固定的对数正态倍数（均值 1）。
- `40_gl.js` `drawSparksGPU`：两样都关时用原来的程序。基准回归 7 个逐像素相同（`基准回归_4.9.57/`）。
