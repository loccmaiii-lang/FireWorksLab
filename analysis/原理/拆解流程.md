# 参考烟花拆解与复刻（同一把尺子）

> 对话框新花型 2026-10-08 写；用户 08:58 定的方法。claude.ai 上有同名 skill（firework-reference-breakdown）指向这里；改方法改这一份。

用户 2026-10-08 08:58 定的方法：对着拆好的帧逐项打点（点 / 线的数量、角度、粗细、密度、长短、明暗、闪烁频率，每个点有编号）→ 匹配库（化学 / 做法）→ 分层、记每层转变节点 → 按各层细节初填烘焙器参数 → 合层、调整体质感 → 比对 → 提交。目标是**成品**，不是「模板改个名」。

仓库规则（CLAUDE.md、协作/标准.md、状态清单、认领、版本、记录）照旧，这里只讲拆解和调参的方法。

## 0. 质量线（用户说过的，别再犯）

- 不许从相近模板抄参数几乎不改就交。每一层都要有「实拍量到的数 → 我们渲染量到的数」的对照。
- 星头不是一个圆点了事：形状略随机（拉长随速度变）、会闪、光感足、通透（白芯 + 干净的色边），不沉闷。
- 自己放大看：每轮都看关键时刻的**放大局部**（整朵 + 右上四分之一放大），不是只看缩略图和分数。
- 分数和眼睛不一致时，以「为什么不一致」为准：多半是量法或相机造成的，不是去凑分。

## 1. 准备

- 读 `analysis/原理/<效果>.md`（已有的逐时刻观察）；没有就先写：开花帧（视频秒）、花心（cx / cy，0–1）、几层、各层颜色时间线、有尾无尾、熄灭方式。
- 找开花帧：逐帧看，第一帧出现爆点 = t0。花心按中后段亮部重心。
- 有两段同一种玉的实拍（A / B）就都量：两条曲线重合 = 尺子稳。

## 2. 打点（`analysis/scripts/打点.py`）

```
python3 analysis/scripts/打点.py selftest --out <目录>        # 改过打点.py 先跑，合成图已知答案，全过才用
python3 analysis/scripts/打点.py ref <视频> --t0 <开花秒> --cx <0–1> --cy <0–1> --tmin 0.07 --t1 <结束> --step 0.0667 \
    --split auto --track <a:b> [--track <c:d>] [--mpp <米/像素>] --out analysis/原理/<效果>/打点
```

- 一定加 `--split auto`（里 / 外分界在时间上平滑补空；不加时很多帧没有分界）。
- `--track` 放在要量闪烁的时段（辉星、点灭、熄灭期）。视频常常 30 帧容器、实际 15–25 帧（看 meta.fps_eff），闪烁最多量到 fps_eff / 2。
- 跑完**看叠图**（`叠图_<t>.jpg`）：点有没有圈对（颜色类）、线有没有画对、半径对不对（天光 / 被照亮的烟会把半径撑大）。不对先修尺子（合成图加一条复现再修）。
- 云端能跑（几分钟，裁剪框省内存）；别同时跑两个。

## 3. 拆解卡（`analysis/scripts/拆解卡.py`）

写 `analysis/原理/<效果>/拆解配置.json`：
```
{ "名": "...", "参考": {"B": {"打点": ".../打点.json", "叠图目录": "...", "mpp": 0.45}},
  "叠图时刻": [..4 个关键时刻..],
  "层": [ {"名": "橙引尾", "类": "线纹理", "源": "橙线", "区": "全部", "时段": [0.1, 1.0], "说明": "..."},
          {"名": "柠点星", "类": "点", "区": "外", "时段": [0.3, 4.0]} ] }
```
- 类：点（星头 / 光点）、线纹理（密的放射尾，按极坐标纹理量）、线（稀的长线）。
- 源（线的通道）：橙线 = 线性 R − G，暖色线 = R − B，绿线 = 线性 G − R，亮线 = max。挑能把这一层和别的层分开的通道。
- 区：外（亲星）/ 里（芯）/ 全部。层名 = 颜色 + 造型 + 位置（3 个字左右）。
- 层里可写 `"比": [...]`、`"不比": [...]`、`"比时刻": [...]` 控制候选对比比哪些量（`候选对比.py --card` 按层自动生成：点层比个数 / 亮度差 / FWHM / 光晕 / 拉长 / 饱和 / 晕色相，线纹理层比线带里外端 / 线宽 / 成串 / 外内亮度比 / 对比度 / 里外色相；时刻取时段的 15 / 40 / 65 / 90%）。

`python3 analysis/scripts/拆解卡.py analysis/原理/<效果>/拆解配置.json --out analysis/原理/<效果>`，然后在 拆解卡.md 顶上写**人话总结表**（每层：读出来的样子（数）| 对配方意味着什么）+ 节点 + 物理（花径随时间 → 初速 / 终端速度）。给用户看的就是这张表和 拆解卡.jpg。

## 4. 匹配库（`analysis/原理/匹配库.md`）

每层按签名（打点的数）查：是什么药 / 做法 → 烘焙器起点参数。查不到就加一行；做完一个参考把实测签名补进「实例」。
烘焙器缺这种能力 → 先按标准第 3 节补通用能力（认领、升版本），不指望调参补结构。

## 5. 初填

- 同一批星的不同阶段 = 同一模拟（同种子 / 星数 / 初速 / 终端速度）；头尾颜色不同就拆成同一模拟的两层（一个发射器只有一条颜色曲线）。
- 花径：拟合各时刻外层半径 → v0、vt（真花大小按 mpp 换米）。
- 时间节点 → 参数：尾停 = sparkStop；尾的最后一点没 ≈ sparkStop + sparkLife ×（1 + 寿命离散）；起势 / 变暗 = starBrightCurve（寿命分数 × burn）；变小 = starSizeCurve；延迟点火 ignDelay（会把熄灭也往后推：burn 从点火算）。
- 颜色：最终 = 渐变图(v) × v × 颜色曲线 × 4 × 显示强度。白芯 + 饱和色边 = 渐变图暗端饱和色、亮端白，颜色曲线接近白。颜色在**线性光**里算。
- 数量 / 粗细 / 长短 / 亮度起伏：按拆解卡的范围填，不按模板缺省。

## 6. 候选对比（`analysis/scripts/候选对比.py`，本机显卡）

每轮 4–6 个候选（一个基准 + 每个只动一两处方向），排本机任务（一轮约 10–15 分钟）：
```
{"id": "<前缀>V<n>", "type": "script", "priority": 6, "name": "...",
 "steps": [{"name": "候选对比", "script": "候选对比.py", "must": true, "ok": [0], "timeout": 2400,
   "args": ["--mt", "<模板 id>", "--ref", "analysis/原理/<效果>/打点/打点.json", "--card", "analysis/原理/<效果>/拆解配置.json",
            "--variant", "基准:", "--variant", "甲:L1.sparkRate=1800;L2.M.headInt=1.6;L2.M.stages=0:#ffd090|0.8:#fbffe8", "--px", "1100", "--out", "{out}"]}]}
```
- 改动写法：`L<层号>.<参数>=<值>`；颜色那边 `L2.M.ramp1=#4a5008`、`L2.M.headInt=1.6`、`L2.M.stages=0:#..|0.45:#..`。
- 结果：差距.md（每层每项实拍 → 候选、|ln| 差距、总差距、每层平均）+ 对照_<t>.jpg。
- 改动叠在模板上：模板改了以后，旧的改动串叠上去就不是原来那个候选了（只能当参考）；定稿就写进模板，下一轮以模板为底（`"定:"`）。
- 每轮写 `analysis/results/<id>/看法.md`：数说了什么、眼睛看到什么、两者哪里不一致（为什么）、下一轮改什么。
- **分数 vs 眼睛**：总分低的不一定像。一层的量法出错会拖垮整体（看每层平均）；看图更像但分数差 → 找出是哪一项、是不是量法问题。
- 连续两轮没改善 → 回头查模型 / 量法，不加候选硬跑。
- 不追的（写进看法）：相机糊造成的线间对比度、过曝的芯（白一大团、光晕占比在过曝区量不准）、天空底色让颜色看起来更淡。不能靠模糊画面、调暗某层、藏特征来降差距。

## 7. 量法的坑（已经踩过的）

- 里 / 外分界：渲染图必须用**实拍同一时刻的分界**（候选对比已这样做）；渲染自己找分界会失败、退回「全部」，把别的层混进来。
- 实拍星头多半过曝：光量 / FWHM 是被截过的；比颜色、光晕、走势，不比绝对亮度。
- 天空是蓝的：线性光里减天空再取色相；参考看着「柠绿」，线性光里可能只有 60–70°。
- 过曝的芯里量的「光晕占比」偏大（周围全是亮丝），粉点之类按眼睛 + FWHM 定。
- 线带亮度两边曝光口径不同，只比走势（总差距里不算）。
- OpenCV warpPolar 要 WARP_FILL_OUTLIERS + 裁剪，不然有未初始化内存。

## 8. 参数 → 画面（标定过的规律，持续补）

- 芯的底光 tailHaze > 0.05（密芯）→ 一整块过曝白盘，看不到丝；0.03 看得到一根根。
- 点很密的一圈（芯外缘粉点）光晕 haloFrac 0.75 / haloR 4 → 糊成连续光环；0.3 / 2.5 + 星头 1.0 → 一颗颗小点。
- 渐变图暗端（ramp1）决定星头外晕和淡火花的颜色：太绿 → 整朵发绿雾；深橄榄 → 发闷。
- headTear（泪滴）会让星头变大变白（FWHM ↑、核心饱和 ↓）；要「快时拉长、慢时圆」用快门 shutter。
- 橙引成丝：火花要密、颗粒大一点、温度高一点（sparkRate ↑、sparkSize ↑、T0 ↑）→ 成串 ↓。
- starBright 只管尾，不管星头；星头亮度 = headBright × 显示强度 × 曲线。
- 光晕（haloFrac / haloR）只在 coreProfile = 1 时生效。
- coreProfile 1 会换输出族（指纹变），导出 / 回放检查要重跑。
- **显示端饱和**：最终 = 渐变图(v) × v × 颜色（线性）× 4 × 显示强度，再过 1 − e^(−x)。很亮的层（芯，v≈1）颜色亮了就饱和成黄白，降显示强度没用；要暗下去 / 变色就把**颜色曲线本身**压暗（目标显示色反推：线性颜色 ≈ 目标 / (4 × 显示强度)）。
- **颜色段有过渡宽度**：每段在 [t − xw/2, t + xw/2] 平滑过渡，段时刻写成「想要完全变好的时刻 − xw/2」。
- **曝光是观感的一部分**（相机曝光，编码前乘）：候选对比用的是模板里的曝光；换成自动曝光会推翻对照。自动值只作「亮处会不会过曝」的参考，改了要重新比。
- 火花「早出的寿命长、晚出的短」：sparkLifeEnd < 1（末段出生火花寿命 ×）。序列时长按 sparkTailEnd 保守估计（不认 < 1 的 sparkLifeEnd），会多出暗帧。
- 分层星的前段尾（橙引）在转色前**不要一刀切停**：sparkStop 停早了，尾巴浮在半路、和星头断开一截；一直出到转色、用 sparkRateEnd 让末段变少 + 颜色曲线同时变暗。
- 淡火花要细直：sparkSpread（横向散）缺省 2.5 会毛成一团，细线用 0.2–0.3；寿命按实拍熄灭节点倒推，别让它拖过节点（多出来的小点会被当成星头数进去）。
- 青绿细线这类很淡的受光烟迹：同层加少量细火花（sparkRate 400、sparkSize 0.2、sparkBright 0.06–0.08、sparkInherit 0、阻力 3），颜色由渐变图暗端决定。

## 9. 进模板、导出、验导出包

1. 认领（状态清单「共享文件」）→ 把选定的候选写进模板（或条目）→ 升 VERSION、CHANGELOG → `python3 tool/build.py` → `标准检查.py mt:<模板> <条目>`。
2. 生成条目（效果自己的生成脚本）→ `review_to_baker.py` → 再 build。**条目曝光以模板为准**（生成脚本别把旧条目的曝光盖回去）。
3. 曝光先估：`analysis/scripts/过曝估算.py --mt <模板> --layer n --E a,b,c`（本机）——每层到顶像素占比；估算比回放检查实测低约 1.5–2.5 倍，**估 ≤ 0.6% 才稳过 2% 上限**。降曝光后用显示强度补回，候选对比确认观感不变。
4. 导出（export 任务）。**依赖导出包的任务（`候选对比.py --pack`、全程回放）等导出结果回来再排**——本机会并行跑，同一次推上去会量到旧包。
5. 导出回来：回放检查 pass → 排 `候选对比.py --pack analysis/local/输出/素材包/<包名> --pack-name <导出号> --ref ... [--card ...]` + 模板实时渲染（`"定:"`）+ 全程回放 + 标准检查。导出包和实时的差距表差不多 → 交；差很多 → 查导出（帧预算、曝光、Ramp），别交。
6. 看法里写：差距表（实时 / 导出包）、关键时刻放大对照（实拍 / 导出）、剩下的差异（不影响主要目标的）、哪些没进 UE 验。进「待我验收」，一个推荐候选。

## 10. 验过的参考（2026-10-08）

- 金蕊青柠星 → 金蕊柠 JQ6：JQ5（模板级）同尺差距约 0.56 → 导出包 0.34；8 轮候选 + 6 次导出包同尺比，每轮看法在 `analysis/results/NFJV*/`、`JQ6E*/`。
- 球形C（远景、银辉星）只写了 `拆解配置.json`，打点 / 拆解卡 / 候选对比 --pack 都没改脚本：读数能区分「整齐不闪的色光星」（金蕊柠 p90/p10 1.5、闪 2–3%）和「不整齐、一闪一闪的银辉星」（3.7、19% / 8 Hz），也指出了 QC12 导出包的差距（银辉星晕太白、陆续熄灭不够不整齐）。远景星头 1–3 px 时 FWHM / 光晕不可信。

## 11. 怎么跟用户说

- 拆解卡顶上的人话表、每轮看法、最后的细节对照图是给用户看的；分开写「执行结束 / AI 自检 / 用户验收」，自检通过 ≠ 通过。
- 用户以前明确说过不要的元素（比如某个花型的淡细线），这次又在实拍里量到了：可以做，但在更新记录顶部写一行「做进去了，不要就关」，并说怎么关。
