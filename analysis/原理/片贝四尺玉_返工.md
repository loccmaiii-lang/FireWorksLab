## 2. 首轮为什么是规整环 + 拼贴

1. 子弹（小割玉）全部同一速度 → 都开在一个很薄的球壳上 → 投影成一个圆环。
2. 每朵子花同样大、同时开，子星不继承子弹速度 → 一朵朵一样的圆球。
3. 子星的尾巴短、星头亮 → 小花是「点」而不是「放射线」，连不成帘；子星终端速度太小 → 花开不大、也不往下拖。
4. 彩色小割太少、太小，而且飞到了金菊外缘。
5. 子弹飞行时星头还亮着（0.4 倍），远看像多了一层星。

## 3. 补的能力（默认关，旧配方逐像素不变；参考 Codex Ultra 实验移植到正式烘焙器）

| 能力 | 参数 | 用在这里 |
| --- | --- | --- |
| 子弹飞行时的亮度（0 = 不可见） | `carrierHead` | 小割玉飞行时是暗的 |
| 子星继承子弹速度的比例 | `subKeep` | 小花沿飞行方向张开 → 扇形 / 毽子形 |
| 每朵子花的大小离散 | `subScaleJit` | 大小不一 |
| 子星自己的终端速度 / 下坠 | `subVt`、`subGrav` | 花开够大、之后往下拖成帘 |
| 子花开花闪光 | `subFlash` | 去掉每朵都闪一下 |
| 余烬长尾（寿命长、亮度低） | `emberFrac` 等 | 垂帘的长线、金菊的连续放射线 |
| 子花开花时刻上限放宽（3 → 8 s）、子花燃烧上限（3 → 8 s） | 滑杆范围 | 4–5 s 才开、燃烧约 4.5 s |

**已解决的视觉差异**

| 子弹飞行时多一层亮点 | 子弹不可见 | 整体图 3.45 / 4.3 s 列 |

**仍未解决的差异**

1. 垂帘的「竖直下垂感」：实拍 +8 s 以后下半更竖、更长（下缘 364 像素对上缘 286 像素）；模拟整体还偏圆。子星下坠 / 终端速度 / 余烬寿命的量，交给拟合。
2. 彩色小割：实拍每朵是一团又密又亮的彩球（带光晕），模拟还是偏稀的点簇。星数、亮度、星头大小交给拟合；如果还不够，引擎里可以改成「每朵一张小单帧 + 粒子」。
3. 金菊后段：实拍放射线基本保持直；模拟顶上开始弯（终端速度偏低）。
4. 扇形 / 毽子形：模拟已有方向性，但实拍的扇形更明显（尾巴更集中朝内朝下）。
5. 中心的红色光团（+3.6 s）和下面被照亮的云没有做。

## 7. 物理 / 化学印证

- **官方名字就是结构**：第 1 天「昇天銀竜黄金すだれ小割浮模様」= 银色曲导升空（昇天銀竜）+ 金色（黄金）+ 垂帘（すだれ）+ 小割 + 彩色图样（浮模様）。
- **小割 = 大玉里装的许多小玉**：开花时割药把小玉连同星一起抛出，小玉飞行时是暗的；各自的导火线烧完才开 → 错时开花（实测 3.9–5.2 s，约 ±12%）。小玉装在大玉里不同深度、受的推力不同 → 速度有离散 → 开在一层厚球壳里，而不是一个圈。
- **扇形 / 毽子形**：小玉开花时，子星在小玉原来的速度上加一个向外的速度，所以整朵小花跟着往外飞、同时张开，形状偏向飞行方向（继承速度）。
- **金色 = 木炭（锦）**：子星是木炭为主的锦冠类药，燃烧时间长（约 4.5 s）、尾巴是长时间发光的木炭颗粒，终端速度低 → 往下拖 → 连成竹帘（すだれ）。垂帘长度 ≈ 终端速度 × 剩余燃烧时间。
- **彩色浮模様**：小牡丹，锶（红 / 洋红）、铜（蓝）、钡（绿）；无尾、燃烧短（约 1.2 s）。
