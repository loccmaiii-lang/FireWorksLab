# 万彩千轮 C/D 颜色与发光复现说明

用途：交给另一位 AI，在任意绘图、合成、着色器或程序化渲染工具中复现相似色光。这里交接的是数字特效的成像模型，不是烟火化学配方，也不要求沿用本项目软件或规则。2026-09-28 用户认可 C/D 色光；不代表运动或全效果已经定稿。

## 可直接给另一个 AI 的任务

请复现附件 C/D 烟花星点：高饱和彩色主体、极小高亮芯、低峰值宽彩晕；亮芯清楚但不成为大白圆点，外围虚柔但不是均匀发亮的圆盘。不要把整张图模糊，不要靠增加白色或扩大白芯获得 Bloom。每团保留稀疏黑隙，不增加点数。先用同点位、同镜头、同曝光输出 C/D 对照，确认单点及远景后再加运动。主色、核心尺寸、白芯、近晕和远晕须独立可调。以本文公式和逐粒 JSON 为数值依据，PNG 为已生成的外观依据；不要只按文字重新随机猜颜色。

## 版本区别，避免混用

- V09 C：柔肩＋弱宽外晕；D：更强的小白芯＋较紧近晕。
- V10 S200：只将主体芯和白芯尺寸扩大到 V09 的两倍，近/外晕不同比放大。
- V11 C_Soft / D_Soft：沿 V10 S200，再加三层宽而淡的彩色柔光。本包 PNG 与逐粒数据采用 V11；表中同时保留早期参数，若你指的是较紧的早期 C/D，可关闭新增柔光并使用 V09 尺寸。
- C/D 是两套替代方案，不是两层叠加。D 方案不等于文件后缀 D（后者原来表示溶解图）。

## 单颗星点公式：线性 RGB 中累加

坐标单位为 1024×1024 单格的像素，像素中心 (x+0.5,y+0.5)。逐粒 JSON 中 pixel 为中心，sigma 为基础宽度 s，angle 为弧度，aspect 为椭圆长短轴比，amplitude 为能量系数，color/hot 是直接参与线性计算的 RGB，不要再次做 sRGB 解码。

设 dx=x+0.5-px，dy=y+0.5-py，r²=dx²+dy²；u=dx*cos(angle)+dy*sin(angle)，v=-dx*sin(angle)+dy*cos(angle)。G(a)=exp(-0.5*r²/(s*a)²)。a 是高斯标准差倍数，不是硬边半径。

| 项目 | C | D |
|---|---:|---:|
| V11/V10 主体标准差倍数 b | 1.44 | 1.44 |
| V11/V10 白芯标准差倍数 p | 0.48 | 0.48 |
| 白芯峰值 w | 0.9 | 2.0 |
| 近晕标准差 n | 3.0 | 2.0 |
| 近晕峰值 h | 0.028 | 0.045 |
| 外晕标准差 / 峰值 | 8 / 0.003 | 8 / 0.003 |

V09 则使用 b=0.72、p=0.24，其余表中值不变，无新增柔光。

```python
# 可移植伪代码：标量运算可直接转 GLSL/HLSL/节点。
body = exp(-0.5 * ((u/(s*b*aspect))**2 + (v/(s*b))**2))
pin = w * G(p)
near = h * G(n)
outer = 0.003 * G(8)
# 仅 V11：新增宽柔晕，峰值很低；不是把白芯放大。
R = max(12, min(px, py, 1024-px, 1024-py) - 12)
t = clamp((R-sqrt(r2))/(R*0.30), 0, 1)
edge = t*t*(3-2*t)
soft = (0.022*G(6) + 0.006*G(14) + 0.0014*G(23))*edge
RGB_linear += amplitude * (
    body*hot + pin*vec3(1,1,1) + (near+outer+soft)*color
)
```

这一公式说明：强白色被限制在非常小的 pin 内；彩色主体和宽彩晕承担色相。D 比 C 更锐亮，但不是整颗星变白。edge 只收敛新增柔晕，防止图格边缘截断，不作用于原主体/近晕。增大晕宽会增加积分能量，不能称为“亮度不变”。

精确像素复现还需短尾：遍历 trail_pixels，令 step 从 0 开始，L 为长度；每个尾采样加上 amplitude*color*0.095*(1-(step+1)/L)^1.2*exp(-0.5*distance²/(s*0.5)²)。没有长拖尾；若省略，这是相似复现而非逐像素一致。V11 实际局部绘制窗口半径 ceil(85*s+3)，按中心 int(pixel) 向两侧截取，限定在单格内。

## 颜色与疏密

stars_0.json 至 stars_3.json 分别对应青碧、玫红、蓝紫、橙金四类；点数为 56/64/64/56。每颗星的实际 color、hot、amplitude、sigma、aspect、angle 已附，不用全团统一色或全白核替代。JSON 还有历史字段；halo_sigma、halo_gain 不参与上述 V11 光核，不要误用。需要完全相同布局直接使用 pixel；换分辨率时中心与所有宽度统一按新单格尺寸/1024 缩放，别把 s 当世界单位。

保留固定点位、逐粒明暗/尺寸变化；不是在圆盘内均匀撒相同大点。四格按 01左上、02右上、03左下、04右下拼接为2048²。贴图是四种静态造型，不是四帧动画。

## 烘焙与颜色编码（复现原 PNG 的关键）

先将所有粒子的浮点线性 RGB 相加，再对每个像素执行统一分母压缩：

```python
mapped = raw / (1 + max(raw.r, raw.g, raw.b))
srgb = where(mapped <= 0.0031308,
             mapped*12.92,
             1.055*mapped**(1/2.4)-0.055)
# 原实现：numpy.random.default_rng(902144).random((1024,1024,1))
# 每像素一个固定随机量，RGB共享，不逐帧变化；每格重置同一seed。
byteRGB = floor(srgb*255 + fixed_random_0_to_1)
byteRGB = clamp(byteRGB, 0, 255)
byteRGB[max(mapped.r,mapped.g,mapped.b) < 1e-6] = 0
```

注意分母是每像素 RGB 最大分量，不是全图最大值，不是各通道分别压缩，也不按每颗星单独归一。随机量用于8位量化减轻弱晕色阶，不是闪动或运动 Noise。

原素材是黑底 RGB、无 Alpha；彩色主图用 sRGB 采样。已有试机设置是 BC7、2048²。要复现原贴图路径，应在导入后只解码一次 sRGB；不要直接把编码后的 RGB 当线性光相加。固定引擎材质的黑底提取会改变弱晕，不承诺另一个工具与引擎截图逐像素一致。

若新工具直接输出 HDR 发光，可从 raw 开始，使用目标工具的曝光/色调映射；此时不要再照搬上述 LDR 压缩并宣称等价。PNG 已有烘焙光晕，额外的实时 Bloom 先关闭再逐步增加，避免重复扩散。原引擎颜色倍增10/20仅是历史测试条件，不是所有软件通用的发光值；提高倍增也可能令彩色区域趋白，不能保证任何强度下都保饱和。

## 验收与排错

1. 黑底同曝光看单点：小亮芯、带色主体、柔弱远晕均能区分；不能变成硬圆盘、大白点。
2. 同镜头看整团：点间有黑隙，四类色相分组清楚；不为“更亮”增加粒数。
3. 缩到实际观看尺寸检查细点是否消失；需要加大时单独改主体/白芯宽度，不把整个宽晕一起加粗。
4. 加亮后变白：先检查白芯面积、RGB通道比例、曝光/色调映射与重叠，别只继续加 Bloom。
5. 晕不明显：先确认线性处理、弱值是否被黑底提取/阈值/Alpha再次压低，再调晕强度；外部既有材质不可擅改。
6. 本轮仅复现色光，不迁移 V11 的旧5秒编排或把其尺寸曲线当真实弹道。需要动态时另接已选运动；本包不含爆裂物理求解器。
