# 选中导演掉帧：原因、实测和处理（本机同步 8，2026-10-13）

用户 11:37：「之前 Codex 去掉重复内容后帧率正常很多，我现在看又开始掉帧明显了，是因为高低差导致模板数量激增了么？」

## 原因

10-09 卡顿报告的结论仍然成立：卡在 Details 面板，选中导演（或打开导演蓝图、看类默认值）时，编辑器要为导演表里的每个结构、数组元素、字段各建一行属性，每帧都要过一遍。UE 实测约每千行 2 ms，表越大越卡。

| 导演表 | 子模板 | 父模板 / 条目 | 属性行 |
|---|---|---|---|
| 10-08 Codex 去重前 | 13 | 252 / 1689 | 5.5 万 |
| 10-08 Codex 去重后 | 17 | 43 / 247 | 1.1 万 |
| B01 16.0.15（Failed 导演 _7） | 45 | 115 / 724 | 2.7 万 |
| B02 16.0.20（高差没进 UE） | 52 | 147 / 780 | 3.0 万 |
| 16.0.21（高差烘进子模板，1 m 一档） | 398 | 147 / 780 | 5.0 万 |
| 16.0.22（只往上，你 11 点导入的） | 309 | 146 / 771 | 4.4 万 |
| **16.0.23 修订3（10 m 一档 + 不写没被引用的子模板）** | **138** | **141 / 734** | **3.3 万** |

- 高差确实让子模板翻了好几倍（52 → 309），属性行多了约 50%。
- 但大头一直是父模板：B02 有 978 发、734 条不重复的父条目，单这部分就 2.3 万行，比 10-08 去重后的整张表还大一倍。那时是 252 次调度但只有 43 种父模板。

## UE 实测（Night 导演，只改场景实例内存，测完写回并核对，未保存）

帧率 = 日志行帧号差 / 墙钟时间，每段 6–8 秒。本机是远程桌面。

| 状态 | 帧时间 | 帧率 |
|---|---|---|
| 选中导演 + 导演蓝图窗口开着（你今天上午的状态），16.0.22 | 200–207 ms | 约 5 |
| 不选中，蓝图窗口开着 | 114 ms | 8.8 |
| 不选中，**蓝图窗口关掉** | 24–26 ms | 39–41 |
| 选中导演，蓝图窗口关掉，16.0.22 | 111–114 ms | 约 9 |
| 选中导演，蓝图窗口关掉，**16.0.23 修订3** | 97 ms | 10.3 |
| 选中导演 + 蓝图开着，换成没高差的表（对照） | 172 ms | 5.8 |
| **点了预览后取消选中**（蓝图关着，从 86 s 起放，137 个粒子组件照常生成） | 28 ms | 36 |

- 导演蓝图 `BP_NewYearFireworks_ShowDirector_Night` 的编辑器窗口从 10-12 20:17 起一直开着，类默认值里也是同一张大表（导入时蓝图默认值和场景实例一起写），一直吃掉约 90 ms/帧。测试时已经关掉了，没重新打开。
- 数据侧最多只能省 20–30%：就算完全不要高差也有 2.6 万行，选中照样只有 6–10 帧。根治要改编辑器的 Details 显示（见 `协作/导演Actor卡顿修复计划_2026-10-09.md` 第二阶段），需要引擎开发做。

## 处理

1. **用法（立刻见效）**：用完导演蓝图就关掉它的窗口；在 Details 里点了预览以后，在视口空白处点一下取消选中，预览照常播放，约 36–41 帧。
2. **数据（16.0.23）**：修订3 把高差取整到 10 m（小 0/10/20/30、中到 40、大到 70），点位、时刻、档位、发数和修订2 一样，重叠体检同为 9 处（都是余烬后压前）；导出时不写没被引用的子模板。属性行 4.4 万 → 3.3 万，选中时 114 → 97 ms。
3. 文件：`fps-ab*.mjs / .json`（`fps-ab.json` 里第一段的帧率被同名标记算错了，以本文为准：534→564 帧 / 6.02 s = 5.0 帧）、`size.mjs`、`quantize.mjs`。
