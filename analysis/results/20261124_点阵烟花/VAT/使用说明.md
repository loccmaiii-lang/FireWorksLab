# 兔子点阵 VAT 素材

这一份可以直接作为 UE 导入源。它由 Houdini 20.5.487 的 SideFX Labs VAT 3.0、Particle Sprites 模式生成。轨迹包含 476 个兔形灯点，另有 1 个独立的爆心短闪，全部使用稳定 ID。星簇沿四周绽开，内圈相对放大，耳朵和灯棒在展开途中连成兔形。第 48 帧定形，随后沿原轨迹散开，余火渐暗到全黑。图案高约 200 m，完整正方形画布边长 236.14 m。手机与 PC 可以共用此份数据，手游顶点纹理读取、材质编译、实际纹理格式和显存仍待目标机验证。

| 文件 | 用途 |
| --- | --- |
| DotRabbit_mesh.fbx | FBX 2018，477 张四角光点卡。UV0 用于光点外观，UV1 索引动画，另有两个记录边界的数据三角形 |
| DotRabbit_pos.exr | 477×110 RGBA 半精度浮点，RGB 为 UE 局部厘米坐标，A 是 VAT 编码的相对点径 |
| DotRabbit_col.exr | 同尺寸，RGB 存线性色相乘当帧亮度，A 恒为 1。即使现成材质仅消费 RGB，末段也可渐暗 |
| DotRabbit_data.json | 原生 ROP 的 6 个 Bound 值和 Houdini FPS。小数含解码元数据 |
| bake_vat.py / verify_vat.py | 从共享轨迹烘出 FBX、EXR；从成品重新读取三角、纹理、位置、颜色和点径 |
| vat_player.js / vat_data.js | 对照页的 WebGL 2 播放器和素材的网页封装。顶点 shader 从真实半浮点数据取位置，两个 UV 与三角拓扑取自 FBX |
| verify.json | 此版全帧误差、纹理尺寸、几何统计与 SHA-256 |

## 顶点与时长

每张四角卡复用 4 个角，组成两个三角形。477 张可见卡共 **1908 个控制点、954 个三角形、2862 个三角形角索引**。FBX 另有 2 个记录编码边界的三角形，各用 3 个独立控制点，整份网格合计 1914 个控制点、956 个三角形、2868 个角索引。静止成形段有 476 个发光图案点，额外的引子卡只在开头短暂发光。网页剔除数据三角后按三角角展开，每次提交 2862 个卡片顶点输入。UE 静态网格 LOD0 的渲染顶点数还受引擎导入与构建设置影响，须在网格编辑器读回。

此份 VAT 每帧占一行。64 帧是上一份演示的长度。此版把 Houdini 的开始／结束帧设为 1 和 110，按 30 Hz 读取全部 110 行，纹理高度随动画时长变化。将来换时长时重新生成网格、两图与 bounds，并同步修改粒子寿命和材质时钟。给定 F 帧和采样率 R，寿命为 F/R 秒，Dynamic[0] 曲线的末段在年龄 (F−1)/F 时到达 (F−1)/R 秒，然后保持到年龄 1。

## Medic 案例的实际结构

在本机运行中的 UE 4.24.2 读取了指定 PS，原案共五个发射器。VAT 是对象名 `ParticleSpriteEmitter_0`、Type Data 里 Mesh 为 `SM_EFX_T_EFX_Medic_3x_Cards_01_mesh` 的**第三个发射器**（Emitters[2]）。其余层包括光晕和火花，复制整个 PS 播放会污染 A/B 结果。

该层一次 Burst 1，Local Space 开，Type Data 勾 Override Material，Required 的 MI 是 `MI_VAT3_ScaleByVelocity_Color_Medic_3x_01_Inst`。母材质为 `/Game/MaterialLib/Materials/FX/Parent/VAT/M_VAT3_Sprite_ScaleByVelocity_WP`。实例的 Position Texture、Color Texture 各为 1024×900，两者使用 HDR、Nearest、关闭 sRGB；外观遮罩另接现有 `T_EFX_Glow_Mask_01`。原案 Houdini FPS 24，TimeOverride 时钟曲线以 6.5 结束，速度、点径、粒子颜色、整体变换另有曲线。原案还打开了 NeverStream，固定 PS Bounds 为 ±600 cm。上述字段均为案例读回值。

## UE 空闲后的独立沙盒接法

以下为本 demo 的接线与试播起点。项目中尚未创建新 PS / MI，未在 UE 或手机实际播放。

1. 在独立沙盒导入 `DotRabbit_mesh.fbx` 为 Static Mesh，单位 cm、Import Uniform Scale 1，保留 UV0 和 UV1，关闭 Generate Lightmap UVs、Remove Degenerates 与自动 LOD。保留 VAT 边界三角和原始网格 bounds。未导入材质。
2. 两张 EXR 作为**数据贴图**导入，Compression Settings = HDR（保留 RGBA 半浮点），sRGB 关、Filter = Nearest、Mip Gen Settings = NoMipmaps、Never Stream 关、LODGroup = DistantVFX。保持原尺寸 477×110，禁用重采样、缩尺寸、MipBias 和有损颜色压缩。核对目标格式实际支持 RGBA16F 的顶点阶段采样；若手游设备或项目组限制会压缩或丢 A，先在该机型验证。两图预算约 0.801 MiB（839,520 字节），未计遮罩、网格、对齐和实际目标平台分配。
3. 从原案例复制对应发射器和实例到沙盒，给 Type Data 指定新网格，Required 指定实例副本。Instance 的 Position Texture / Color Texture 换成各自 EXR。保留 UseVATColor、UseTimeOverride、Support Legacy Parameters and Instancing。关闭 Particles Can Spin，便于检查圆点。Tex_Color 取现有 `T_EFX_Glow_Mask_01`，Tex_AlphaChannel 为 (1,0,0,0)，Color 为白 (1,1,1,1)，Alpha 为 1。
4. 材质实例按 `DotRabbit_data.json` 原样填六个 Bound 数值，包括小数。Houdini FPS 30、Playback Speed 1、Game Time at First Frame 0、TimeOverride 初值 0。Mask U/V Scale 各 1；Global Particle Scale Multiplier、VAT_AddPsScaleUniform 初始都设 1。Particle Width / Height Base Scale 等宽，先用 **240 cm / 240 cm** 看正面静帧，单独微调这对值来匹配点隙。原案 20 / 20 和 40 倍总缩放针对纸牌。当前宽度建议尚未经母材质验证，目标是开花就位时相邻白点中间确有暗谷。
5. Cascade 只发一次。Required 的 Local Space 开，Duration 3.666667 秒、Loops 1、Delay 0。Spawn Rate 0，Burst 在 Time 0 发 1 个。Lifetime 恒 3.666667 秒，Initial Size XYZ 均 1，粒子速度/自转 0，Size Scale、Size Multiply Life 恒 1，Color Over Life 始终白，Alpha Over Life 恒 1。保留原网格层朝向作为第一轮机位测试起点。正面 XZ 图案需要朝向观众的设计机位。
6. Dynamic Parameter 的第 0 路 `TimeOverride_Param` 用 DistributionFloatConstantCurve，使用粒子归一化年龄，线性键 (0,0)、(0.990909091,3.633333333)、(1,3.633333333)，勾全过程更新。第 109 帧在 3.633333 秒到达，末个 tick 把材质时钟留在黑帧，到期正常退出。第 1 路 `ScaleByVelocity_Param` 常数 0，关掉随速度拉长；第 2 路 `Param3` 常数 1，第 3 路 `VATPSScale_Param` 常数 1。若成形停住时圆点也消失，优先查速度高度乘数，将时钟停在 1.8 秒检查。此处输入按**秒**，现有 Baker 的 Dynamic[0] 使用序列帧号。
7. 对 **ParticleSystem 自身**打开 Use Fixed Relative Bounding Box，沙盒首轮 Min=(-15100,-15100,-15100)、Max=(15100,15100,15100) cm。取值包住形状与卡片余量，适合检查移近视野边缘。材质六个 Bound 携带帧数、行数与点径等元数据，保持 JSON 原值。把整体摆入视野后检查转镜、边缘裁切和重新触发。

## 比较与复生成

网页用窄核与宽晕渲染兔形灯点，用独立高斯光斑渲染起势处的小引子，两路参数同步。原案例的一个材质实例共用 Glow 遮罩。引子光点的半径、强度和持续时间来自真实 VAT 纹理，它在 UE 中的具体轮廓需结合该遮罩复核。VAT 着色使用真实动态 Cd，烘焙器可以按灰度分别走三张 Ramp。实际 UE 会用项目 Glow 遮罩、母材质与游戏自身曝光。网页展示的点心轨迹、色相、明暗和卡片索引经过成品回读，Glow 遮罩、场景 Bloom 和动态通道的最终效果须在游戏里核对。

Windows 在本目录执行以下命令。第一步需要 Houdini 及 SideFX Labs VAT 3.0，第二步使用安装 NumPy 与启用 OpenEXR 的 OpenCV 的 Python。临时逐帧点缓存会自动清理。

```powershell
& 'D:/FXTools/Houdini20.5/bin/hython.exe' ./bake_vat.py
python -X utf8 ./verify_vat.py
```

脚本给每个灯点稳定的 id，逐帧写 P、pscale、Cd、Alpha，使用 Particle Sprites / Unreal Engine / HDR 导出。对照页直接双击上一级的 HTML 即可。替换图案时先更新共享轨迹，再运行这两步；调点位、颜色或运动均须重新生成数据。

验收时先拖看第 6、21、36 帧，观察初始星簇、兔耳与灯棒逐渐可读，以及外圈减速。再看 48–67 帧的停形、89 帧之后还在移动的余火、109 帧的全黑，以及重新激活。逐项核对兔耳、棒与嘴的点阵配色、静止段速度归零后的点径，以及最后一帧和画面边缘。在 800 / 1000 / 1200 m 比较低档和常用画质，在相同实例数下分别记录 GPU 时间、过绘和卡片解码成本。当前两张纹理以完整 477×110 尺寸读回，点心的最大误差折算至 512 像素画布约为 0.1214 px。

与上版 87a62ea5 的 EXR 成品逐值对齐，第 48–109 帧合计 29,574 个点样本，两张纹理所有通道及对应解码范围均相同。

Edge 的独立 512² WebGL 回放从最终半浮点纹理取数。第 89、99、105、107、108、109 帧的画面 RGB 峰值依次为 209、132、61、33、17、0（0–255）。在第 108 帧即 3.600 秒仍有余光，第 109 帧即 3.633 秒时整个画面全黑，3.667 秒寿命结束。这个结果同时检查了素材、顶点取样与光斑绘制；项目里的曝光和观察距离会影响人眼看到余光的时刻。
