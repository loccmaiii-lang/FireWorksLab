# 点阵烟花序列素材包

`DotRabbitDemo/` 可供项目烟花导入器的手动素材入口选择。PC 选 `cascade.json`，手游选 `cascade_mobile.json`。名称已经使用独立的 `DotRabbitDemo` 前缀。开发源码里没有 `df.pattern-points/1` 的读入入口，本 demo 在仓库外部轨迹与烘焙器原序列导出之间加了一层适配。

| 项目 | PC | 手游 M |
| --- | --- | --- |
| 同屏面片 | 3 个，白、金、青各有独立 Ramp | 1 个，白色合层 |
| 主序列 | 3 张 2048²，单格 512² | 1 张 1024²，单格 256² |
| 容量估算 | BC7 无 mip 主序列共 12 MiB | 如采用每像素 8 bit 压缩，基础层 1 MiB，完整 mip 链约 1.33 MiB。实际取决于设备压缩格式和驻留层级 |
| 成形段采样 | 逐层识别到 318、125、33 个峰 | 单格识别到 476 个独立峰 |

单次播放 110 个 30 Hz tick，约 3.67 秒。第 0 帧为爆心白闪，之后的 476 颗星按型物模板的展开方式进入兔形。第 48–67 帧停形，第 68–89 帧沿用原来的 22 帧消散。第 90–109 帧余火继续下落、逐渐减弱，第 109 帧完全熄灭。

PC 白、金、青三个发射器分别使用 64、63、63 个格位，金、青在第 1 tick 开始。手游使用同一页的 64 格。应用按每层自己的寿命、发射延迟与帧号曲线取格，成形停留时一直显示同一格。手游在 256 像素单格内为下落余火增加 7.5% 的固定取景宽度，面片尺寸同步放大，保持兔子在世界中的高度约 200 米。每组 Cutout 由该层所用的全部采样生成。

关闭额外的场景 Bloom 时，CPU 解码原包测得第 108 帧的最高显示值为 PC 白层 14.57/255、手机 9.65/255，第 109 帧的两项均为零。本轮在实际走查中仍需观察目标平台的 mip、TAA 和曝光对远距离点隙的影响。

## 重新生成

在仓库内打开此目录，运行以下命令。需要 Python、NumPy、SciPy、Pillow 和 Node 22 或更高版本。脚本从相邻的 `shared/` 读取轨迹与世界尺寸。

```powershell
python -X utf8 bake.py
python -X utf8 verify.py
```

`bake.py` 对每颗光点做亚像素覆盖积分，按 16 格一组依次写入 R、G、B、A。`pack.cjs` 调项目 4.9.138 的 PNG、Ramp、Cutout、多层 Cascade 配置、统一命名和 `packFinalize`，再用离线导入器核对配置与目标路径计划。生成图片时保留了 Alpha 通道中的帧数据。用普通预乘 Alpha 的图像工具另存图集会损坏其他三个通道。

`verify.py` 对 PC 和手机分别运行仓库 `回放检查.py`，核对每张 PNG 的 SHA256、110 个 tick 的选格、各层尾段光量连续下降和最后零亮度。第 57 帧以附近的局部峰匹配原始点位，PC 各层最大偏差 0.45 格内像素，手机最大偏差 0.68 格内像素。两平台都展示了全部有效格位，未出现裁边、回跳或无用的中间和尾部黑格。尾段整体亮度由 `ColorOverLife` 驱动，保持量化精度，也让曲线在可播放的最后一帧到零。报告和关键帧图位于本机 `analysis/local/20261124_点阵烟花/Baker/`。UE4.24 实播和目标设备的实际画时待核对。
