## 解决了什么

- **原因**（引擎着色器核实）：LiteHDR 每次绘制先把颜色压缩（`J3BasePassOutColorCompose.ush` 第 56 行），半透明 / 加色混合在压缩后的值上做。颜色倍增一高，三通道都压到接近 1，再被 alpha 混合就成了灰白；亮度也会明显掉。所以 `_M` 现值在 LiteHDR 下又暗又白（发白比例 W 0.8–1.0）。
- **3.0 原来三档都指同一个 `_M`**：现在 `_H` 单独一份，手游表 FxSP_High 指 `_H`，FxSP / FxSP_Low 仍是 `_M`。
- **`_M`（LiteHDR 开）**：每个发射器颜色总倍增 ≤ 3（ColorScaleOverLife），亮度靠 alpha ×4–×8。LiteHDR 下颜色恢复，亮度从现值的 0.2–3.5 提到 0.8–28（随效果大小不同）。和 `_H` 新值的差距（亮度对数比 + 饱和度 + 发白 + 色相）：16 个从 2.4–5.1 降到 0.14–0.77；点灭星 2.49（随机色，打分不可靠），金垂柳 2.13——`_M` 是满金色，`_H` 是更亮、带白热芯，LiteHDR 下做不出白热芯又不发灰。
- **`_H`（LiteHDR 关）**：偏暗的发射器颜色提到最多 3，alpha ×2–×4，亮度约 1.25–3.8 倍（点灭星不变），颜色不变灰。

## 怎么定的值

同机位、同一时刻（0.15T、0.4T）、黑挡板模拟夜空，`_H` 试 现值 + c{1,2,3}×a{1,2,4}，`_M` 试 现值 + c{1,1.5,2,3}×a{2,4,6,8}，按亮度 / 饱和度 / 发白比例 / 色相打分，再逐个看图。c = 每个发射器颜色总倍增目标（min(现值×c, 3)），a = alpha 倍数。

人工改了两处：
- 金垂柳 `_H`：alpha ×4 偏白，改 ×2。
- 点灭星：颜色每次随机、又会闪，打分不可靠，按 3 次重复拍判断：`_H` 原本就 ×100、不暗，保持不动；`_M` c3a8 在 LiteHDR 下亮，而且有粉 / 黄色。

## 需要你确认 / 剩余差异

1. **「颜色 ≤ 3」我只用在 `_M`**。`_H` 里原本就高于 3 的发射器保持原值、没往下压（红彗星星头 2500、金垂柳 10、银冠菊 10、银星扇 12、点灭星 100、尾缀 4–6、闪光层 4）。原因是压到 3 会丢掉红彗星星头的光球。如果你的意思是 `_H` 也要 ≤ 3，告诉我，我按同样流程重做 `_H`。
2. **红彗星 `_M`** 星头在 LiteHDR 下只剩小红点，做不出 `_H` 那个光球；**金垂柳 `_M`** 没有 `_H` 的白热芯（都是颜色 ≤ 3 的上限）。
3. **alpha 提高的副作用**：Translucent 材质 alpha ×6–×8 会更多遮挡后面的东西。白天天空下，点灭星 `_M` 每个亮点外面有一圈暗边；夜空下看不出来。多个烟花前后叠在一起时有没有发暗，**没测**。
4. **没做的**：窜天猴 sku 5 行（GlitterChry、SkyRocketTail、Smoke、SkyRocketSprint、SkyRocketSparkler）。它们多数发射器没有 ColorScaleOverLife，颜色曲线到 10–200，还共用很多资产都在用的材质实例，要改曲线本身，另做。`SkyRocketSparkler_H` 早就存在但表没用它，没动。
5. **验证范围**：只在编辑器手游预览里用 `r.Mobile.OnePassLiteHDR 0/1` 看过，没有中低端真机、没有打包，也没看编排整场。
