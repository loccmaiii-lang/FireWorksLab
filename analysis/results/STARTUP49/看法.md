# 启动效率：4.9.47 → 4.9.49

## 问题与改动

用户要求测试初次打开变慢并优化。源码及隔离实测显示：启动预先同步编译全部显卡程序；随后为默认/上次效果烘焙。并非所有功能都会在首次打开用到。

新增 `lazyProgram`，程序首次读取 p/u 时才调用原编译逻辑，成功后替换为普通属性。40_gl.js 的 shader 文本、编译内部步骤均未改。所有参数、输出版本、贴图规格和自动烘焙行为保留。

## 速度证据

Windows / RTX5080 / Chromium / 1366×768，独立浏览器资料；前后交替各3次，中位数。`startup.json`、`startup-combo.json` 保留每次原始数据。normal为无存档时自动打开金芒菊，combo为测试资料标记旧候选已看并恢复金蕊柠四层；不读取用户原浏览器资料。

| 场景 / 指标 | 修改前 | 修改后 | 变化 |
|---|---:|---:|---:|
| normal 首屏内容绘制 | 1.900秒 | 1.504秒 | 快20.8% |
| normal 脚本可调用 | 1.702秒 | 1.301秒 | 快23.6% |
| normal 烘焙及细化空闲 | 4.527秒 | 4.174秒 | 快7.8% |
| 四层首屏内容绘制 | 1.812秒 | 1.460秒 | 快19.4% |
| 四层烘焙及细化空闲 | 15.046秒 | 14.334秒 | 快4.7% |
| ?fast 脚本可调用（不开效果） | 1.496秒 | 1.106秒 | 快26.1% |

初始化定位的单次插桩：原显卡编译约857ms；空资料localStorage累计约0.5ms。页面及三份外部JS约4.88MB。这些数据不能用于判断用户自己的存档容量；不建议据此清空存档。

限制：真实个人存档、扩展、后台GPU占用会改变耗时；四层仍需约14秒烘焙，当前优化主要减少首屏工作。没有降低效果复杂度或精度。?fast仅用于定位，正常工作入口不需要加它。
