## 条目体检（一个页面里挨个打开）：还有两个超时

- 待验收的：金芒菊、青柠星、鸿巢、两种尾缀都正常，烘焙中帧数 122–141 / 140（不卡）。鸿巢烘焙 3 页 1.8 + 2.1 + 0.3 s，等显卡 117 次共 3.7 s。
- **引菊 → 锦（接在鸿巢后面）、片贝（接在永丰后面）超时**：等显卡 1851 / 2394 次，每次约 160 ms，每批的量掉到最小 0.2M 粒。
- **原因**：检查里实时模拟默认不压子样本，上一个效果（鸿巢）的实时模拟一帧就要 26.6 ms 显卡时间（SMOKE19 量的），新效果烘焙时显卡一直被它占满；烘焙的每次等待都排在实时模拟后面，看起来「每次都很晚」。4.2.25 把「等得久」当成「这批太大」，每次按比例压小，压到最小以后又是一次只交 1 个子样本。用户实际使用时实时模拟会在烘焙中让出显卡，但笔记本上显卡本来就被实时模拟占满时一样会掉进去，所以要修。
- 球形 A / B（等 802 / 489 次、37 / 51 s）也是同样的拖慢，只是没到 300 s。
- 七夕、V3「缺贴图」：两个都是暂停 / 未开始的效果，主条目没有可烘的层（和这次改动无关，清理清单 A1 建议去掉）。

## 4.2.26

## 结论
