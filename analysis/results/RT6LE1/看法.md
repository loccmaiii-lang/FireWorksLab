# RT6SE1 / RT6ME1 / RT6LE1 看法（对话框15，2026-10-05 18:20）

审看：烘焙器 4.5.1 导出（本机 RTX 5080，每个约 0.7 分钟，17:42 发布）。三个包一起看，写在 RT6LE1。

- **回放检查**：
  - 近段 RiseLoop 过曝 大 1.5% / 中 0.7% / 小 1.1%，远段 TrailFar 0.4% / 0.5% / 1.1%（上限 2%）。
  - 帧号不回跳、碰边 ≤ 0.1%、没有空帧。
  - 大 / 小全过；**中档 RiseLoop 没过：「中心抖动 3.96 px（512 格）」**，上限 3，第 43 帧。
- **为什么中档抖**：这一项只对写了 Size By Life 的层查（原意是查 Zoom 取景整体抖）。RiseLoop 是真循环，亮部中心随喷射脉动（rtPulse 0.2、6 Hz）前后挪。
  - 近段面片比 RT5 短一大半（160 m 对 400 m），同样挪 1 m 在 512 格里是 2.5 倍的像素：RT5M 1.19 → RT6M 3.96；RT6L 1.82、RT6S 1.99 也比 RT5 大。
  - 3.96 px（512 格）= 面片上约 1.2 m，一百多米长的尾迹里看不出来。按标准这一项仍算没过，不进就绪；要改检查口径（循环层不按 Zoom 查抖动）还是降脉动，等用户定。
- **烘焙回放**（RT6L，实时 vs 导出，0.66–5.96 s）一致：
  - 近段亮段 + 远段大量停在空中的火花；0.8 s 起远段出现，交接处看不出缝。
  - HUD 里远段帧号走（16/64 → 41/64）。
- STD11 放行（标准检查）。

结论：大 / 小等 STD11 回来就绪；中档等中心抖动的口径定了再说。没经过 UE 验证：两段交接、远段帧率、TrailFar 竖直朝向、GPU 远看大小。
