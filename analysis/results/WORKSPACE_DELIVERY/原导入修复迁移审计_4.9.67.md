# 4.9.67 原导入修复迁移审计

用户要求核对旧导入器历史修复是否漏搬，并修复截图中 RiseTrail_M 更新同名时 PC/手机共享 Ramp、两个 Cutout 的目标冲突；接续原下一步 List。

## 结论与修正

旧执行修复模块未漏搬。八个原生模块的现行源码全文均包含在原工作台、独立交付入口及本机 runtime 中；未从旧备份重建执行器。本轮修的是原控制器的批次检查缺陷，以及交付呈现对原控件状态的保留。

1. 单个平台改设置后 `preview([id])` 只重查这一包，丢失与同批另一平台的共享纹理关系；逐包检查又过早混入旧提案，重新检查可能继续卡在旧冲突。现在先清除所选批次旧提案，按完整所选批次重建共享计划，再统一判定冲突。相同内容的共享贴图只计划一次实际写入；不同 SHA256 内容碰到同一正式名仍阻止。
2. 同批重查只将用户请求的包作为当前核对对象，避免改手机包后跳回 PC。仅无关、未被用户请求重查且完整计划指纹完全一致的旧确认可以保留；源、依赖、操作或目标变化以及显式重新检查仍要求新确认。
3. 清单区分“复用本批次贴图”与有保存证据的“复用已保存贴图”，不把批次计划说成已经落盘。RED后原/新入口共享检查各6组通过。
4. 完整设置中的原 GPU 峰值控件搬移后，原渲染器只在资产预览中找展开状态，导致编辑收起。独立交付构建适配读取同一原节点的展开状态，按包保留；原字段和原生处理器不复制。
5. 旧后端测试加载器只识别旧导出 API 边界，未真正覆盖交付入口。现在支持两种入口，对新 HTML 直接执行原回归；测试定位搬移后的原控件。旧命名完整性检查更新为本轮开工前已批准 v2.25 入口，包含后来批准的 FText/Unicode 保存修复，不把批准后的变化当成 10-05 快照破坏。
