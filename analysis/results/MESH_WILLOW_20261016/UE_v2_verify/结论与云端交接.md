## 3. 与云端结论的明确差异

### A. OBJ 映射不是预计的 x,z,y

本机实测导入默认转换为 UE=(OBJ.x,-OBJ.y,OBJ.z)，云端 gen_ue.mjs 预测的 x,z,y 在本机不成立。测试复制件预转换 p=(x,-z,y)，得到云端预计的UE包围盒；原包一字未改。`input/`留着修正版及显式法线，gen_ue.mjs后续应做可选导入目标坐标适配，先试件再批量。

### B. 颗粒遮罩的“结构相似”不代表数值相同

母材质实读：

```text
A = Noise.r + DissolveOffset + 2*(Param2 + Progress)
mask = smoothstep(clamp(hardness,0,1), 1-clamp(hardness,0,1), A)
```

云端 v2：`smoothstep(uTh-0.12,uTh+0.12,Noise.r)`。
原实例 hardness=0、Progress=0、DissolveOffset=0。Param2=0.6使A>=1.2，mask基本全1，颗粒被抹掉；建议值0.8/0.6/0.4不能直接称“颗粒阈值”。
在沙盒，uTh=0.34对应 hardness=0.38、Param2=0.08（Min=0.38，Max=0.62，A=noise+0.16），代数上等价cloud的smoothstep(0.22,0.46,noise)。本轮 `grainfix.json` 记录设置，截图有颗粒mask试件。独立复核指出该记录的 Param2=0.08 起初只是目标值；随后 `finalcheck.json` 补了 UE 真实读回：DP1运行表为0.0799999982，分布对象曲线同为0.08，完成该项读回。颜色、溶解对输出的其它乘项仍需锁定曝光比较。

### C. 镜头不转与省面数是实质取舍

锁轴允许单片省一半面数，但整朵会随相机方位转；固定十字不转，较符合用户原来的强约束。此次可比较两套，不推荐偷偷把锁轴当成“不旋转”。手游1998点试件只证明预算，是否允许锁轴仍由用户决定。

### D. 自动落盘与当前API陷阱

- `AssetImportTask.save=false`并不能约束`EditorAssetLibrary.duplicate_asset`；复制MI和PS已经自动建立12个uasset（MI_Plain/Grain、PS_*和PS_*R）。这与本机先前“全部只内存”的说法不符，必须明确更正。
- `finalcheck.json`列出这12个落盘文件的名称、大小、SHA256；网格 / 贴图仍没有该目录中的uasset，未另存，重启后这些粒子系统引用可能缺失。沙盒不是可正式交付的包；未提交P4，未删除落盘文件，避免再扩大操作。
- /object/set 对 JSON 数组有陷阱：未返回failed_properties也可能清空Emitters/Modules/LOD。首批PS_*因此无效，保留只作诊断。改成PS_*R：保留13发射器、关闭12个，仅LOD0测试；不声称手游LOD规范通过。
- 只修改Distribution对象并不能保证RawDistribution.LookupTable更新，需读回实际表。运行表本轮已核对。
