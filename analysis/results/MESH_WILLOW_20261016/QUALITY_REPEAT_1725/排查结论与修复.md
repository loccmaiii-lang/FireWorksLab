## 1. 确定的采样差异与修复

当前实际网格UV（`user_mesh_uv.json`）为 U=0…64、V=0…1.192698。U不是播放时间：每束用一个整数U偏移，宽度跨一个周期；V才是星头经过轨迹的时刻。

原贴图实读（`effective_texture_settings.json`）：
- MainTex=T_MW_Strip，AddressX=Clamp、AddressY=Clamp；Filter=Default；NoMipmaps、sRGB关。
- Clamp两个方向并不正确：U大于1的束会钳到横向边缘，不再采到完整的中心亮部／粗细。低、高默认过滤也受全局采样质量影响。

最终修复保持原16×1024像素内容、新建纹理与实例隔离其他引用：

| 属性 | 最终值 |
|---|---|
| MainTex | T_MW_FlowFixed（同原图内容，不是换造型） |
| Address X | Wrap：每束整数U偏移仍应平铺横向截面 |
| Address Y | Clamp：年龄／播放方向绝不能平铺 |
| Filter | Bilinear：不再跟TextureGroup Default改变过滤方式 |
| MipGenSettings | NoMipmaps |
| sRGB | False（保持该条带线性值口径） |
| MI UVParam | (1,1,0,0)，保持 |

最低后处理复测已能保留白热亮段与弧形长尾；同一后处理仅MaxAnisotropy=0/8时，两张图主体近似一致（ROI MAE 1.77/255、PSNR39.63，含动态天空，不能当最终画质分数）。全最低／全极高后处理仍有Bloom、曝光和AA的预期差异；本轮未为了“像素相同”强行开启最低配全局高档后处理。

证据：`compare_address_fixed/low_sampling.png` / `high_sampling.png`、`low_filter.png` / `high_filter.png`、`修复前后_高低配证据.jpg`。

## 2. 重复流动：已收口的事实与尚不能单因归责的部分

- 用户澄清“没消失就又流一次”，不是整朵重新开始。
- 原系统实读：Rate=0、Burst1次、EmitterLoops=1；DP0相对寿命0→1线性0.9941→−1.2049、UseEmitterTime=false、SpawnTimeOnly=false、bIsLooped=false。没有专门配置粒子无限循环。
- 原系统还有2个发射器／4个LOD：首发射器LOD0关、1–3开，但其Required共享模块关闭；不能仅凭LOD开就断言多出粒子。第二发射器为用户正在用的单片锁轴。
- 本轮删掉无效首发射器及遗留发射器LOD引用，最终只留**1个单片发射器引用／1个发射器LOD引用，Loops1**；系统LODSettings仍有4个空结构，不声称全部LOD元数据已删。Mesh、锁轴、RGB(40,16.7553,5.11368)、寿命16.1及DP0原曲线实读一致。
- 独立复核指出20:15的final_readback里唯一LOD临时为false；用户20:16确认高配正常后，20:22只读复核`after_user_confirmation_readonly.json`已为LOD=true、Required=true、临时Actor0。两次状态变化的操作者／原因没有记录，不自行推断。
- 同一复核还发现MeshRotation从排查初态关闭变成当前开启且随机值变化。本次修复脚本未写该模块，但不能把“所有朝向相关参数都没变”当成事实；保留用户刚确认可用的当前状态，不回写旧旋转参数。最低配应基于这个最终现场再验，不混用早期状态。
- V Clamp实读确实生效；没有被改成Shared Wrap。把U/V全部Clamp不会停止DP0时间更新，也不会防止组件重置时从曲线起点重算。
- 连续抽样35秒的原系统和诊断单发射器均没有记录到粒子消失后再生；每次激活一直最多1个活粒子。该计时是Slate累计dt，不是直接粒子年龄，不能将约26–30秒耗尽解释为寿命改错，也不足以证明同一存活粒子所有帧均无局部回跳。
- 用户20:16在实际高配上确认修复后只流动一次。**组合修复后的高配故障已由用户确认消失，但未完成旧发射器/LOD与采样寻址两项的因子反向复现，不能把重复现象的唯一本因全部归给其中一项。**

## 3. Panner、shader 与具体位置

### 主图材质节点（只读，未改）
`M_EFX_DissolveOutline_Soft:MaterialExpressionTextureSample_1`
← Add_1 ← Add_3：MF_FX_Panner输出＋DP0×UVIncrementChannel，再加可选扭曲。

`MF_FX_Panner:MaterialExpressionPanner_3` 的 bFractionalPart=true；但**取小数针对 Time×Speed 平移增量，不是整个UV坐标**。此处实例UVParam.ZW=(0,0)，该项平移增量为0；DP0在函数之后相加，所以不能把它说成DP0被frac导致周期回跳。

本轮曾做半区贴图／UV倍率0.5的诊断候选，后证据否定了“整UV取模”的推断；已拒绝，未写进用户PS_FixedR，脚本nofrac_assets/nofrac_apply/commit_user入口已禁用。不要复用MI_NoFrac试件。

### 云端预览
`tool/prototypes/mesh-willow-v2/index.html`：
- 主图shader采样 `texture(uTex,vec2(vUV.x,vUV.y+uDP0))`，没有frac／fmod。
- 主图U REPEAT、V CLAMP_TO_EDGE。
- 播放控制在t超过L后把t重置0，是**HTML演示循环**，不是UE材质代码；当前UE Loops1与之独立。

### 项目画质配置（仅查）
`DFM/Config/DefaultScalability.ini` 的 EffectsQuality@0／@Cine有MaterialQualityLevel、SceneColorFormat、DetailMode和发射率等区别；PostProcessQuality有Bloom／EyeAdaptation／AA区别。母材质顶层没有MaterialQualitySwitch分支。

实际试验分别切材质级别0/1/2、HDR格式3/4、过滤0/8、曝光／Bloom／SeparateTranslucency。前两者没有复现用户那种“弧形突然变直”的材质连线差异；显式后处理开关改变亮度／背景，不更换轨迹网格。对照图中的“low/high”是记录过的局部显式CVar组合，不代表UI里全部最低／极高预设；部分sg.*标签因控制台写入优先级没有同步，所以本轮不宣称完整档位通过。若要求低／高连Bloom视觉也完全一致，需要另定跨档视觉策略，不能靠改Clamp解决。

### 实际修复脚本
`analysis/scripts/网格垂柳_v2/quality_fix.mjs`：
- address_assets：创建同内容纹理，set_editor_property显式写U Wrap/V Clamp/Bilinear。
- apply_validated：只保留用户有效发射器／LOD0，换到MI_FlowFixed；不改用户曲线／RGB／朝向。
- save_validated、audit_final：三个保存返回true，磁盘SHA256与引用读回在saved_validated.json／final_readback.json。

`quality_test.py`、`quality_probe.mjs`：按正确CVar类型读回后做可逆实验。初次用get_console_variable_float_value读整数变量返回0并报警，那轮CVar数值不作证据；后续改get_console_variable_int_value且逐次记录真实值。

## 4. 验证范围与交接

- 已备份PS_FixedR原uasset，备份哈希一致；只存本轮白名单三个资产，不传uasset实体。
- 单片方案保留；高配20:16与最低配20:34均有用户实测正常回执，本次异常问题可收口。主体稳定不等于不同后处理逐像素完全一致。
- 本机复现方式是固定机位、暂停粒子组件Tick，再分别切Bloom/曝光/AA/半透明路径/MaxAnisotropy等CVar；拼图标注为局部参数对照，不是完整最低预设。没有用ForcePreviewLodIndex模拟整引擎低画质。Cascade中的粒子LOD和纹理过滤、后处理是不同控制层。
- r.MaxAnisotropy=0/8仅测试各向异性过滤上限，不是LOD0/LOD8，也不决定播放次数。最终修复是贴图固定Bilinear、U Wrap/V Clamp及发射器LOD收敛，而不是强制最低配使用r.MaxAnisotropy=8。
- 全质量像素完全一致未实现：Bloom／曝光差异仍存在，未改全局配置文件。当前重点是同一主体不丢白热／弧尾与一次播放。
- 本轮临时Actor与回调清理，最近可核对的CVar／相机恢复；收到用户高配正常回执后不再动其高配播放参数。
- 云端接续：保留U/V分工和显式Filter、删除旧LOD；不要再次按“Panner整UV frac”改母材质。下轮若最低配仍重流，需用户10–20秒录屏和当前引用核对，再对组件重置／质量切换更新展开，不能凭三张不同时刻截图补根因。
