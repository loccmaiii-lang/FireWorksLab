## 已知差异和风险（别当成已确认）

1. **尾巴亮度只随「年龄」变化**：来自烘焙器火花公式的整条火花云平均。金锦层火花率随时间上升（sparkRamp 1.01 s）、不同星的火花寿命随相位变化，这两点网格表达不了，同秒图里尾巴疏密会和烘焙器不同。
2. **橙引线层喷火花结束后的暗红小点没有做**：烘焙器同秒图（开花后 2.0 s，`金曜菊B/对照/烘焙器_橙引线层_t2.0.png`）里，橙引线层在火花停喷（约 1.2 s）后，星仍以暗红的短点烧到约 3.3 s；网格版轨迹只记到火花停喷，之后这一层是空的。亮度很低，但是可见差异。
3. **一束 = 一条带**：烘焙器里一颗星后面是一团火花云，网格版是一条带，细节靠颗粒贴图近似；头部目前是平头，烘焙器是圆的发光点。
4. **「单束的序列」没有做成序列贴图**：Soft 母材质只有普通 SubUV、没有 RGBA 接力；FireBase 有 RGBA 解帧但没有独立 UV 平移（本机 14:31 读回）。现在是静态条带 + UV 滑动（滑动已在本机 UE 验证）。要做真序列需要改母材质，这需要用户单独授权，本次未做也不建议。
5. **锁 Z 整朵随相机方位转**（本机实测）。手游 / 低配用它是因为点数预算，高配十字世界固定不转，更符合用户 06:20「不想看到旋转」的约束。手游若用十字，同样 2,000 点两层合计只能放约 76 束 / 层（ε 3 m；锁 Z 能放 153 束 / 层），这是锁 Z 的主要收益，也是用户要权衡的取舍。
6. **手游金锦层 p95 误差 2.8 m**（1 km 处约 3 px）是为卡进 2,000 点放宽 ε 的结果，不是 bug。
7. 颜色亮度的起步值没有 UE 依据（设置说明写了）。
8. 「2,000 点」我按**两层合计**算（更严）。如果用户的意思是每层 2,000，手游档束数可以翻倍。
