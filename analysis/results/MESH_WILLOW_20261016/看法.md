## 做了什么

- **朝向**：世界固定，不跟镜头转（Cascade Required `ScreenAlignment = PSA_Square`）。每束是两片互相垂直的带，沿轨迹用平行移动标架，从任何方向看都有一片是正面。
- **UV**：V = k × 星头经过时刻 / 4.8 s，材质 UV 匀速流动（Dynamic Parameter 0 从 0.75 线性到 −1.5417，寿命 11 s）。星头按真实减速走，尾巴按年龄冷却。
- **错落**（用户 06:20）：
  - 每束播放快慢 k = 1 ± 0.15（三角分布），像初速不同；
  - 45 % 的束提前 4–18 % 熄灭；
  - 条带贴图 4 列变体（尾长 0.8–1.3 倍、星头亮度、余烬断续），每束随机取一列。
- **规模**：200 / 300 / 400 束，每束平均 15.7 段，三角面分别 12.6 k / 18.8 k / 25.1 k（十字，所以比方案里的单片翻倍）。星头位置误差 p95 0.78 m（800 m 外 0.5 px），开花 0.6 s 内 3.1 m。

## 已知差异和风险

1. **余烬跟随**：烘焙器里星灭后余烬 0.45 s 内淡掉（emberFollow），网格只能整朵统一淡出（8.8 → 10.8 s），所以单束熄灭后尾巴会多留一会儿。
2. **混合方式**：母材质是 Translucent，烘焙器是光的加法。中心汇聚处会比烘焙器暗一点（预览已按 Translucent 算）。
3. **下垂高度**：这朵花从爆点往下垂 774 m。主角尾缀开花高度只有 400 m，原尺寸会垂到地面以下。要缩放或抬高，编排时定。
4. **更新模式**：UE 里 FixedTime@10 FPS 会不会让 UV 流动一跳一跳，还没测（沙盒里 N400 和 N400_RT 各一份）。
5. **轴向和 UV 方向**：轴向试件还没在 UE 里读回。

## ⚠ 已知局限（必须带着看）

1. **轨迹不是烘焙器核**：v2 用的是我按截图配方写的近似模拟（二次阻力 c = 9.8 / vt²、重力单独算；与方案轮廓表对照侧边 / 底部误差 1–3 %），**没有载入 `tool/src/js/20_sim.js`**。仓库里的 v1 生成器 `analysis/scripts/网格垂柳_生成.mjs` 是载入烘焙器模拟核的。用户 12:03 第 c、e 条意见（不是烘焙器轨迹）在 v2 里只是「更接近」，没有根治；根治办法是 v2 的条带 / 颗粒 / 朝向 / 导出用烘焙器核出的轨迹。余烬的实际受力参数也没取。
2. **UE 行为全未验证**：OBJ 轴向与 V 翻转（按 UE 导入器惯例推）；锁轴在 PSA_Square 下是否生效；条带贴图 sampler 类型；Param2 / 噪声溶解是否如预览建模（噪声 UV 是否 = UV0 × NoiseUVParam 且不加流动量、溶解是否乘在不透明度上，要看母材质表达式图确认）；FixedTime 10 FPS 下 UV 流动是否一格一格跳。
3. **混合方式**：UE 半透明混合，预览按 Translucent 估，中心交叠会比烘焙器的加法暗。
4. **锁轴的代价**：单片锁 Z 在绕行时整朵会跟着转（用户 06:20 说过不想看到旋转）；游戏机位 1 km 外平移 / 走动是否看得出，要在 UE 里判断。
5. 配方里的亮度倍数、颗粒阈值与 Param2 不是一一对应，需在 UE 里重新标定。
