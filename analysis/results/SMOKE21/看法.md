## 新页面里打开（实时显卡负担.py）：又卡住了

引菊 → 锦、鸿巢、青柠星都等到 300 s 上限（SMOKE20 是 4.5 / 6.7 / 1.9 s），只有金芒菊 1.6 s。

- **原因**（云端复现了，`实时负担检查.py` M7⑥）：4.2.26 的「显卡速度」按**估计的粒数**算，而且**一直带到下一次烘焙**。尾缀那类不按星轨道画的层，粒数估成接近 0，算出来的速度极小（条目体检里升空尾缀之后每批只剩 0.2M 粒）；之后的烘焙就按 20 万粒一批切，每个子样本等一帧——引菊 → 锦一帧最多 64 个子样本，一次烘焙要等几千次。新页面打开前已经烘过默认模板和尾缀，所以一开就掉进去。
- **4.2.28**：按真画了多少粒算（每次画都记数），每页烘焙从 800 万粒重新开始量，每个子样本多少粒也按上一批实测。M7⑥：先把速度设成极小再烘一朵菊，4.2.27 等显卡 143 次（44 帧），4.2.28 等 11 次。排 SMOKE22 复核（新页面打开、条目体检两种都看）。

## 用户的笔记本（RTX 4060 笔记本版）

大约是 5080 的 1/3–1/4（不是我前面写的 1/10–1/20）。按 SMOKE19 量的显卡时间换算（估算，没实测）：

| | 5080 实测 | 4060 笔记本估计 |
| --- | --- | --- |
| 鸿巢 不压（16 子样本） | 26.6 ms | 约 90–110 ms |
| 鸿巢 2 子样本（现在的下限） | 3.2 ms | 约 11–13 ms |
| 引菊 → 锦 专注 2 倍屏 不压 | 21.3 ms | 约 70–85 ms |
| 引菊 → 锦 专注 2 倍屏 2 子样本 | 2.9 ms | 约 10–12 ms |

结论：4060 笔记本上，现在的「按显卡负担少画子样本」降到下限时一帧 10–13 ms，够用，不需要再降一档。但这个自动调整只在慢于 22 fps 才开始少画，25–40 fps 之间不动，可能还是看得出顿。用户说会在 5080 上对照测一次：5080 顺、笔记本顿，就把自动调整的门槛提到「慢于 40 fps 就少画」。
