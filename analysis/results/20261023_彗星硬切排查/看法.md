# 彗星「没播完就硬切」排查（2026-10-23，LiteHDR，只读排查，没改任何资产 / 表）

## 结论

**原因找到：资源表的同 ID 实例上限，不是粒子文件，也不是导演逻辑。**

- 红彗星 `P_EFX_FireWorks_FanComet_01`（PC 表、手游表行 `跨年烟花3.0_小型_B_红彗星`）设的是 `MaxInstanceNum = 10`、`bLimitByMaxInstanceNum = True`。
- 导演通过 `UFXResourceContainerComponent::PlayEffect`（GPResource）按 ResourceId 播放。同一个 ID 同时在场超过 10 个时，FX 管理器会把最早的一个强制停掉。
- 粒子里的 `bKillOnDeactivate` 都是 False，所以这里的「硬切」是管理器强制停掉造成的，不是发射器自己的设置。
- **日志证据**：`Saved/Logs`（2026-10-21 11:17–11:21 的 PIE，`BP_NewYearFireworks_ShowDirector_Night_2`，PC、High）里有：
  `LogGPVfx: … AddParticle() … fx resource id: P_EFX_FireWorks_FanComet_01 … will be deactivated beacause of FXLimit: MaxInstanceNum (10).`
  按 HandleIndex 去重后，红彗星至少被切 511 次，银星扇 85 次，极小尾缀（上限 20）9 次，小爆裂 6 次，小金、绿牡丹各 2 次。HandleIndex 会重复使用，所以实际次数只多不少。
- **为什么彗星最明显（推断）**：彗星一个只活约 3.8 s，被切掉的「最早那个」通常还在飞，所以看得出来；银星扇拖尾长，最早那个多半已经在淡出，被切了不显眼。
- **为什么像是「PIE 才好复现」（推断）**：日志里的切除只出现在 PIE 世界。编辑器里直接预览导演，看起来没走这道限额。**打包后的游戏走的是同一个 FX 管理器，正式上线一样会切**，并不是 PIE 特有的问题。

## 同时在场数 vs 上限

估算方法：寿命取「发射器延迟 + 时长和粒子寿命里较大的那个」，算的是下限；按导演时间线展开到每个 FX；详见 `并发与日志.json`。

| 资源 | 夜场 B11修订3 PC 高配：峰值 / 上限 | 白天导演（编辑器里未保存版）PC：峰值 / 上限 |
|---|---|---|
| 红彗星 FanComet_01 | **144 / 10** | 10 / 10（刚好顶格） |
| 银星扇 FanSilver_01 | **158 / 10** | **35 / 10** |
| 极小尾缀 RiseTrail_Tiny | **37 / 20** | 8 / 20 |
| 小型尾缀 NY_Trail_Small | 17 / 20 | 20 / 20（顶格） |
| 中型尾缀 NY_Trail_Medium | 18 / 20 | 2 / 20 |
| 银冠菊、小银菊 | 9–11 / 10（按长寿命估算会超） | 9 / 10 |

另外：这些行还勾了 `bLimitByMaxFXTypeNum = True`（按 SHOW 类型限总数）。现在编辑器里 `fx.maxShow = 0`，Config 里也没设，日志里没有出现按类型切的记录。但夜场 SHOW 类同时在场有 257–379 个，以后谁给 `fx.maxShow` 设了值，会再切一批。

## 改法（要你定，我没动表）

1. **最简单（推荐）**：PC 表、手游表里 3.0 烟花用量大的几行，把 `bLimitByMaxInstanceNum` 改成 False：红彗星、银星扇、极小 / 小型 / 中型尾缀；银冠菊、小银菊也可以一起改。
   - 理由：节目密度已经由编排22按画质档控制，上限 10 是通用默认值，不是给烟花秀定的。
   - 代价：这几行不再有实例上限，安全阀只剩导演的分档。
2. **保守**：保留上限，把数值抬到峰值以上，留点余量：彗星 ≥ 160、银星扇 ≥ 170、极小尾缀 ≥ 45、小型 / 中型尾缀 ≥ 30、银冠菊 / 小银菊 ≥ 15。
   - 代价：以后编排加密了还会撞上限。
3. 不改表、让编排降密度，属于编排22的范围，而且夜场需要从 144 降到 10，等于重排，不现实。

上限是不是性能组定的安全阀，我这边没法确认。表是共享配置，所以没替你改。

**验收**：改完跑一遍夜场 PIE，日志里 `beacause of FXLimit` 不再出现 3.0 烟花的 ID，彗星完整播完。
