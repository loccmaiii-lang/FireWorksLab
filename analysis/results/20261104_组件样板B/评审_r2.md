## 门禁 2：盲比结论

- 胜出：v2。
- 胜出维度：主色只用于状态；密度与纵向利用；边框更少；顶部动作层级；去掉无用标签；单一字体；导航（无页签重复树）；单位清晰；滑杆更长。
- 退步维度（6 项）：
  1. 树的图标列失去说明：去掉「显示 只看」列头后，圆圈图标含义不明。
  2. 数值看起来像比例数字，不如 v1 等宽字体确定。（实测已是等宽数字，见上表；属观感问题）
  3. 停用的恢复按钮几乎看不见。
  4. 只靠间距分组，比 v1 的分隔线弱：模块标题到第一行（约 31 px）与行距（30 px）接近，折叠的模块之间约 36 px。
  5. 搜索框左缘随当前对象名长短移动（金锦层约 79 px，火花约 66 px）。
  6. 数值框只有底色无边，不够像可编辑框。

## 评审给出的前 5 项改动（v2）

1. 恢复树图标列的含义：在「整体」行加小号灰色「显示 只看」，或把只看图标换成可辨认的图形。
2. 分组节奏：标题到第一行缩到约 22–24 px，模块间距加到约 52 px；或在顶层模块间加约 6 % 白的细线。
3. 「随机 ±30% / ±70%」虚线框改为灰字，使参数行保持 30 px。
4. 数值框用等宽数字；「继承速度」无单位，单位列留空；数值框加约 8 % 白的 1 px 边，悬停 / 聚焦加亮。
5. 当前对象名占固定宽度，搜索框不再跳动；停用的恢复按钮提高到约 3 : 1。

## 处理（样板 v3）

| 退步 / 建议 | 处理 |
| --- | --- |
| 1 图标含义 | 只看图标改为准星形，与眼睛明显不同；不恢复列头（第 1 轮评审要求去掉列头，两轮意见取图形方案） |
| 2 数字观感 | 不改：实测已为等宽数字；Windows 上为 Segoe UI 的等宽数字，云端为替代字体 Inter |

| 5 搜索框跳动 | 当前对象名固定 96 px，超出省略 |
