## 1. 结论

1. **能做，但不是“一键重导出就修好”。** 有三个前提缺口：
   - 库里 20 个资源只有 **10 个（9 个粒子系统）出自烘焙器**；宪章最关键的金芒菊、银彩菊、金垂柳、金曜菊、小银菊、点灭星、金裂星、彩千轮、两种扇都**不是烘焙器做的**，烘焙器重导出管不到它们。
   - 烘焙器做的那 9 个，**导入 UE 后被手调过**：亮度倍数（Color Scale Over Life）从导出的 1 调到 ×5 / ×10 / ×20 / ×30 / ×50 / ×100；橙辉星面片 149 → 160 m、寿命 3 → 2.8–3.2 s；爆裂星寿命 3.17 → 1.5 s。**直接重导出覆盖会把这些手调冲掉**，而这些手调没有回写进烘焙器。
   - `spec/尺寸标定.json` 的 map 只配了 3 个效果（金芒菊名下的烘焙效果、金蕊柠、分裂星），尾缀和其余都没配；主角 280 m / +400 不在表里。
2. **高度普遍高 24–27%，原因在尾缀，不在花。** 三档尾缀导出时没按尺寸表缩：S 尾缀顶 ≈ 193 m、M ≈ 269 m、L ≈ 416 m（导出包里远段竖直面片 8×190 / 16×268 / 23×420 m），固定子模板的开花点照着尾缀终点放（S 188–192 / M 262–267 / L 408–409 m）；宪章是 +150 / +210 / +330（主角 +400）。重导出三档尾缀（长度 × 0.79，时间不变）就能一次修正全部 15 个花型的高度，D（2.95 / 4.38 / 7.37 s）不变，编排卡点不用重算；现在的 L 尾缀（416 m）正好留给主角 +400。
3. **花径：烘焙器做的有 2 个已按标定缩好，其余偏大 1.6–3 倍（估算）。** 见第 2 节。非烘焙器的 10 个只能实测，截图粗测试过，光晕和场景灯干扰太大，要专门的测量场景。
4. **烘焙器和引擎“不同步”的根子是亮度口径和单向流程**：烘焙器导出亮度倍数 1，引擎里实际要 ×5–×100 才对眼——说明烘焙器的曝光 / 亮度模型和 UE 后期不一致（UE-03 一直没测）；而 UE 里的手调没有通道回到烘焙器。

## 3. 方案：量 → 对 → 回 → 改 → 验

1. **量（引擎里的真实尺寸）**：做一个专门测量场景，代替截图粗测——黑天、关 Bloom / 自动曝光、隐藏坝体灯，单朵放在已知距离，冻结粒子逐帧截图，按亮度阈值取外轮廓，换算米；同时读粒子组件的 Bounds。产出每个资源的「最大花径、出现时刻、开花高度、尾缀实际终点」，写回 `spec/尺寸标定.json` 的实测字段（目标值和实测值分开，规范本来就这么要求）。
2. **对（定每个资源用哪个规格）**：把 20 个资源都配进尺寸表 map，包括三档尾缀、主角 280 / +400、230 m 大号版本；先解决“金曜菊算 S 还是 M”“小青柠是坝顶 90 还是前台 30”这类口径问题。尺寸表由编排对话框维护，改了要升 version 并跑 `tool/build.py`。
3. **回（引擎 → 烘焙器）**：重导出之前，先把 UE 里的手调读回来写进效果记录（亮度倍数、寿命、面片尺寸），否则重导出会冲掉。长期做法：导入器每次导入后自动“读回比对”（本轮的 `engine-vs-baker.mjs` 就是雏形），不一致就报告，不静默覆盖。
4. **改（三条路，按资源分）**：
   - 烘焙器做的 10 个：按尺寸表重导出，只改长度、不改时间和贴图（用户 10-09 定的口径）；尾缀三档优先，收益最大。
   - 非烘焙器的 10 个：烘焙器管不到。可选：固定子模板条目的 EffectScale（零资产改动，但它对不同发射器是否等比缩放花径**没验证**，世界空间 / 局部空间发射器表现可能不同）；或者在 Cascade 里直接改；或者长期用烘焙器重做（属于新效果，要你验收）。
   - 高度：尾缀重导出后，固定子模板开花点跟着改到 150 / 210 / 330 / 400，并让 24 的工作台按新尾缀重算。
5. **验（补引擎验证，在 UE-01～13 之外新增）**：
   - UE-14 EffectScale 实际效果：同一朵花 ×0.6 / ×1 / ×1.5，量花径、亮度、粒子速度是否等比。决定非烘焙器资源能不能靠条目缩放。
   - UE-15 尾缀实际终点：三档尾缀实播测星头最高点和开花点是否接上（现在全是“原参数积分估算”）。
   - UE-16 亮度口径：同一曝光下，导出 ×1 和 UE 里 ×N 的画面对照，找出烘焙器亮度模型差了多少，并入 UE-03 修烘焙器，而不是每个资源在 UE 里手调。
   - UE-17 导入后读回比对：作为导入的固定步骤，读回面片尺寸 / 寿命 / 时长 / 亮度 / 朝向 / Pivot 与 cascade.json 对照。
   - 已有的 UE-01～13 里，和这件事直接相关的是 UE-03（曝光）、UE-05（尾缀 Pivot / Size By Life）、UE-06（多层仰视对齐）、UE-11（剔除与 GPU 上限）、UE-13（各效果原生验收）。

## 4. 风险与提醒

- 用户 10-11 11:07：烘焙器导出的改动先测试对比、再确认，不直接改。尺寸重导出也照这个办：每个资源先出一版对比（引擎旧 / 新），你看过再替换。
- 正式库规则：用户通过的效果锁当时烘焙器版本，以后只改形式。按尺寸缩放属于“只改大小”（10-09 你允许过），但改亮度口径、改寿命不算形式，要你另行批准。
- 绿牡丹和多重菊共用一个粒子；金芒菊 / 金锦菊资源名和粒子名对调。改一个前先确认影响面。
