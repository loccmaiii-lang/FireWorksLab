- **直径怎么来的**：这批花几乎都是「一朵 = 一个序列大面片」（星画在贴图里），模块只能给面片大小（Initial Size × Size By Life 最大），那是花径的上界。真实花径 = UE 面片 × 交付包里的「花径 ÷ 面片」：在 `D:/ProjectTextures` 157 个 `cascade.json` 里按面片尺寸逐个对上（`size_spec.target_m` ÷ 包里 Initial Size，12 个对上，比值 0.68–0.99、中位数 0.953）。对不上的（金锦菊、绿牡丹、多重菊、金裂星、金垂柳、银彩菊：老包没有尺寸标定或是手搭的 2×2 序列）按中位数推，表里标「推断」，范围见 json `rangeM`。
- 绿牡丹、多重菊另有 GPU 光点层（星头），按 ∫v dt 算的直径只有 128 / 96 m（`particleLayer`），比序列面片推的 289 / 287 m 小得多——序列层（含尾迹 / 下垂 / 取景留边）的真实外径要截图量（T10）才能定，这两种的 1.9× 可信度最低。
- 彩千轮是粒子花：4 个发射器都在**半径 80 m 的球里随机出生**（无速度），粒子 25–42 m，所以直径上限约 202 m、中值约 155 m；另有 3 个事件接收发射器（Sparks Cloud 每次事件再生 50–200 颗 GPU）。
- 面积量是 EffectScale 1 的一朵；编排里放大 s 倍要乘 s²（金芒菊大 ×1.53 → ×2.35）。序列面片是整张四边形光栅化，透明留边也算填充（Cutout 只在部分包里有）。
- 扇（按实读，用户 10-16 01:13 说的「尾缀近段 / 远段做法」）：**银扇一束 54 个粒子**（TrailFull 1 个序列 + Dot_A **GPU** 光点 50 burst + 3 rate），和「50–60」一致，但 **Dot_A 是 GPU 发射器（TypeDataGpu），银扇每束仍有 1 个 GPU**；**红彗星一束 25 个**（TrailFull 1 + Dot_A/B/C 三个 CPU 光点各 5 burst + 3 rate），0 GPU，不是 45。
- 三根坝顶尾缀 L / M / S：现在 LOD0 只开 RiseLoop + TrailFar 两个 CPU（火花 6 个 GPU 发射器都关了，10-14 读数是 10 启用 / 6 GPU）。
- 「逐粒子随机」：一朵 = 一个粒子的花，逐粒子就是逐朵（整朵一个随机值）。用 Uniform 尺寸的：金芒菊 225–236 m 面片、金裂星、银冠菊、点灭星、三个小平台花、银彩菊；颜色随机只有点灭星（Color_Seeded，见 `颜色大小随机案例.md`）。

## 3. Tiny 缩 0.65

- 模块：1 个发射器 TrailFull，CPU、Rectangle、**Required.bUseInLocalSpace = true**；Initial Location (0, 0, 3059.62 cm)，Initial Size (261.3, 6478.59) cm，Pivot (0, 0)；Initial Velocity (0, 0, 28.55 cm/s)，bInWorldSpace = false、bApplyOwnerScale = false；Lifetime 2.8179 s 常量；没有 Acceleration / Drag。
- 原生：面片上沿 = 30.60 + 64.79 / 2 = **63.0 m**（2.8 s 后再上移 0.8 m）；作者用的到顶 62.0 m / 1.6875 s（贴图里星头到的位置）。
- ×0.65：本地空间，出生位置和面片尺寸都跟组件缩放走 → **到顶 62.0 × 0.65 = 40.3 m**（上界 40.9 m）；升空画面按 Dynamic Parameter 帧号曲线（相对寿命）播，寿命常量 → **时间不变 1.6875 s**。和 UE-14（大尾缀 ×0.8 只改长度）同一机制。线宽 2.6 → 1.7 m。斜放的那根按 cos(角度) 再低一点。T10 截图量对照。
