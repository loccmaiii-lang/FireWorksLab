## 读回里决定方案的四个事实

1. **我们的 Ramp 在 UE 里几乎都是 Wrap + 带 Mip**：绑定到序列的 24 张 Ramp 里，我们导出的 256×8 那 19 张有 18 张 `AddressX/Y = TA_Wrap`、`MipGenSettings = TMGS_FromTextureGroup`（会生成 Mip），只有 `T_EFX_FireWorks_Lime_Core_R` 是 Clamp（用户这次手改的那张）。10-07 建议的「Ramp 一律 Clamp + NoMipmaps」从没落到导入器里（10-07 14:00 改成「导入器不用改 Ramp 的平铺设置」）。
   - 这正好解释 10-07 的灰白细线：Wrap 时灰度接近 0 的地方会和 Ramp 最后一格混色；当时加的「最后一格涂黑」是对 Wrap 的补丁。
2. **材质查 Ramp 的坐标就是灰度本身**：父材质 `M_EFX_FlipBookSuperPack_FireBase_Unlit`（半透明）里 `q = pow(v·D^P, 2 − D^P)`，45 个材质实例的 D = P = 1（中性）→ q = v；Ramp 的 Custom 节点是 `float emissiveUV = float2(EmissGrayscale,0.5); Texture2DSample(EmissiveRampTex, EmissiveRampTexSampler, emissiveUV)`——变量声明成 float，实际采样点是 (v, v)；我们的 Ramp 8 行完全相同，所以这一处不影响结果。没有把坐标拉伸。
3. **8 张序列很可能是旧的（没封顶、最亮 255）配上了同名的新 Ramp（末格黑）**：金锦菊 GoldRay A / B（序列候选 4.9.19，Ramp 4.9.33）、尾缀 L / M / S 的近段 Loop 和远段 Far（序列候选 4.5.1–4.9.29，都绑到 4.9.68 的 `RiseTrail_L_R`）。机制：新导出的 Ramp 和旧 Ramp 同名，导入时覆盖了旧 Ramp，但还在用它的旧序列没有跟着换。磁盘上同名多版并存，UE 里的实际字节没核实，所以是候选、不是确证。
4. **点灭星的序列绑到了别的效果的 Ramp**：`T_EFX_FireWorks_Strobe_Strobe_4x4_01_HD` 绑 `T_EFX_FireWorks_GoldCoreLime_RedCore_R`，和 Strobe_D90 包自己的 Ramp 字节不同 → 颜色可能不对，和黑块无关但要修。其余 15 处 Ramp 名字不同的绑定都和包里的 Ramp 字节相同（导入器按内容复用），不是配错。

另外 30 张「封顶 253 + 末格黑 + BC7」的序列：只有压缩把 253 冒到 254 / 255 才会黑（云端模拟会），没证实；用户的 RGBA8 试验对哪张做的不清楚。

## 结论（推断）

黑块是「Ramp 末格黑」这个补丁本身的副作用：它让 Ramp 和序列必须是同一代、而且序列在 UE 里一个色阶都不能冒顶。Wrap 才是 10-07 那圈细线的源头。根治 = 源头改对（Ramp 用 Clamp + 不要 Mip）+ 去掉补丁（末格不再涂黑）——这样旧序列（255）、新序列（253）、压缩冒顶都不会再查到黑色，序列图一张都不用重导，Ramp 重复也不再有风险。

唯一没证实的前提：10-07 13:42 用户说「改了 Clamp + NoMipmaps 线还在」。读回显示那时以后库里的 Ramp 仍然是 Wrap，那次改动可能没落在实际绑定的那张上；需要在 UE 里用一张「末格不黑 + Clamp + NoMipmaps」的 Ramp、Color Over Life ×30 看一次细线回不回来，再全量铺开。
