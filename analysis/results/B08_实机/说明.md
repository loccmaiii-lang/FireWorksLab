# B08 修订7 / B05 编辑器实放：PC 低配 Translucency（派活 T10，卡住：UE 中途崩溃）

**三条结论（编辑器是 RTX 5080，不是 960，只看相对值；单帧读数、噪声大，可信度低）**：① B08 修订7 低配 Translucency 是 B05 的 **132 %（64.5 s）/ 121 %（182.6 s）/ 88 %（184.5–189 s，三帧合计）**——前两处 B08 反而更高，和「限峰后约 B05 八成」的预期不符，但绝对值只有 0.24–0.54 ms、帧间跳动 0.1–0.3 ms，这个差别在噪声里，**定不了**；② B08 全场最高三刻 **64.5 s 0.54 ms、116.5 s 0.54 ms、184.5 s 0.49 ms**（B05 最高三刻 43.5 s 0.76、187.5 s 0.63、165.0 s 0.62 ms；B08 全场最高比 B05 最高低 29 %）；③ 量到的花径：**金蕊柠 ×1.411 约 238 m，名义 212 m → 约 1.1 倍**（只量成这一朵，金芒菊大开得太早没长开、小平台花和坝体灯光混在一起）。

> 本机实测（25）· 2026-10-16 02:26–02:57。被测：导演实例 `BP_NewYearFireworks_ShowDirector_Night_2`（`MA5_FireworkOnDam_Night`，10-11 的 `_7` 已不在），用户 01:48 摆好的视口机位（整条没动）。数据在 `Translucency.json`，截图 `B08_低_0184.5.png`。

## 做了什么

- 内存里换表（只换 EffectSubTemplates / EffectTemplates / EffectScheduleGroups 三组），每次读回和文件逐项一致、其它字段没变；DebugPlatform = PC、DebugQualityLevel = EQuality_Low（表里低配条目都是 MinQualityLevel VeryLow，Low / VeryLow 筛出来一样）；DebugPreviewStartTime 0 放整场，按墙钟在 22 个时刻执行 ProfileGPU，执行偏差 ≤ 0.016 s，被测的是命令后的下一帧。
- 视口渲染 2210×1105、r.ScreenPercentage 100、D3D12。读的行：顶层 `Scene` 下的 **`Translucency`**（含 `Translucency_Standard` / `Translucency_AfterDOF` / `Translucency_AfterDOFModulate`；烟花基本都在 AfterDOF）和整帧 `total GPU time`。
- **r.ParallelTranslucency 要设 0**：默认 1 时半透明是并行录制的，ProfileGPU 里只剩 0.2 ms 的空壳，烟花那部分统计不到（第一遍 B05 就是这样，作废）。改 0 后 B05 / B08 同条件重测。r.ProfileGPU.ShowUI 也改了 0。
- B05 分两段放完（0–116.5 s 一次、118 s 起续放一次，中间一次请求断连）；B08 一次放完。

## 花径（从截图量，推断）

- 方法：按表展开 184.5 s 在开的花 → 用相机位置 / 朝向（水平 FOV 按编辑器默认 90°，没读到实际值）投影出花心像素和深度 → 亮度 > 55 的像素膨胀后取包含花心的连通域 → 水平宽度 × 该深度的 m/px。点位用 10-11 读回的世界坐标（P0–P8 实际相距 662 m，不是设计的 800 m）。透视：花有厚度，前后半径的深度差让 m/px 有 ±(D/2)/深度 的误差，大花约 ±20 %。
- P8 金蕊柠大（×1.411，开花 3.4 s）：402 px、深 568 m → **约 238 m**（名义 150 × 1.411 = 212 m → 1.12×）；P0 同款 ≥ 219 m（上沿出画）→ ≥ 1.03×。P4 那朵绿点稀、连通域没连上，目测约 320 px → 约 200 m。和 T09 从模块推的「金蕊柠原生 150 m（1.0×）」一致。
- 金芒菊大（P0 / P8，184.265 s）截图时才开 0.24 s，还没长开，量不了；小平台花见上。
