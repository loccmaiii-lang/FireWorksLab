# SMOKE19 看法（对话框15，2026-10-03）

审看的是 **4.2.23**（本机 RTX 5080，后台监控，23:04 完成，`env.json`）：条目体检 `--real --cap --only ef:` + 第一次跑 `实时显卡负担.py`（显卡计时器）。

## 1. 打开后烘焙时：鸿巢好了，引菊 → 锦变慢（4.2.23 引入的回退，4.2.25 修）

| 效果 | 烘焙中两段帧数（满分约 140 + 140） SMOKE18 → SMOKE19 | 打开用时（实时显卡负担.py，新页面） |
| --- | --- | --- |
| 鸿巢 | 14 + 87 → **141 + 140** | 8.6–9.3 s |
| 青柠星 | 106 + 141 → 133 + 141 | 2.2–2.8 s |
| 金芒菊 | 122 + 141 → 122 + 141 | 3.2–5.1 s |
| 引菊 → 锦 | 41 + 71 → 97 + 97 | **44–45 s**；条目体检里接在鸿巢后面打开 → **300 s 超时** |

- 鸿巢「打开后头 5 秒约 3 秒没画面」没有了：分批交显卡起作用。
- 但引菊 → 锦烘焙慢了 3–4 倍，条目体检里超时（那一行的帧数、时长其实还是鸿巢的，因为没打开成功）。
- **原因**（云端复现了）：浏览器不会立刻告诉页面 fence 已经做完，每等一次有一段固定延迟（一帧或一个计时器）。4.2.23 用「这批的粒数 ÷ 等的时间」估显卡速度，把这段延迟当成显卡时间，每批越算越小，掉到「每等一次只交 1 个快门子样本」。引菊 → 锦一帧最多 64 个子样本（高画质），一次烘焙要等几千次。`实时负担检查.py` M7④：模拟每次至少等 17 ms，4.2.24 分批烘焙 15.6 s / 不分批 4.3 s、等了 691 次。
- **4.2.25**：不再估速度。每批的量按结果加减：一帧多一点就等到了 → 下一批 × 1.6；要等两帧半以上 → 按晚的比例减。M7④ 变成 4.2 s / 4.1 s、等 11 次。条目体检加了每页烘焙用时、等显卡次数和时长，排 SMOKE20 复核。

## 2. 实时模拟一帧的显卡时间（显卡计时器，毫秒；括号里是这一帧画的粒数）

| 效果 | 正常（画布 412） | 专注 1.5 倍屏（924–1148） | 专注 2 倍屏（1236–1532） |
| --- | --- | --- | --- |
| 鸿巢 不压 16 子样本 | 26.6（5430 万） | 26.7 | 26.6 |
| 鸿巢 2 子样本 | 3.2（680 万） | 3.2 | 3.2 |
| 金芒菊 不压（1.83 s） | 6.3（310 万） | 6.0 | 6.2 |
| 引菊 → 锦 不压（3 s） | 11.9（2550 万） | 17.2 | 21.3 |
| 引菊 → 锦 2 子样本（3 s） | 1.5 | 2.0 | 2.9 |
| 青柠星 不压（0.55 s） | 1.1（110 万） | 3.7 | 5.8 |
| 全屏那几遍（无粒子） | ≤ 1.1 | ≤ 1.0 | ≤ 1.0 |

- **成本基本和粒数成正比**：鸿巢约 0.5 ms / 百万粒，金芒菊火花大，约 2 ms / 百万粒。全屏的几遍（清屏、底光、上色、后期）不到 1 ms，不是问题。
- **「放大」（F 专注模式）**：单层（金芒菊）实时模拟按导出单格的分辨率画（超采样画布固定 1024²），放大不变。多层（鸿巢、引菊、青柠）按画布大小画：鸿巢火花小，放大几乎不变；**引菊 → 锦、青柠星火花大（开花那几帧铺满），2 倍屏是正常的 2–5 倍**。
- 用户实际的样子（自动按负担调子样本，rAF 驱动）在本机都是 18 ms 一帧；鸿巢专注 2 倍屏偶尔 53 ms。
- 检查里不压子样本时鸿巢一帧 26.6 ms > 一次刷新，这就是之前条目体检里鸿巢 90% 36 ms 的来源（检查默认不压）。

## 3. 推到笔记本（估算，没实测，要用户的显卡型号才能定）

常见笔记本显卡大约是 5080 的 1/10–1/20。按上表：鸿巢就算压到现在的下限（2 个子样本、所有火花都画）也要 32–64 ms 一帧（15–30 fps）；引菊 → 锦专注 2 倍屏下限 30–60 ms。也就是说笔记本上现在的下限还是太重，自动调子样本降到底也顿。

下一步（只改实时模拟，烘焙 / 导出 / 引擎回放不变）：显卡还跟不上时，子样本降到 1，再按比例少画火花（亮度补回来，总光量不变）；多层在专注模式下画布太大时降一点实时模拟的分辨率。要看笔记本上到底够不够，需要用户的笔记本显卡型号。

## 结论

- 4.2.23 解决了「打开后烘焙时画面停」（鸿巢 14 → 141 帧），但带进一个回退（引菊 → 锦烘焙慢 3–4 倍），4.2.25 已修，SMOKE20 复核。
- 放大时卡不卡取决于火花大小：引菊 → 锦、青柠星放大后显卡负担翻 2–5 倍；鸿巢主要是粒数多。笔记本上要再往下降（上面「下一步」）。
