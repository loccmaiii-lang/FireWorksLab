## 二、问题清单（按严重程度排序，19 条）

### 主要（9 条）

**P1 数值框把输错的内容里能解析的开头部分直接提交了**
- 任务：1、11
- 做了什么：在缩放框里分别输入「15」「2.5x」「1.1*1.2」，然后回车。
- 预期：越界或格式不对时拒绝，回到改之前的值（时间框就是这样做的）；或者像 AE、Houdini、Figma 那样计算表达式。
- 实际：输入过程中提示了「超出范围」，但回车后分别变成 1.00、2.50、1.10，并记成「未保存 1 项」。也就是写进了一个用户没打算输的值。
- 一句话改法：输入时不要每敲一个键就写入；回车或失焦时整串不合法，就恢复到改之前的值。

**P2 层可以改成重名，导出文件会互相覆盖**
- 任务：12
- 做了什么：按 F2，把「金锦层」改名成「点灭星」。
- 预期：提示重名并拦下来。
- 实际：改名成功，树里出现两个「点灭星」。导出详情写着 `T_金曜菊-B_点灭星_01–05.png`，第 3 层也会生成 `T_金曜菊-B_点灭星_01–02.png`，01、02 会撞名。另外，名称清空后回车会静默恢复原名，没有任何提示。
- 一句话改法：改名框里就地报「已有同名层」「名称不能为空」；或者在文件名里加上层号。

**P3 在不生效的参数上改值，也会把层标成「需重新导出」**
- 任务：6
- 做了什么：在点灭星上，打开爆后扰动 → 「扰动开始时间」按一次 ↑ → 关上爆后扰动。
- 预期：开关关着，这个参数不进导出，不需要重新导出。
- 实际：顶栏变成「2 层需重新导出」，原因写「点灭星：扰动开始时间 0.40 s → 0.41 s」；同时算一项「未保存」。另外，这个变灰的已改行上没有 ↺，只能去状态栏恢复，或者双击名称（双击恢复的是默认值）。
- 一句话改法：被关掉的子参数不计入「需重新导出」（保存可以照算）；在原因和变灰行上标「未生效」，并保留 ↺。

**P4 「放进编排」的说法和结果不一致**
- 任务：8
- 做了什么：勾上「放进编排 · 首次新增，之后更新」，导出金锦层。
- 预期：编排里的金曜菊-B 换成新版本。
- 实际：提示「已放进编排：金曜菊-B」；进编排一看，这一项是「有新版本 · 更新」，要手动点「更新」才换。
- 一句话改法：要么勾选后自动更新；要么把文案改成「之后生成新版本，在编排里点「更新」生效」，提示条也写「已生成新版本」。

**P5 层里的输出平台、单格，跟导出菜单的平台互不联动（待确认）**
- 任务：7
- 做了什么：在金锦层的「输出」里，把单格改成 512 px，关掉「手机」，然后导出。
- 预期：导出只出 PC，单格 512；或者两处共用同一个设置。
- 实际：导出菜单仍勾着「手机 3 张」，提示「PC 5 张、手机 3 张」，交付表仍写 1024 px；改动只出现在「需重新导出」的原因里。同一个概念（出哪些平台）有两个开关，用户不知道哪个算数。
- 一句话改法：导出菜单的平台跟随层的设置，或者在菜单里写明「金锦层：手机已关」；如果只是样板没联动数据，请确认。

**P6 删除被别的层引用的层时，没说引用会断**
- 任务：3
- 做了什么：删除点灭星，然后看金锦层。
- 预期：提示条或改动清单写一句「金锦层的轨迹联动已断开」。
- 实际：金锦层的「轨迹联动」从「第 3 层」悄悄变成「未联动」；提示条只写「已删除「点灭星」」，清单只写「点灭星 删除」。撤销能恢复，但提示条 12 秒后就消失了。
- 一句话改法：提示条里写出受影响的引用；被引用的层在 ⋯ 菜单的「删除」后加一句说明。

**P7 从入点框到出点框，焦点会丢，输入被当成快捷键**
- 任务：5
- 做了什么：入点输入 0.5 后，按 Tab，或者直接单击出点框，再输「3.0」。
- 预期：像 AE、Figma 那样，Tab 移到出点，单击能直接输入。
- 实际：入点提交后，时间行重绘，焦点回到页面；「3.0」里的「.」触发了「下一帧」，播放头 2.00 → 2.03，出点仍是 2.85，没有任何提示。（参数数值框之间直接单击切换是正常的。）
- 一句话改法：提交入点时不要重建出点框，或者重建后把焦点还给刚刚点中、Tab 到的那个框。

**P8 用户在别的工作区时，导入完成的提示条落在屏幕外**
- 任务：9
- 做了什么：导入写 UE 的过程中切到编排，等导入写完。
- 预期：在当前位置看到「已导入 Comet 3.0 红头金尾，覆盖的 3 个已备份」。
- 实际：提示条定位在已经隐藏的导入区，坐标 y = −48，两次复现都看不到。相关的还有：「已导出 … · 回到制作」在回到制作后还挂着；人已经在编排里，提示条上仍有「去编排看」。
- 一句话改法：提示条挂到当前工作区（或者全局底部）；切换工作区时，收起或改写已经过时的按钮。

**P9 写到一半才问备份，取消会留下半个包（待确认）**
- 任务：9
- 做了什么：备份文件夹未选，点「导入」。
- 预期：开始写之前就问（预检已经知道要覆盖 3 个），和 UE 的导入对话框一样。
- 实际：先写了 Ramp 和 _01 两个新资产，到 2/10 才弹框；暂停期间顶栏的转圈仍写「UE 写入中 2/10」。按 Esc 或「取消导入」后提示「已取消导入，未覆盖已有资产」，没提已经写进 UE 的 2 个，列表仍是「待导入」。
- 一句话改法：点「导入」时先检查备份；如果坚持写到第一个覆盖再问，取消时写明「已新建 2 个，未覆盖已有资产」，暂停期间顶栏改成「等待选择备份」。

### 次要（10 条）

**P10 「打开时 / 上次保存 / 默认」几套基准混用**
- 任务：1、5
- 做了什么：改入点 → 保存 → 再改 → 点时间行的「恢复」。
- 预期：照提示「入点、出点恢复到打开时」回到 0.35。
- 实际：回到的是上次保存的 0.50。参数行的 ↺ 写「打开时」；状态栏、工具行的「还原」用的是「上次保存」；「仅已改」等于「非默认或本次改过」，不能只看本次改过的。
- 一句话改法：时间行的「恢复」和参数行用同一基准，并在提示里写明；筛选里把「本次改过」和「非默认」拆成两项。

**P11 区间下限不能超过当前上限，报错没说原因**
- 任务：4
- 做了什么：寿命 0.012–0.032，下限输入 0.8。
- 预期：像 Niagara 的 min/max 那样两个值各自输入，或者自动把上限推上去；至少说明是被上限挡住的。
- 实际：报「超出范围 有效范围 0.005–0.032」，回车后恢复原值，得先改上限。
- 一句话改法：报错改成「不能大于上限 0.032」；或者允许输入，再自动对调上下限。

**P12 报错文案不准**
- 任务：1
- 做了什么：数值框里输入「abc」。
- 预期：提示「请输入数字」。
- 实际：显示「超出范围 有效范围 0.10–3.00」。
- 一句话改法：区分「不是数字」和「越界」两种报错。

## 三、做得好的（8 条）

1. **撤销、重做的反馈非常具体**：在改动发生的地方出一条短提示并闪一下，例如「撤销：缩放 1.30 倍 → 1.42 倍」「撤销：大小曲线 关键点 2 寿命 20 % → 15 %、大小 1.00 → 0.90」。Houdini、AE 都只能翻历史面板才知道。
2. **Esc 能取消所有拖动**：滑块、播放头、入点和出点的方括号都适用，取消后回到原值，提示「已取消」，松开鼠标前也不再跟随。这和 Houdini、AE 的习惯一致。
3. **变灰的控件都写明原因**：「UE 未连接，GPUECli 启动后自动连上」「导入正在写 UE，写完后可用」「仅 Chrome、Edge 能读写文件夹」。悬停和单击都给出同一句话，没有点了没反应的死按钮。
4. **改动可见，也能逐项恢复**：状态栏「未保存 N 项 ▾」逐项列出「对象 参数 旧 → 新 · 恢复」；参数名的悬停提示同时给出默认、范围、打开时、现在；导出范围的改动合成一条。
5. **「为什么要重新导出」随手就能看**：悬停树上的 ↻ 或工具行，就能看到「金锦层：缩放 1.00 倍 → 1.10 倍 / 单格 1024 px → 512 px」。
6. **删除、还原不弹确认，但能撤销**：提示条停 12 秒，悬停不消失；撤销后连层上的参数改动一起回来；切换效果前，会问是否处理未保存的改动。
7. **被开关控制的参数处理得好**：「4 项已隐藏 其中 1 项已改」，配合「仅已改」和搜索，会把隐藏的已改项和控制它的开关一起露出来。这比 Niagara 里参数被关掉就看不见要好。
8. **首次使用的恢复路径顺**：导出时没选文件夹，选完会接着导出，不用再点一次；需允许访问的恢复入口在顶栏标签、按钮旁气泡、导入区空状态三处，用的是同一句话；UE 断开后有倒计时自动重试，也能手动重试。
