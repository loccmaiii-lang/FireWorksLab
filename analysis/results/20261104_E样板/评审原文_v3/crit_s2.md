Intended direction: A quiet, dense, dark "instrument" in the DCC lineage (Houdini / Unreal / DaVinci / Final Cut inspector). The firework is meant to be the only bright thing on screen. The chrome is typographic rather than decorative: flat blue-grey surfaces, hairline module dividers, one mint accent, near-square corners, and small numerals with dim units. The viewport crop marks and the "PC 30 fps tick 26" overlay show a wish to make it feel like a measuring device. The aim is calm, precise and readable all day, with nothing competing with the work.

Contrast with Pentagram / Apple / Teenage Engineering: Pentagram would start from one strict column system and make every module obey it. The label, control, value and unit columns would sit at the same x-positions in the inspector. The 01–13 emitter numbers would form one aligned typographic column shared by the tree and the timeline. Module headers would follow one rule instead of four different ones. Apple (Motion / Final Cut / Logic) would make the timeline carry the meaning: lifespan clips, trigger markers and a single authoritative time readout. It would also visually separate "workspace mode" from "zoom level" and mark the current page in the top bar. Teenage Engineering would commit to the instrument idea that this screen only hints at: tabular figures everywhere, one display-style readout for time and frame, custom glyphs that tell emitter types apart at a glance, and mint used for exactly one meaning ("now / live"). Today the screen has the right restraint. What it lacks is the pixel-level system that turns restraint into craft. It reads as a careful in-house tool, not a designed instrument.

Biggest gaps:
1. The timeline is the weakest module and covers about a quarter of the screen. The 13 tracks are identical 1 px grey hairlines across the full width, and the selected row is only a brighter hairline. The tracks show no lifespans, trigger points or bake frames, so the area reads as empty ruled paper. The nested rows (06 / 08 / 07) start their lines 25–35 px late, copying the label indent. If that offset is meant as data, nobody can read it as data; if it comes from the indent, it misstates the time. The export-range label "0.00–2.13 s" sits on top of the ruler's "1 s" tick label. Six empty bordered boxes at the end of the bake strip look like broken image placeholders.
2. Three time readouts disagree. The transport shows "0.89 / 2.13 s" and "烘焙 27/64", and the viewport shows "tick 26", one less than the frame number. "烘焙 27/64" sits next to a partly filled bake strip, so it reads as bake progress rather than the current frame. A technical artist has to work out which number is true.
3. The inspector grid does not hold. Single values are right-aligned 70–100 px away from their slider, while range values ("0.012–0.032 ⌄ s") press against the slider end, so the value column has no consistent edge and the eye zigzags. Units are inconsistent: 触发时刻, 触发概率 and 亮度增益 5760 have none. The range chevron "⌄" is squeezed between the number and the unit. The curve plots start about 20 px to the right of the slider tracks above them. The axis caption "寿命 0–100 %" sits inside the plot and touches the last keypoint. The section chevrons are tiny and hang in the gutter, almost on the column divider.
4. The top bar gives status, actions and navigation the same look: grey text separated by pipes. "设置" (an action) sits between the backup status and the two page entries. Nothing shows which page is current. Colour carries the good news but not the bad: "UE 已连接" gets a mint dot, while "备份 未选" (a real risk) is plain grey. Two different count styles appear in one bar: a superscript "²" after the version, which reads like an exponent or footnote, and an inline "2" after 资源交付.
5. The mint accent means five things at once: tab underline, tree edit outline, the filled 导出 button, the playhead and the UE status dot. The filled 导出 button is the loudest object on screen apart from the firework, and the playhead competes with the tree outline for "what is selected". The palette is fixed, but how it is used is not.
6. Control hierarchy is flat. The workspace-mode switch (实时模拟 / 引擎回放 / 贴图与交付), which changes the whole workspace, looks exactly like the zoom toggle beside it (适应 / 1:1 / 游戏内). Both also look exactly like the inspector toggles (球面 / 锥形, 线条 / 点 / 碎片) and the library filter. That makes five identical segmented controls at three different levels of importance.

The left column ends with about 150 px of empty space under the library, while the timeline hides four rows behind "还有 4 行" and the inspector runs off the bottom. Each module is headed differently: the tree has no header band (its root row sits in the toolbar band, and the toolbar's bottom line stops at the column divider), the library has large tabs, the inspector a breadcrumb and the timeline a transport bar.
8. The icons are generic and mixed with text. The emitter glyphs in the tree are 12 px wand and branch shapes that are too similar to tell emitter types apart. The viewport toolbar has five unlabeled stock icons (grid, sticky note, code brackets, two sidebars) whose meaning is guesswork, next to one labeled "预览设置". The inspector toolbar mixes undo/redo icons, an icon-only duplicate button and text-only 还原 / 保存 / 另存.
9. The transport bar has no rhythm. Gaps between controls vary from about 18 to 42 px with no grouping logic, and the loop toggle is the only filled control in the bar.
10. Library details. The status words 制作中 / 待验收 / 新 / 已通过 all share one grey and one weight, so "待验收", the state that needs the user, is no more visible than "已通过". The search field has no edge and reads as a caption. Latin text (version number, "Comet 3.0", codes) is set in a different family and a lighter grey than the CJK text, so mixed names look uneven. The tree order 06 → 08 → 07 looks like a sorting bug and breaks the scan.
