Intended direction: A quiet, content-first dark pro tool in the Resolve / Unreal / Houdini lineage: flat blue-grey panels in four close value steps (top bar, toolbar band, panels, near-black viewport), 1 px hairlines between modules, one mint accent kept for "live / current / primary" (UE dot, tree outline, tab underline, 导出, playhead), amber only where it matters (⚠ on the layer and on export), dense 13 px type, numbers right-aligned in a strict control column. The firework is meant to be the only bright thing on screen, framed by thin crop corners, with a timeline that doubles as a bake-progress readout. Restraint is the stated value and, at the macro level, it holds: the column lines are all the same step, the inspector rows keep a steady 28 px pitch, sliders, toggles, segments and checkboxes all start on the same x, and the viewport is uncluttered.

Contrast with Pentagram / Apple / Teenage Engineering: Pentagram would get the same calm from a typographic system rather than from dimness alone: two sizes, two weights, tabular numerals, one consistent "label: value" grammar used everywhere from the top bar to the collapsed-section summaries, and a grid every edge snaps to. Here, hierarchy is carried almost entirely by bold at 13–16 px, so status, navigation, headings and values all speak in one voice. Apple (Final Cut Pro, Logic) would apply one control vocabulary across the whole app: one segmented control, one switch that can't be mistaken for a checkbox, one icon family at one optical weight, a transport treated as an instrument with fixed spacing, and a ruler where nothing ever overlaps a label. Teenage Engineering would make the inspector feel like hardware: fixed-width parameter cells, monospaced readouts with units set small and consistent, and one signature graphic carried with conviction. That signature is already here, in the bake strip of tiny rendered frames, but it is undersold, and its empty cells are drawn louder than the finished ones. All three would remove the small collisions and drift that this screen still shows. The direction is right; the craft is about 80% there.

Biggest gaps:
1. No real type system. Bold is the only hierarchy tool and it is used everywhere: product name, current tree row, current tab, two selected segments, inspector title, every section heading, 单次, 全部, the timeline layer names. Sizes 13/14/15/16 sit too close together to read as levels. With bold on everything, it no longer marks anything, and the screen reads flat and monotone. Numerals look proportional, not tabular, so the time readout and values shift as they change.
2. Inconsistent control vocabulary. There are four segmented-control treatments: mode (bordered container), zoom (filled container), library filter (bordered with internal dividers) and 单次/循环. The toggle (a square thumb in a square box) and the checkbox (a square with a tick) are nearly the same drawing, so on and off states are hard to tell apart. Toolbars switch between icon-only and text-only buttons within the same row (five glyphs, then 预览设置; undo/redo icons, then 还原, then an icon, then 保存/另存). Icon stroke weights vary: undo/redo are thin, the duplicate icon is heavy, and the grid icon is dense. Counts use four notations: superscript "2" on the version, a trailing "2" on 资源交付, "6 个", and "⚠ 1".
3. The timeline header has collisions and inverted emphasis. The playhead head sits on top of the "2 s" label. The range label "0.35 – 2.85 s" floats in the same band as the ruler numbers, so one row holds a ruler, a range and a caption. In the bake strip, the unbaked placeholders (outlined boxes with gaps) are the brightest linework in the timeline, brighter than the baked frames, which sit as abutting dark squares, so emptiness reads louder than progress. The transport row has uneven gaps (roughly 12/37/20/40/30 px) and an empty right half.
4. Column heads don't follow one grammar. The center and right columns have a toolbar band in a lighter tone. The left column has no band, so the tree root sits at toolbar height on the panel tone and the band stops abruptly at x = 300. The right column then adds its own title row plus a search row. The result is three different header structures across three columns. Document-level actions (undo, save, 另存, 导出) sit on the inspector's side of the column line, so they read as if they only apply to the inspector.
5. Selection hierarchy is inverted in the left column. The library's current item gets a heavy filled block, while the tree's item being edited has only a 1 px outline. The library row outweighs the editing target, which should be the strongest "you are here" on screen.
