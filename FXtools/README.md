# FXtools：工具使用入口

今后从这个文件夹找工具。当前工作区为 `F:/FireWorksLab`，无需再进入 D 盘维护。

| 要做什么 | 打开什么 |
| --- | --- |
| 日常离线编排 | `烟花编排工作台/烟花编排工作台.html` |
| 发给其他人 | `烟花编排工作台/烟花编排工作台-离线包.zip` |
| Git 拉取后更新成品 | `更新离线工作台.cmd` |
| 修改源码后检查、重新生成 | `检查并生成离线包.cmd` |
| 本机浏览器走查三个工具 | `启动本机工具.cmd` |
| 找到唯一开发源码 | `打开编排源码.cmd` |

第一次从 Git 克隆后，先运行“更新离线工作台”。它核对源文件和成品指纹，然后把仓库成品放到上面的固定文件夹；不用安装前端依赖。若云端只更新源码未生成成品，会明确提示，需安装依赖后运行“检查并生成离线包”。

源码只有 `../tool/workbench` 一份，`../tool/offline-workbench` 只负责打包。8025 直接使用该源码，`8025/release/` 通过 HTTP 读取最终 HTML。这不是自动操作 `file://` 页面，也不表示两种协议共享浏览器草稿。

## 原 D 盘的节目历史

原离线路径继续保留。本机更新会同时覆盖原路径的同名工具文件，不动个人节目和音乐。原节目可能存在浏览器数据库里，复制 HTML 不会搬走这些数据。需要换到这里工作时，先在旧入口“下载节目版本文件”，再在新入口“打开节目”导入；旧入口在确认前不要删除。

给别人更新时，让对方覆盖其原来的同名 HTML，保持原路径、浏览器和用户配置。建议每次更新前下载节目版本文件留档。Git 不会自动同步个人浏览器历史。

## 云端修改与同步

云端改 `tool/workbench`，执行 `npm ci` 和 `npm run release -- --no-deploy`，将源码与 `tool/` 下的成品一起提交。本机 Git 拉取后双击“更新离线工作台”，8025 与离线包就来自同一份代码。个人节目另用 `.dfshow` 交换。

原特效工作台和烘焙器的既有运行目录暂不搬迁，启动入口会复用它们；本次统一的是编排工作台维护和三个工具的查找入口。

三个工具分别维护各自源码，不把它们合成同一个应用：

| 工具 | 唯一维护位置 → 使用入口 |
| --- | --- |
| 烟花烘焙器 | `tool/src` → `python tool/build.py` → `tool/FireworkBaker.html` → `8034/baker`；HTTP与直接打开此HTML是同一产物 |
| 烟花编排工作台 | `tool/workbench` → `npm run release` → 固定离线HTML；8025直接开发同份源码，`8025/release/`读取最终HTML |
| 原特效工作台 | 当前仍为 `D:/FXTools/DFWorkbench/df-fx-workbench_v2_locmai.html`；8036按本机配置即时读取该文件，尚未迁入F盘源码 |

2026-10-10实际核对：8034进程运行F盘仓库的`tool/local_delivery/service.py`，它返回的烘焙器页面与仓库`tool/FireworkBaker.html`逐字节一致。8034不是另一个要手工迁移的烘焙器副本。服务也承载独立导入器，导入器路径由本机配置指定，不能把它与烘焙器源码混为一处。
