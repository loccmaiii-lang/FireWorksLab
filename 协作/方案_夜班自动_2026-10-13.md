## 1 关键误区

1. **本机队列没有 AI。** 它只会跑脚本：不会判断、不会写代码、不会读看板。「派给本机」只对「算、导出、检查」有用。看板上 AI 欠你的 50 条，大多是写代码、写文档、出编排——云端就能做。它们卡住不是因为缺显卡，是因为**对话框只在你跟它说话时才干活**。所以真正要补的是 ①：一个你不在时也会开工的 AI。（10-13 22:29 更正：本机另有一半对话框是 Codex，它们是 AI，见 §7。）
2. **这套以前就有。** `协作/接续.md`（09-30）就是这个设计，只是只管「GPU 结果回来后接着评审」，没接看板。它停在 09-30，规则文件里还当它在用（CLAUDE.md 第 62 行）。恢复比新造简单。
3. **用量是硬约束。** 最后一次接续因为用量上限失败。夜班会用你的额度，和你白天的对话抢。所以每班有上限、没活立刻结束、白天不跑。
4. **无人值守碰你的电脑风险最大。** 两种办法都有：让云端定时会话借用你电脑的命令行（要桌面版 Claude 开着），或者用 Windows 计划任务叫本机 Codex 干活。它们都能改你本机工程、碰 UE。本机已经出过推送事故（10-12 把冲突标记推上 main），同一工作目录里还有两个本机 AI 并行。先不上，等第一阶段跑顺。
5. **会和白天的对话框撞车。** `tool/src` 同一时间只能一方改（导出（23）现在认领到 4.9.81）。夜班只做没人认领的，先认领、做完释放；有人在做的跳过。

## 2 怎么走

**看板上：** 每条「AI 欠你」加一列「夜班」，四个值：

- **可以**：云端能独立做完，有验收办法。
- **等依赖**：等你定某条、或等某个对话框释放。
- **要本机**：要你电脑上的 UE 或文件。
- **不行**：要你看、要你定，或者写 UE、动正式库。

总管先填，你可以改。你不想夜里动的，改成「不行」就行。

**你白天：** 做完的勾「我做好了」，要定的写一句反馈再勾。这些勾会让「等依赖」的条目变成「可以」。

**夜班每一班：**

1. 拉仓库，读看板，跑 `看板对账.py`。
2. 同步你勾的：写进负责对话框的队列，看板标「已同步」。
3. 看本机队列推回来的结果（`待处理.py`）。
4. 挑最多 2 条做。条件：夜班 = 可以、没人认领、依赖都满足。按「认领 → 做 → 检查 → 记录 → 推送 → 释放」走，看板改成「已做」或「待你过目」。
5. 要显卡的，写 `analysis/jobs/<id>.json`，下一班看结果。
6. 卡住或者要你定的不猜：看板写原因、标「等你」。
7. 在看板「更新记录」写一条：这班做了什么、在等什么、用了多久。没活就不写、直接结束。

**时间：** 23:47、02:47、05:47（香港）各一班。白天不跑，白天有你和各对话框。

### 7.2 dot 接进来以后的流程

1. **看板 → 派活单。**
   - 你在看板上勾「我做好了」或作答。
   - 总管把能派出去的活写进仓库里的一份派活单 `协作/派活队列.json`。能派的条件：不写 UE、不用你批、前置都满足。

2. **dot 在本机发活。** dot 定时拉仓库，读派活单里标「本机、待派」的条目，把提示词发给对应的 Codex 对话框，比如交给本机同步（8）的就发给 8。提示词统一一句：「按派活单第 X 条做，按 CLAUDE.md 认领、检查、提交推送，做完在那条写结果和提交号」。
3. **Codex 干活、回写。** 认领 → 做 → 检查 → 推送 → 在派活单写「完成」或「卡住（原因）」。
4. **云端的活 dot 管不到。** 交给导出（23）、跨年秀（22）的，还是要靠云端夜班（第 0–6 节，你还在考虑），或者等你打开那个对话框。
