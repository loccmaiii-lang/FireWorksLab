## 1. 用户 6 个问题的结论

### 1.1 分层能力与端侧产物

- **已经满足「调参分 13 层、导出合 1 张」**（已核实）。13 层只存在于模拟里：烘焙时 `makeGraphRenderer` 把所有启用的层画进同一张序列。PC（`bakeGraph` → `fwlLoop`）和手机（`bakeMobileFor` 的通用分支 → 同一个渲染器）都是 1 个发射器、1 张贴图。实包：`analysis/results/SparkGraph/` 里窜天猴 / 仙女棒 PC 512² 单格、手机 256² 单格，都是 4×4×4 = 64 帧、一个发射器。
- **分叉、成簇、爆发建议保留。** 它们只在烘焙时算，进 UE 后是同一张贴图，运行时零成本。
  - 分叉：仙女棒、窜天猴火星「炸开分叉」的样子靠它。
  - 成簇和爆发：用户 4.9.83 时明确要「播放节奏不要过于平均……偶尔有爆发段」，靠的就是它们。
  - 代价只有烘焙时间和参数多。参数多已经靠 4.9.87 的分层标签和模块收起解决。
- **一个限制要知道：** 贴图是 2.13 s 的循环，「偶尔爆发」在 UE 里每 2.13 s 原样重复一次。要更不规则只能加长周期（帧数和贴图变大）或做 2 张不同种子的变体交替。现在不做，看过 UE 实播再定。

### 1.2 导出模块漏接 + 合入门禁

- **Silver 的「随内容放大」有用、Comet 没用**（已核实，真烘 + 真导出）：Silver（CSLRS）是单层，参数原样进烘焙。Comet（CSLRC）是多层，每层经 `libP()` 烘焙，`zoom: P.zoom === 'on' ? 'on' : 'off'` 把 anchor 改成了 off。导出的 L1_TrailFull 没有 Size By Life、Pivot 还是居中。同一个原因：空中花型层在多层 / 我的效果里选「锚在爆点」也无效；你存的「Silver 3.1 · 我的」（一层的我的效果）打开后也会丢锚点（推断）。
- **Comet 的出入点「没法选」**（已核实）：右栏「输出 › 入点与出点」两个滑杆对金尾层是有效的（cutIn 1 / cutOut 4 → 导出 delay 1 s、时长 3 s，PC 和手机都对）。
  - 但时间轴上「设为入点 / 出点」按钮和把手只给空中大面片（`79_workbench.js` `editLayerP` / `cutOK` 只认 `usesTickPlan40`），合成一张一个都没有。右栏那一节的说明又叫你去时间轴点按钮，所以看起来没法选。
  - 第 2 层红头（纯星头）完全不读入点 / 出点：剪了金尾，红头仍从 0 s 播。
- **帧数分配「基本不生效」**（已核实）：合成一张的取帧函数 `rtFullSchedule`（47_risetail.js）只认「固定机位」，别的 4 种（lean / count / tiers / full）都静默按「按运动分」。
  - 下拉却列出全部 6 种，各模式的子项又都隐藏了，切过去什么都不变。
  - 两个条目的格子固定 16×1×RGBA = 64 帧（`rtGrid = -1`），固定机位时「每帧停几 tick」放不下就被悄悄加大，所以设 1 / 2 / 3 一样。
  - 真正生效的只有「燃烧 / 淡出最低帧率」（maxHoldBurn / maxHold）和格子。
- **为什么别的对话框做的新效果总是只管实时：** 没有任何东西强制一个新产物形态把「取景 / 帧数 / 入出点 / 多层 / 手机 / 引擎回放」都接上。界面按 SCHEMA 全部显示，检查只查跑过的路径。完整清单见第 2 节 A、B。
- **门禁方案**（见第 2 节 G）：全量烘焙太慢（云端软件 GL 下分层粒子图的镜头烘焙要几十分钟），改成两层：
  - 快检（1–3 分钟，不真烘）：「看得见又没变灰的导出行必须改变产物」+ 导出 JSON 合法 + 引擎回放和 cascade.json 发射器一一对应 + 界面状态检查的几项关键检查。
  - 只在动了渲染代码时加一组小图真烘（128 px、≤ 16 帧、8 个代表效果），比实时和烘焙的光量。
  - 挂在 git pre-push 钩子上，CLAUDE.md 写成推送前必跑。

### 1.3 Comet 星头 CPU 粒子

- 「导出包里没有速度和大小」**对 PC 的「光点」成立，对手机不成立**（已核实，探针拿到了实际 JSON）。
  - PC 选光点：走的是礼花专用的 `fwlDots` → `dotVis`。尾缀模拟里只有弹体星，被跳过，结果是一个空壳发射器：出生率 0、没有 Burst、颜色 0、没有位置和速度；大小 100 cm 取的是礼花的 `headSize` 缺省值。层页头还写「GPU 光点约 150 颗」，引擎回放里星头直接消失。
  - 手机：已经输出一颗 CPU 软圆点 `rtHeadDotES`（47_risetail.js），带初速 7145 cm/s 和 14 点的 Velocity/Life 曲线（从 7145 降到 2200 cm/s），大小 = `rtHeadSize`。
  - PC「序列」：输出的是单帧小面片，本身就带速度曲线。所以你要的能力已经写好了，只是没接到 PC 的光点。
- **方案：** 纯星头层（`rtHeadOnly`）的 PC 也输出 `rtHeadDotES`。选项改名「CPU 粒子（星头）」，PC 给「序列 / CPU 粒子 / 不出」，手机给「CPU 粒子 / 不出」。
  - soft_dot、`gpu:false`、`max_alive 1`、Burst [[0,1]]、寿命 T、初速 + Velocity/Life（Absolute）、大小 `rtHeadSize`。
  - 补 `local_space: true`（和金尾一致，手机版也补）。
  - 引擎回放画它，产物表 / 层页头写「CPU 1 颗」，文件清单不再列贴图。
  - 导出拦截加一条：出生率 0 又没有 Burst 的发射器不许导出。
- **对齐精度：**
  - 14 点速度曲线积分后和弹道最多差 0.065 m（800 m 外 0.04 px）。
  - 误差主要来自金尾贴图的停帧（每帧尾巴尖最多偏 1.2–1.8 m）。
  - UE 里按 tick 积分，预计星头和尾巴尖差 ≤ 2.5 m（800 m 外约 1.5 px）。未经 UE 验证。
  - 弹道：出膛 71.45 m/s，平方阻力（终端 38 m/s），2.158 s 到 90 m，开花时速度 22 m/s。

### 1.5 实时画了、导出没画（Crackle 为例）

- **Crackle 的闪光不是没烘，是被入点切掉了**（已核实）。你存的 Crackle（`analysis/我的配方/my_fxmuuzfeg7/`）入点 0.2 s：
  - 烘焙从 0.2 s 开始，开花闪光（衰减 0.035 s）到 0.2 s 光量只剩开头的 0.3%。
  - 入点前那段，导出和回放只是把第 0 帧从 2% 放大，闪光不在任何发射器里。
  - 实时模拟不管入点，从 0 s 画，所以看得到。
  - 待我验收里 15 条 Crackle（MYCR-*）入点都在 0.16–0.59 s，开花闪光全丢。
- 一共 12 处「实时有、导出没有 / 不一样」，8 处要修、4 处要补标注，清单见第 2 节 B。分层粒子图没有这类问题（实时和烘焙同一个渲染器）。

### 1.6 关键误区与遗漏

1. 「13 层导出」不存在：分层只在编辑器里，产物本来就是一张。要守住的是「PC / 手机两套都是一张」。
2. Crackle 闪光丢失的真正开关是入点，不是烘焙通道。把入点清掉闪光就回来了，但那会改帧预算。正解是入点前的闪光单独导出。
3. Comet 星头「没有速度数据」只发生在 PC 光点这一条路径。手机和 PC 序列都有速度。
4. 门禁挡不住所有人：本地钩子可以 `--no-verify` 绕过，每个工作副本要各自启用一次。真要卡住只能走 PR + 必过检查（会拖慢所有对话框的提交），不推荐。推荐钩子 + CLAUDE.md 规则 + 快检脚本三层。
5. 第 5 个画面缺陷会改已通过的 RT6 S/M/L 手机合成图，需要你选「重验」还是「加开关、RT6 默认不变」。
6. 我 4.9.86 的变灰条件写错了一处：尾缀「只在实时模拟里画」那几行只在两个平台都合成一张时才变灰。可是手机近段也不出粒子层，应该只看 PC 合成一张（第 2 节 B4）。
7. 「燃尽后曲线与落火」开着时，落火在整个上升段被乘 0，只有燃尽后还活着的落火看得见。这是 Silver 3.1 落火看不见的原因之一，要你确认是不是本意。
