## 1. 两个具体问题的原因

**单束看不到、回放怪**
- 单束有两套入口：花型的「输出形式 = 单束」（P.form = 'unit'）和导出方案里的「PC：单束」（outPC / 层的 out.pc）。后者的单束贴图在单层里不留（导出时临时烘、导完丢掉，`67_fwlcombo.js:272,283`），多层里存在 `e.unitBake`、只在引擎回放或导出时才烘。
- 「贴图」「流转」只读主序列（`texSheets` 只认 `bakeParts / fades / far`），不看导出方案，所以选了单束 / 光点 / 不出，看到的仍是序列。
- 单层引擎回放：直接画序列，HUD 写「单束的引擎回放在多层效果里看」（`80_render.js:252`）；多层：第一次要后台烘，烘完前这一层是空的。
- 「怪」的来源：单束贴图是一颗星按直线、不受重力 / 风 / 随机烘的；引擎里每颗星同一套帧、沿速度方向立着，星下垂后尾巴都指向花心上方（XU1 已记「像辐条」）；回放和导出不一致（回放没速度随机、寿命随机口径不同、翻转 / 镜像 / 半球没处理）。另外 UE 4.24 有已知 bug UE-84941：速度朝向的面片在低速时被压扁（4.25 修），星到弧顶附近在 UE 里也会怪。

**RT6 粒子黑**
- 所有 GPU 粒子（RT6 各层火花、光点）的淡出、闪烁、冷却都写在 Color Over Life 的 RGB 上，Alpha 恒 1（`46_emitset.js:194`）。冷却到 1450 K 以后最后约 20% 寿命 RGB ≈ 0；SparkPops 前 85% 寿命 RGB = 0；细火花 RGB 最大 0.24。
- 烘焙器预览按「加色」画（RGB 0 = 看不见），代码注释也写着「用颜色压暗（加色，等于 Alpha）」——这只在 Additive 材质成立。Translucent 材质里 RGB 0 + Alpha 1 = 一个黑点。预览还乘了一个「自发光 ×4」的假设（`46_emitset.js:133`），未经实测，所以亮度量级也可能对不上。
- 你说的方向是对的：颜色只管色相和亮度，淡出 / 闪烁走 Alpha 或 Size By Life。

## 2. 你的深层需求（从历来的原话归纳）

1. **导出物是能直接用、能接着调的引擎资产**，不是烘焙器里的截图。离开烘焙器的隐藏曲线也能复用（10-05「丢失了你的曲线参数，这张素材基本无法复用」）；亮度、频闪、大小要能在 Cascade 里调（10-05「大小我可以调整，亮度频闪这些我没法调整」）。
2. **帧是最贵的资源**：每一帧都要被看见、花在变化大的地方；开花段不顿，尾段不浪费（10-02「至少都浪费有50%了」、「引菊其实只有十几二十帧就可以搞定」；10-01「之前4.56秒渲染成4x4在游戏中都很流畅」）。
3. **所见即所得**：贴图 / 流转 / 引擎回放 / 交付清单 / UE 里看到的是同一个东西；任何导出形态在任何视图里都看得到（10-06「不要单独只为这个尾缀添加功能……就都可以切换」）。
4. **一个效果是多种产物的组合**：序列面片 + 单束 + GPU 粒子，PC / 手机两套，还有多规格、多种子（10-02「有些效果我也想到处面片+单束+粒子……导出之前在图层选择导出方案」；10-07「2尺玉到4尺……多做几个不同规格」）。
5. **规则别定死**：下限 + 建议 + 可覆盖，旧做法在新做法实测过之前不删（10-01、10-05「旧的这个先留着，我先测试」）。
6. **以 UE 实测为准**：浏览器里的流畅 / 卡顿只是参考。

## 3. 为什么现在零散

- **产物形态的入口有 5 处**：花型的输出形式（大面片 / 分段 / 单束）、单层「导出方案」、多层每层的导出方案、交付页「导出单束包」、升空尾缀 RT 专用的循环层 + 粒子；另有种子变体。每种各自一条「烘焙 → 回放 → 写 cascade.json」的路，所以每加一种就「做一套存一套」，视图也各认各的。
- **帧的规则在 6 种模式里**：按运动分（默认）、匀速、以及最省 / 手动 / 分段帧率 / 全程 30 fps 四个旧模式；自检还在用旧的「< 24 fps 尾段可能发卡」；「分段」的说明仍是 4.0 前的「开花段 + 下垂段两张」。你看不到「这一张里每段多少 fps、哪几帧几乎一样」。
- **引擎写法没有统一规矩**：颜色 / 亮度 / 淡出 / 闪烁混在一条 RGB 曲线里；材质的混合方式没写进规格；GPU 模块限制、曲线查找表精度只零散记着。
- **验证不闭环**：帧号曲线（匀速 / 持帧 / 陡变三种）、RGBA 串帧、曝光标定、单束在 UE 里，都还是 ⚪ 未测。

## 4. 设计：一张「产物表」 + 一本「帧账本」 + 一套「Cascade 写法」 + 一个「实测闭环」

### 4.1 产物表（统一模型，解决零散）
- 每一层（单层效果 = 只有一层）有一张产物表：行 = 这一层要出的东西，列 = PC / 手机。每格选一种产物：**序列面片 / 单束（每星一个面片）/ GPU 光点 / 不出**；升空尾缀的「近段循环 + 远段 + GPU 火花」就是同一张表里的三行。以后要「面片 + 粒子补闪」也只是多一行。
- 烘焙出来的不再是「一个主序列 + 若干挂件」，而是一份**产物结果清单**：每行有自己的贴图列表、发射器列表、帧计划、检查结果。贴图 / 流转 / 引擎回放 / 交付清单 / cascade.json **都只读这一份**。这样单束、光点、远段、消散自动在所有视图出现，不再为某种效果单做。
- 花型里的「输出形式 = 单束」和导出方案里的单束合成一个（产物表里选）；「分段」不再是一种形式，只是「帧多了自动多张」。
- 交付清单升级为这张表的总览：每格写 产物 · 帧数 / 张数 / 尺寸 / 显存 · 发射器 / 粒子数 · 检查状态，点一格就切到那个产物的贴图 / 回放。导出按钮只导这张表上的东西。

### 4.2 帧账本（解决「合适、不卡、不浪费」）
- 现在默认的「按运动分」已经满足几条硬道理：每帧停整数个 30 fps tick（不会忽快忽慢）、开花段 1 tick / 帧（30 fps）、之后一档一档放慢（最慢燃烧 10 fps、淡出 7.5 fps）、先填满一张 64 格再加张、帧号曲线关键点 +0.01（和 Epic 文档的「1.01」规矩一致）。密度和你在游戏里验证过流畅的金芒菊 4.56 s / 64 帧（22 / 21 / 11 / 10 帧分别停 1 / 2 / 3 / 4 tick）基本一样。
- 缺的是**看得见、可试算、有客观口径**：
  1. **账本**：每张贴图列出各时段 帧数 × 每帧停几 tick = fps、可见帧比例、空帧 / 近似重复帧、单格像素和游戏距离下的屏幕放大倍数。时间轴上的帧刻度跟着上色（30 / 15 / 10 / 7.5 fps 四色）。
  2. **试算三档再烘**：例如「32 帧（半张）/ 64 帧（一张）/ 128 帧（两张）」，各写每段 fps、显存、预计在游戏距离下每帧屏幕位移，你点一档再烘。
  3. **「卡不卡」的口径换成屏幕位移**：相邻两帧之间，星在游戏距离（800–1200 m、四尺玉占 1/3 屏高）下屏幕上跳了多少像素。用你验证过的金芒菊 4.56 s / 64 帧算出这个值当标定线；帧计划按「每帧位移不超过标定线」分，而不是只看 fps。规则别定死：标定线是建议值，可改。
  4. **「浪费」分三类处理**：开头太小的帧——入点 + 入点前放大（4.9.21 已改成绕爆点）；尾段变化很慢的帧——自动并成更长的持帧（按画面差异，不只按星速）；最后的整体淡出——可以选「交给引擎」：烘到形状不再变就停，最后一帧停住，用 Alpha 淡出（省下尾段 10–20% 的帧，需要先实测）。
  5. **模式收成两种**：按运动分（默认）/ 匀速（备用）；四个旧模式等 UE 实测包第 1 项看过再删。自检阈值改成标准 2.3 的 10 / 7.5 fps。

### 4.3 Cascade 写法（解决「GPU 粒子、单束在 Cascade 完美可用」）
- **颜色 / 亮度 / 淡出 / 闪烁四件事分开写**：
  - 色相：Initial Color 或 Color Over Life 的 RGB 只管颜色，亮度用恒定的 HDR 倍数（可以 > 1）；
  - 淡出：Alpha Over Life（半透明材质）；加色材质也可以写 RGB，但从不让半透明材质的 RGB 到 0；
  - 闪烁 / 频闪：Alpha 方波或 Size By Life 方波（两种材质都安全）；GPU 粒子的曲线会被烘成共享查找表，一生里开关次数控制在约 8 次以内、平台写宽，随机感靠寿命随机错开（HK10 光点在 UE 里闪是过了的）；
  - 总亮度：单独一个 Scale Color/Life（RGB = 倍数、Alpha = 1），你在 UE 里改一个数就能整体调亮调暗。
- **材质档案写进规格**：soft_dot、序列材质各是什么混合方式、透明度接哪个通道；导出器按档案选写法，半透明档案下发现 RGB → 0 就报错。
- **GPU 白名单**：只写 GPU 支持的模块（一个 Const Acceleration、没有 Dynamic Parameter / Event Generator）、固定包围盒、曲线点数精简（不变就 2 个点）；手机不用 GPU，出 CPU 版或纯贴图。
- **单束的定位**：它本质是「每颗星一张沿速度方向的直尾面片」，星下垂后尾巴不会跟着弯。建议定为「短尾、快星」专用（牡丹、点灭、千轮子花），长尾下垂的层（锦冠、柳）自动提示改用序列；远期可以评估 Cascade 的 Ribbon（尾迹会跟着真轨迹弯，但只能挂 CPU 粒子、粒子数要算进预算）。回放和导出必须同一套参数（速度随机、寿命随机、翻转、镜像、半球）；弧顶附近速度很低时注意 4.24 的压扁 bug。

### 4.4 实测闭环
- 一个「导出基准包」，你导入后 10–15 分钟看完：帧号三种曲线（已有 `UE实测包/1_帧号`）、GPU 淡出三写法（RGB → 0 / Alpha → 0 / Size → 0 各一个发射器）、频闪两写法、单束一层、RGBA 串帧一张（手机 ASTC 4×4 / 6×6 对比）。
- 每个结论记进 `spec/UE实测.md`，导出器的默认值只在实测过的项上收紧；没测的写「未经 UE 验证」。

## 6. 外部资料要点（只作参考，未在 4.24 里逐条验证）

- Translucent：RGB 0 + 不透明 = 画黑；Additive：RGB 0 = 什么都不加。淡出用 Scale Color/Life 动 Alpha、RGB 保持，是 Epic 论坛的标准做法。
- GPU Sprites 不支持 Dynamic Parameter、SubUV Movie、Random SubUV，只能一个加速度；随寿命曲线烘成共享低精度查找表，硬方波会被抹成短斜坡（我们 HK10 的方波在 UE 里实测仍闪）。
- 帧号曲线取整要 +0.01（Epic「1.01」规则），我们已经这么做。
- ASTC 把四个不相关的灰度帧打进 RGBA 最容易串帧，块越大越明显；手机建议 4×4 / 6×6，并做串帧实测。
- Houdini Labs Flipbook ROP、EmberGen 导出器都把「起止帧 / 跳帧 / 每帧分辨率 / 格子 / 通道打包 / 单格预览」放在一个面板里——和第 4.1、4.2 节的「产物表 + 帧账本」思路一致。
