## 0. 一句话

首选做法：**每颗星的真实轨迹做成一条「预先朝向的单片带」，带上的 V 坐标存「星头经过这里的时刻」，材质 UV 匀速流动**。这样星头的减速、伞形、垂帘都直接来自烘焙器的同一套模拟，不靠整体放大网格去凑。整朵花还是 1 个网格粒子、1 次绘制。

和你的思路相比，改了三处：

1. 不做十字束，单片就够，面数省一半。
2. 网格不做整体缩放，大小、动态都写进几何和 UV。
3. 面数不是主要成本，透明像素才是。

本轮只做 PC 主层，先在沙盒里验证，不进正式表。

## 3. 关键误区（依据）

1. **「十字束防穿帮」在这里多余，还有害。**
   - 依据：2.0 网格层用 `MeshFaceCameraWithRoll`，整个网格总是同一面朝相机。
   - 只要把每根带的宽度方向做成「垂直于这根线、也垂直于朝相机的那根轴」（预朝向单片），从任何机位看投影宽度都 ≥ 名义宽度 × cos（视线偏角）。1000 m 看 700 m 的花，偏角最大约 19°，即 ≥ 0.95 倍。
   - 十字束让三角形翻倍。斜看时两片同时可见，线会变亮、变粗，端头出现「X」。
   - 待实测：朝相机的到底是哪根轴。2.0 的 8 顶点面片 `SM_EFX_Plane_17` 本身是十字片，说明前人可能只是习惯，不能证明非要十字。
2. **2.0 的动态做法不适合鸿巢。**
   - 2.0 是「固定形状 + 整体放大 0.5 → 1.5 + UV 线性走一遍」，所有线的弯曲按比例一起放大。
   - 鸿巢是初速 900 → 平方阻力急刹 → 上半停住、下半以 34 m/s 垂落，伞形 → 垂帘是形状本身在变，整体缩放表达不了。
   - 改成「几何 = 完整轨迹，V = 时刻」：UV 匀速流动时星头按真实速度走。尾巴的亮度只取决于「星头经过这里多久了」，正好就是火花 / 余烬按年龄冷却、熄灭；尾迹长度会随减速自然变短。
3. **「最大化缩减面数」的力气用错了地方。**
   - 标准款 400 束约 12.7 k 三角、1 次绘制，PC 上可以忽略。
   - 真正花钱的是透明像素（§2.4）。依据：B05 实测，960 低配 Translucency 到约 1 ms 就触发降分辨率（编排B08 已定清单）。
   - 该优先控制的是：带宽 × 长度 × 束数，以及按时间切块。
3b. **「拿不准面数就每份出三款」——面数可以算出来，不用猜。**
   - 用「星头位置误差 ≤ 0.5 px @800 m」一条口径就定了。
   - 三款可以一键全生成（脚本只差一个参数）。但只有标准款进 UE；另在 400 束上导入一组精 / 标准 / 省做 A/B，用截图验证「0.5 px 看不出」这条假设。
4. **「导入网格是卡点」——技术上不卡，卡在流程上。**
   - UE 的 Python 远程执行本机已经在用（`tool/fwlight` 写灯光），`AssetImportTask` 能导 FBX / OBJ。
   - 真正的门槛：
     - UE 单写登记；
     - P4（保存新资产可能触发 P4，P4 不通时会卡约 2 分钟）；
     - 私有导入器不管网格；
     - 用 Python 很难新建 Cascade 模块，只能复制现成系统再用 `/object/set` 改；
     - 在共用关卡里摆测试 Actor 要不存盘。
5. **Blender 不是必需的。**
   - 几何应直接从烘焙器模拟核出（同一套物理，标准 §3「同一模拟核」），可复现、能跟配方改。
   - 本机 Blender 5.2.2（Steam 版，无界面可运行）只在 OBJ 轴向 / 单位出问题时，作 OBJ → FBX 转换用。

## 5. 首选方案（细）

### 5.1 几何生成（程序化，Node，读烘焙器源码）

- **入口**：新脚本 `analysis/scripts/网格垂柳_生成.mjs`。
  - 照 `帧号点数_当前计划.mjs` 的写法，用 vm 载入 `tool/src/js` 的 `00_util / 05_quality / 10_types / 20_sim`。
  - 不改 `tool/src`。
- **模拟**：
  - 配方取第 0 步核定的那份，主层 P 加 `engine: 'gpu'`（不出火花，只要星头）。
  - 步长 1/240 s，每 1/60 s 记一次每颗星的 (t, x, y, z, 星头亮度)，只留星头发光那段，前面补上开花点 (0, 0, 0)。
- **选星**：按初速方向做最远点排序，取前 200 / 300 / 400 颗；星编号写进旁注 JSON。
- **分段**：
  - 贪心延长一段，直到段内「按时间线性插值」的最大位置误差超过 ε；
  - ε：标准款 0.78 m（0.5 px @800 m），开花 0.6 s 内 ×4；
  - 精款 0.39 m 全程；省款 1.56 m（开花 0.6 s 内 ×4）。
- **坐标**：
  - 爆点为原点，单位 cm；
  - UE 的 Z = 模拟 y（朝上），UE 的 X = 朝相机那根轴（以实测为准），UE 的 Y = 另一水平轴。
- **单片带**：
  - 每个顶点沿 w = normalize(T × X̂) 往两边各偏 W/2（T = 切线）；
  - |T × X̂| < 0.1 时（线正对相机）改用 T × Ẑ；
  - U = 0 / 1 两边，**V = τ / S**（τ = 星头经过这个顶点的时刻，S = 3.2 s = 条带贴图能表示的最长年龄）。
- **输出**：
  - 每份一个 OBJ（或 Blender 转 FBX）+ 旁注 JSON：配方指纹、烘焙器版本、星编号、S、h、L、W、ε、顶点 / 三角数、包围盒、Dynamic Parameter 0 曲线。
  - 先出一个**轴向 / 单位试件**：三根带，X 10 m 红、Y 20 m 绿、Z 30 m 蓝。

### 5.2 拖尾条带贴图（新贴图，不是新材质）

- **尺寸**：64（U，横向）× 512（V，年龄），Clamp / Clamp，BC7，sRGB 开（A 通道在 sRGB 贴图里仍是线性）。
- **V 方向**：V = 1 那一行全透明（星头前面）；星头在 h = 0.98；往下年龄增加，到 V ≈ 0 是年龄 S，全透明。
- **亮度 vs 年龄**：
  - 用烘焙器同一套火花寿命 / 冷却 / 余烬参数算，不手画；
  - 白热段（0–0.76 s）+ 余烬（64 %，2.35 s，亮度 0.6）；
  - 颜色按配方 Ramp 映射；
  - 星头（年龄 ≈ 0）最亮。
- **横向**：高斯软边，带宽 W 内看见的芯约 W / 3。

### 5.3 Cascade（沙盒系统；单位 cm / s，颜色 0–1 与亮度倍数分开写）

做法：在 UE 里**复制** `P_EFX_FireWorks_Hero_HD` 到沙盒目录，关掉另外 12 个发射器（只关不删）。下面是网格层改后的值。

**System**
- SystemUpdateMode：A 份 `EPSUM_FixedTime` / UpdateTime_FPS 10（项目口径）；B 份 `EPSUM_RealTime`，对比用。
- LODDistances：[0]（只留 1 个 LOD）。
- 固定盒：开，Min (−100000, −100000, −100000) / Max (100000, 100000, 100000)。
- WarmupTime：0（截图时临时设成 t，见 5.4）。

**Emitter `Particle Emitter`（网格层）**
1. **Required**
   - Material：沙盒材质实例 `MI_…_MeshWillow`；
   - Use Local Space：false；
   - Emitter Duration：11.5，Loops：1；
   - Screen Alignment：PSA_Square（网格不受影响）。
2. **Spawn**：Rate 0；Burst：Count 1，Time 0。
3. **Lifetime**：Constant 11.5。（p95 熄灭 8.78 s + 余烬 2.35 s ≈ 11.1 s，留 0.4 s。）
4. **Initial Size**：Constant (1, 1, 1)。删掉 2.0 的 Size Multiply Life × 2，网格本身就是世界大小。
5. **Initial Color**：颜色 (1, 1, 1)，Alpha 1。
6. **Scale Color / Life**
   - 颜色曲线（相对寿命 = 秒 / 11.5）：0 → (1, 1, 1)；0.626（7.2 s）→ (1, 0.941, 0.918)；0.713（8.2 s）→ (1, 0.784, 0.753)。
   - 亮度倍数：另乘 K，起点 K = 20，按烘焙器曝光标定（2.0 用的是 R × 50、G × 10）。
   - Alpha：0 → 1；0.97 → 1；1.0 → 0。
7. **Dynamic Parameter**（4 个通道，都 `UserSet`，不用 Emitter Time）
   - 0 UVIncrement：线性曲线 0 → 0.98，1 → −2.614（= 0.98 − 11.5 / 3.2）；
   - 1 Param2：常数 1.02（先关溶解，和烘焙器一比一；以后要「碎着灭」再开）；
   - 2 DistortIntensity：常数 1；
   - 3 AlphaMaskUVScale：常数 1。
8. **Mesh Rotation**：删掉，不要 2.0 的随机偏航。
9. **TypeData Mesh**
   - Mesh：沙盒网格 `SM_…_N400_E05` 等；
   - MeshAlignment：`PSMA_MeshFaceCameraWithRoll`；
   - Override Material：true；
   - Cast Shadows：false。

**材质实例**（复制 `MI_EFX_FireWork_Trail_01`）
- MainTex = 新条带贴图；`AlphaChannel` = (0, 0, 0, 1)；`UVParam` (1, 1, 0, 0)；`UseDynamicUVIncrement` 开；`UVIncrementChannel` (0, 1, 0, 0)。
- 双面开；DepthFadeDistance 100；其余照原值。
- 推断（没核实）：「不新增材质」指不新增母材质，复制实例算正常（导入器一直这样建实例）。

### 5.5 「别的方式模拟」：Cascade 仿真预览

- **形式**：独立 WebGL 页 `tool/prototypes/mesh-willow-v1/`（不碰 `tool/src`）。
- **读入**：同一个 OBJ、条带贴图、旁注 JSON。
- **照 5.3 计算**：
  - 网格粒子 X 轴对相机；
  - Dynamic Parameter 0 / 1 曲线；
  - V_tex = V + Dynamic Parameter 0，Clamp 取样；
  - 透明度 = A × 粒子 Alpha；
