## 第 3 条展开：花和尾缀终点

做法：每个子模板里，每根尾缀按自身 RotationOffset 走表上高度（S 150.07 / M 210.11 / L 330.18 / Tiny 62.02 m），得到终点和到顶时刻（LocalTimeOffset + 升空时间）；每朵花找「到顶时刻差 ≤ 0.01 s」的尾缀终点，量距离；再做一一配对（排列穷举）。两种约定：

- 作者约定：Roll 正 → 局部 −Y；
- UE4 推断：FRotationMatrix 把局部 +Z 变到 (−(CR·SP·CY + SR·SY), CY·SR − CR·SP·SY, CR·CP)，P = Y = 0 时是 (0, sin R, cos R)，即 Roll 正 → +Y（推断，未实测）。

| 版本 | 花条目 | 作者约定超 2 m | UE4 推断超 2 m | UE4 下对不上的实例（高配）PC / 手游 |
|---|---|---|---|---|
| B06 | 173 | 0 | 166（最大 28.3 m） | 638 / 655，327 / 333 |
| 16.0.33 | 78 | 0 | 75（点灭星 9.83、银冠菊小号 9.30、辉星中号 12.46、LittleGold 28.3 m） | 912 / 929，615 / 621 |
| **修订1** | **78** | **0** | **0** | **0 / 929，0 / 621** |

- 时刻：78 个花条目 LocalTimeOffset 都等于同子模板某根尾缀的起飞偏移 + 升空时间（差 0）。
- 球花：54 个子模板（S 20、M 24、L 10）尾缀 Roll 全 0，花在正上方，两种约定距离都是 0.000 m。
- 小平台带花的 8 个子模板（LittleGold / LittleCombo ±11.3° + 竖直；LittleGoldV02 / LittleComboV04 竖直 + ±9.4°；LittleCrackle / LittleComboV02 ±8.1°；LittleCrackleV02 / LittleComboV06 ±10.5°）：
  - 每对两根尾缀：同资源、EffectScale 1、同一 LocalTimeOffset、Roll 互为相反数；
  - 对应两朵花：同资源、同缩放、同时刻，Y = ±h·sin a，Z = h·cos a；
  - 约定反了，+Y 的花落到另一根（Roll 符号相反那根）的顶端，距离 0。两朵花一样、两根尾缀一样、同时起飞，所以**画面上等价**（推断：前提是 RiseTrail_Tiny 自身左右对称、没有朝单侧的漂移）。
- 剩下没对上的：无。无花的 V 形四根（RiseTrailTiny，Roll ±5 / ±16，随机 ±6°）没有花，不在此条。扇（FanComet9Left / Right）Roll 方向反了只会让扫的方向左右对调，扇位置不变（推断，与本条无关）。
- 手游尾缀：`analysis/results/RT6SE7/` 两份 cascade json 的差别只在贴图名、后面几个发射器的 gpu 标志和发射率，RiseLoop 运动模块无差别。手机上实际用的 RiseTrail_S_M 是不是这份导出、到顶高度 / 时刻是否一样，没核（没有 UE 读回）。
- 结论：**表里对上了；手游上若仍错位，问题在资源 / 渲染**（推断）。

- 代价（作者在「要你看」里写了）：宽度保住，但中间变空。
