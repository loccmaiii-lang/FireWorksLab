  - 这和用户 12:14 说的点灭星错位是同一种机制，偏得还更大（点灭星按同一公式只差 9.8 m）。
  - 球花这一部分修好了：54 个球花子模板倾角都是 0，两种约定下花和尾缀终点最多差 0.03 m，时刻差 0。
- 其他客观改动核下来是真的：
  - 扇在严格口径下 0 对重叠，但最小时间余量只有 0.075 s；
  - 手游中配同屏面积压回 B06（峰值 8.46 = 8.46，平均 1.660 < 1.721）；
  - PC 花的发射和 B07 逐条相同。

## 第 3 条展开

做法：

- 每个带花的子模板里，按 LocalTimeOffset 把每个花条目配到一根尾缀（花的时刻 − 尾缀的时刻 = 升空时间）。
- 尾缀终点 = 尾缀 PositionOffset + 旋转后的 (0, 0, 到顶高度)。到顶高度取验收单的表：150.1 / 210.1 / 330.2 / 62.0 m。
- 所有尾缀的 Pitch、Yaw 都是 0，只有 Roll。父模板条目的位置、旋转全是 0。
- 两种约定：
  - 作者约定：Roll 正 → −Y。终点 = (0, −H sinR, H cosR)。
  - UE4（推断，没实测）：FRotationMatrix 第 3 行（局部 Z 轴）=(−(cR sP cY + sR sY), cY sR − cR sP sY, cR cP)。P = Y = 0 时是 (0, sinR, cosR)，所以 Roll 正 → +Y。
- 平台按父模板条目的 PlatformFlags 分开：含 2 的是手游，含 4 / 8 的是 PC。

| 球花（54 个子模板），PC 529 / 手游 221 次 | 最多 0.030 m，全过 | 最多 0.030 m，全过 |
| 小平台带花（12 个子模板），PC 400 朵 / 手游 400 朵 | 最多 0.020 m，全过 | 400 / 400 朵都 > 2 m，最多 28.32 m |

  - 球花表内对得上。点灭星要是还错位，问题在资源 / 渲染（比如手游 RiseTrail_S_M 的到顶高度 / 时刻），不在表里。

先按原文（同一个父模板 = 一排，≥ 4 点）：

  - 中配 7 处：121.5 s GoldChryV03（少 P1 / P7）、183.2 s GoldChryV02（少 P7）、B 排 26.5 / 123.3 / 162.2 / 165.5 / 181.6 s。

再按作者的口径（同组、同一种花、起飞相差 ≤ 2 s 的父模板合起来）：

- PC 132 排、手游 56 排，0 处丢端。
- 19 处里有 18 处，是同一时刻按大小拆开的片段（×0.92 / 1.0 / 1.08）。起飞相差 0–0.6 s，高度一样，花种一样。合起来是 P0–P8 九点：中配 P0 / P2 / P4 / P6 / P8，低配 P0 / P4 / P8（或 P0 / P2 / P4 / P6 / P8）。两端都在。
- 例：183.1–183.6 s 金曜菊，原片段 P0 / P1 / P5 / P6 / P7，×0.92 是 P2 / P4 / P8，×1.08 是 P3。低配合起来是 P0 / P4 / P8。和作者说的一样。
- 剩 1 处靠 2 s 窗才过：112.0 s 多重菊大号在 P2 / P4 / P6 / P8，P0 那朵 113.6 s 才起飞（晚 1.6 s）。窗口取 0.3–1.5 s 时，这里低配少 P2。
- 2 s 窗是单链合并，会把 112.0–118.2 s 的 7 个多重菊片段串成一排。只有这一串超过 1 s，不改变结论。

我接受作者的口径。理由：

- 用户原话是「这样**看起来**播放范围不会变」，说的是看到的宽度，不是表的结构。
- 被拆开的片段同时、同高、同一种花，看起来就是一排。
- 宽度的实测也支持（第 16 条）：中 / 低配的左右范围是高配的 1.00 / 0.97，B06 只有 0.89 / 0.76。

保留的意见：

- 验收单是作者自己写的。以后应该把口径写成「同组、同一种花、起飞 ≤ 1 s」，再单独处理 112 s 这种晚 1.6 s 的端点。
- 两端都在，不代表中间不空：PC 低配覆盖宽度只有高配的 82 %。

## 第 5 条展开

- 直径：
  - 原生直径按资源取，来自交付 dfshow（`NewYearFireWorks_v01-B07修订1-球花竖直-扇不叠.dfshow`）的 templateLibrary 基础花型：小号 90 m、中号 150 m、大号 230 m（用户 10-10 的尺寸），金垂柳 230 m。
  - 小平台小花取 templateLibrary 直径 ÷ 子模板缩放：LittleGold 40、LittleCrackle 24、LittleSilver 32、LittleCombo 30 m。
  - 每朵的直径 = 原生直径 × 子模板花条目的 EffectScale。
  - 交叉核对：R1 的 74 个子模板按 mappingAudit 对回 templateLibrary，直径 0 处不符。
- 亮着的时间：开花（StartTime + 父 LTO + 子 LTO）到开花 + 0.75 × 寿命。寿命取 templateLibrary 的 life（例：银冠菊 4.56 s、金芒菊 4.56 s、银彩菊 4.56 s、金垂柳 9.7 s）。
- 面积：每朵 (D / 230)²，按 0.01 s 采样到 214.4 s。平均是全程平均（含空的时候）。扇不算。

## 方法（能重跑）
