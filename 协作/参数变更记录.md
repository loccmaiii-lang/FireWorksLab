## 2026-10-14 · 烘焙器 4.9.102（导出（23））：加 1 个参数 `rtFullFx`，两处含义改了（落火的燃尽门、落火进贴图的亮度）

- **用户原话**（10-14 13:12）：「全部要修」；（14:14）「按第 3 节执行顺序从 4.9.88 做起；第 4 节要我定的按推荐默认处理（我另有意见会直接说）」。第 4 节两条推荐（`协作/方案_导出排查_2026-10-14.md`）：② 「V5 加开关 `rtFullFx`，RT6 默认关、画面不变，CSLR* 和以后的新条目默认开；RT6 要开再重验」；③ 「燃尽门只作用在曲线上，落火上升段照常可见；会改 Silver 3.1 的落火」。
- **加了什么**：`rtFullFx`（合成一张时烘进贴图，选项 0 / 1，类别引擎字段）。在「输出 › 导出方案」，只在合成一张（PC 或手机选了「近段 + 远段合成一张」、不是纯星头）时出现。
  - 1：合成一张的序列里，星头光晕 `HeadGlow`、末段爆亮 `SparkPops`、发射口闪光 / 火花 `LaunchGlow` / `LaunchSparks`、烟带 `Smoke`、GPU 落火 `Embers` 和贴图落火按实时模拟里的样子烘进去——每帧先照旧画星头 + 火花，再把这些软圆点按引擎自发光口径画进一张临时图，逐像素按材质（Ramp × Color Over Life × 显示强度 × rtBright × 4）反推新的灰度。实时模拟（单层、多层）照画同一份。限制：颜色变成 Ramp 色；亮到 253 截顶；入点以前的不在；材质改了要重烘（烘焙器自己重烘、导出前也查）。
  - 0：和 4.9.97 逐字节一样（只有星头 + 火花）。
  - **缺省**：`BASE` 里 0（存档 / 条目没写的 = 0：RT6 S/M/L、FC2R / FC3O、你的「我的效果」画面都不变）；新建的升空尾缀模板（`TEMPLATE40` tailS / M / L）写 1；CSLRS、CSLRC-T 条目写 1（它们本来就在待我验收、要重验）。
- **含义改了**：
  - `rtTailAfterBurn = 1`（燃尽后渐入）对落火：以前落火的亮度再乘一次燃尽门，整个上升段 × 0、只有燃尽后还活着的落火看得见；现在燃尽门只作用在「大小 / 亮度随寿命」曲线上，落火上升段照常可见（推荐 ③）。所以没填曲线时这一项不起作用（右栏变灰写原因）。影响 CSLRS / CSLRC-T（Silver 3.1）的落火。
  - `rtETex = 1`（落火进入合并贴图）且 `rtFullFx = 1`：落火的亮度 / 大小从贴图火星口径（× 0.01 × 贴图火星亮度 ÷ 细火花亮度，比 GPU 落火暗 125–740 倍、没有最小尺寸）改成 GPU 落火的口径（`rtEI`、`rtESize`、远看直径 `rtGpuDisp` / 增益 `rtGpuGain`、粒子层亮度总倍数 `rtDotGain`，σ = 尺寸 / 4、最小 0.55 像素）；出生、寿命、运动（含燃尽后气流）不变。`rtFullFx = 0` 时照旧。
  - 合成一张 + `rtFullFx = 1` 时，以前变灰的「GPU 粒子 / 引擎里加的效果」那些行（光晕、爆亮、发射口、烟带、远看直径 / 增益、粒子层亮度、落火）起作用了；GPU 火花预算、闪烁火花仍不起作用。
- **类别**：导出（只在 `rtFullFx = 1` 或「落火进贴图 + 燃尽后渐入」时变，导出指纹多一档 `fullfx`）+ 界面（一行新下拉、变灰规则）；已有条目打开后的参数逐键不变（CSLRS / CSLRC-T 的条目数据加了 `rtFullFx: 1`）。

## 2026-10-14 · 烘焙器 4.9.96（导出（23））：没有新参数——「光点」在纯星头层上的含义改了、一处可选值放开

- **用户原话**（10-14 13:12）：「Comet 的星头我不想导出成序列图，只想要一个上升速度能跟尾缀对齐的 CPU 粒子；但目前选择 GPU/CPU 粒子导出时，导出包里根本没有速度和大小的数据。这是一个能力缺失，请给出补齐方案。」「比如我保存的 Crackle，在『实时模拟』里有开花闪光，但在『引擎回放』和『贴图流转』里完全看不到闪光。」；（14:14）「按第 3 节执行顺序从 4.9.88 做起；第 4 节要我定的按推荐默认处理」。
- **改了什么**：
  - `outPC = dots`（单层）/ 层上的 `L.out.pc = dots`（多层）：在**纯星头**的尾缀层（只有星头、没有火花的 RT6 合成一张，如 Comet 红头）上，含义从「礼花的 GPU 光点（只出星头）」改成「CPU 粒子（星头）」= 手机那颗软圆点（`rtHeadDotES`，CPU、1 颗、没有贴图）。以前这个值在尾缀层上导出空壳发射器（4.9.89 起不给选、存的按 `seq`）；现在纯星头层又能选，别的尾缀层照旧不给选。礼花层上的含义不变。界面上纯星头的 PC 选项写「序列（单帧小面片）/ CPU 粒子（星头）/ 不出」，手机「CPU 粒子 / 不出」。
  - 纯星头单层的 `outPC`：可选 `full`（单帧小面片，原来那种）/ `dots`；`emitFullOut` 把 `dots` 也算进「合成一张」那一套（入点 / 出点照样起作用）。
  - 多层产物表的尾缀层：PC「近段 ↔ 合成一张」、手机「近段 ↔ 合成一张」写到这一层尾缀自己的 `outPC` / `outMobile`（和单层产物表同一个值）；「不出」写在层上（`L.out`）。
- **没有新参数**：入点前的开花闪光（Flash 发射器）、单束 / 光点的闪光都用已有的开花闪光参数（`flash`、`flashR`、`flashSize`、`flashTau`、`flashLife`、两条随寿命曲线）和入点 `cutIn`，不另加开关（方案第 4 节第 4 条按推荐）。
- **类别**：导出（设了入点 / 单束 / 光点的礼花多一个发射器；纯星头 PC 选 CPU 粒子）+ 界面（可选值）；已有条目打开后参数逐键不变。

## 2026-10-14 · 烘焙器 4.9.89（导出（23））：没有新参数——三处可选值收窄、一处控件换型、一处旧值改写

- **用户原话**（10-14 13:12）：「Comet 的『出入点』我也没法选，切换各种『帧数分配』格式也基本不生效，导出模块到底还有多少漏接的 bug？」；（14:14）「按第 3 节执行顺序从 4.9.88 做起；第 4 节要我定的按推荐默认处理」。
- **改了什么**：
  - `frameBudget`（帧数）：合成一张（尾缀 / 彗星）只能选 `motion` / `fixed`；以前另四种（lean / count / tiers / full）在合成一张上一直按 `motion` 烘。存成那四种的合成一张打开时改写成 `motion`（提示一条），导出逐帧不变。空中花型不变。
  - `rtGrid`（尾缀格子）：控件从 0–3 滑杆换成下拉，值不变（0 自动、−1 按列 × 行、1 / 2 / 3 = 16×1 / 8×2 / 4×4）；以前滑杆表示不了 −1。
  - `holdTicks`（每帧停几 tick）含义不变；合成一张 + 手动格子时以前放不下就悄悄加大，现在先加行（最多 × 4）。没设（0 = 自动）时逐帧不变。
  - 多层层页头的 `L.out.pc / mobile`：尾缀层只认 `seq`（按尾缀自己的产物）/ `off`，存的别的值按 `seq`；尾缀 P 里 `outMobile = off` 多层照它。`outPC = dots` 在星头不发光的层不给选。
  - `cutIn / cutOut` 对纯星头（只有星头的尾缀层）起作用了（以前不读）。
- **类别**：界面（可选值、控件）+ 导出（只在设了以后变）；已有条目打开后的参数逐键不变（合成一张存了旧帧数模式的除外：改写成 motion，导出不变）。

- **用户原话**（10-14 10:29）：「它给我做的仙女棒与尾焰，直接把我的参数系统给换了，你能帮我检查一下……且修复与统一参数系统界面吗？」

## 2026-10-14 · 烘焙器 4.9.86（对话框23）：没有新参数、不改含义——镜头成像的适用范围、合成一张时的显隐 / 变灰、分层火星模板默认值

- **用户原话**（10-14 10:29）：「我发现GPT做的很多效果有bug，有些效果加了我好像调了也没什么用，以及它给我做的仙女棒与尾焰，直接把我的参数系统给换了，你能帮我检查一下它昨晚上传的内容并且找到bug，且修复与统一参数系统界面吗？」

## 2026-10-13 · 烘焙器 4.9.81（对话框23）：「面片取景」`zoom` 加一个值 `anchor`（带锚点的 Zoom）

- **用户原话**（10-13 21:36）：「同意增加带锚点的Zoom」——回 20:00 的提问（「为什么gpt新做的FC6O我选了zoom没生效？comet这种取景也不够满」），我提的做法：缩放中心放在爆点（花）或发射点（尾缀），按每个时刻的实际范围放大，作为面片取景的新选项、不改现在的 Zoom。
- **改了什么**：没有新键。`zoom` 原来 `off`（固定）/ `on`（随开花放大，绕爆点画圆、爆点在面片中心），加 `anchor`：
  - 空中花型（大面片 / 分段）= 「随开花放大 · 锚在爆点」：面片最大尺寸和固定取景一样（横向以爆点对称、竖向按内容偏，Pivot Offset 把爆点放在粒子位置），每个时刻的大小按内容相对爆点的左右 / 上 / 下范围取最紧的那个，Size By Life 阶梯（最多 12 级，换帧同一刻换大小）绕爆点放大；收紧（实测包围盒）、碰边放大都绕爆点。
  - 合成一张（升空尾缀 / 彗星，产物表选了合成一张才出现）= 「随内容放大 · 锚在发射点」：每帧低分辨率量内容相对发射点（跟着面片上移 vz 一起走）的范围，面片形状 = 各方向最大值，每帧大小 ≥ 0.1；导出 Initial Location Z = 0 + Pivot Offset + Size By Life。
  - `off` / `on` 输出逐项不变（13 个效果的取景计划和 4.9.80 相同）。
- **类别**：导出（取景；选了才变）。

## 2026-10-13 · 烘焙器 4.9.80（对话框23）：多层的手机格加「自动（按手游规范）」，没手动选过 = 自动

- **用户原话**（10-13 20:00）：「最近导出功能的Bug有点多，可以排查一遍还有哪些我没提到的Bug吗？」——排查 ①：多层烟花缺省一律被导出拦截拦下（手机格缺省每层「序列」，同一时刻两张大序列，规范 v1 §6 只许 1 张）。回复里写了改法、用户可以否。
- **改了什么**：层的 `L.out.mobile` 多一个值「自动」（存档里不写 = 自动；手动选的写 `mobile` + `mobileManual: true`）。自动 = 按层号先后，和前面已出手机的层同一时刻都有大序列、或手机发射器会超过 3 个 → 这一层手机不出；不冲突出序列。只管大面片母版层。旧存档里 `{pc: 'dots', mobile: 'seq'}` 这种（以前改 PC 格顺手写的 seq）当自动；`unit` / `frame` / `off` 照旧当手动。产物表 / 层页头改一格只写那一格。
- **类别**：导出（只影响多层效果的手机配置；PC 不变；以前缺省导不出来的现在能导出）。

## 2026-10-10 · 烘焙器 4.9.59（对话框相机渲染）：`sparkShape` / `sparkShapeIrr` / `sparkShapeSpin` / `sparkBrightJit` 适用范围放大 + 渐变亮核 bug

- **用户原话**（10-10 01:37）：「我看了下,为什么这个效果没有单束导出功能，这些不都是通用的吗？以及你上面修改过的两轮，后面别的效果也能通用吗？走查一遍看看有没有遗漏」。
- **改了什么**：含义、范围、缺省都不变，没有新键。适用范围从「空中花型的 GPU 火花」放大到「GPU 火花 + 地面花型 / 上升循环的火花」；面板显示条件跟着放大（序列 × 地面 / GPU 内核 / 上升循环）。CPU 火花（物理尾缀、升空尾缀 RT6、旧 CPU 内核）仍不显示、仍是圆。另修 4.9.57 bug：渐变亮核（`coreProfile` = 1）时开「火花亮度随机」亮核被画成实心圆盘。
