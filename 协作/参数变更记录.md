## 2026-10-09 · 烘焙器（对话框FanGold，版本号合并时定）：火花发射器补全——起始半径 / 跟星头、向后喷 + 锥角、每米生成、扇面筒距、星头单独光晕

- **用户原话**（10-09 20:44）：「我们现在的烘培器，火花是从什么地方播放出来的？是星头吗？星头如果变大，那火花离星头近的位置为什么不会跟着变大？火花会有一个发射器概念吗？……如果按照niagara的概念，应该就是星头就是作为发射器，发射器越大，火花出生范围也会更大，也就会变得更粗，请你帮我看看还有没有类似的问题没有发现或者忽略的」；（21:48）「同类没发现的问题与你建议我补的我都要，FC6可以暂时不用改」——批。
- **理由**：`analysis/原理/火花发射审查_2026-10-09.md` 9 条。主火花出生在星心一个点、初速各向同性、按每秒生成；星头实心圆盘、光晕和火花共用；扇面 N 簇没有筒距。宪章第 1 条第 5 款「每个发射器同一套模块」里火花的「形状」模块是空的。
- **加什么**（全部缺省 = 现在的行为，逐像素不变）：
  1. 火花 › 形状：`sparkSpawnR` 起始半径（m，0–30，缺省 0：星心一点；> 0 = 在以星心为中心、这个半径的球里均匀出生）；`sparkSpawnHead` 跟星头大小（×，0–3，缺省 0；1 = 再加上星头半径，跟「星头大小随机」「星头大小随寿命」）。和自定义发射器的「起始半径」同一个意思（问题 1、2）。
  2. 火花 › 初速：`sparkJet` 向后喷速度（m/s，0–200，缺省 0：没有）——火花相对星往运动反方向喷出的速度；`sparkJetCone` 喷射锥角（°，0–90，缺省 0：正后方），喷射方向在正后方这个半角的锥里随机。和升空尾缀的 rtJet / rtCone 同一个意思。原来的速度随机（线条宽度）照旧叠加（问题 3）。
  3. 火花 › 生成：`sparkRateBy` 生成方式（选项：每秒（缺省）/ 每米）；`sparkPerM` 每米生成（个 / m，0–100，缺省 5），只在「每米」时出现、起作用，这时「生成率」「末段火花密度」不起作用（灰字写原因）。每米 = 星每走 1 m 出这么多颗，星快的地方不再稀（问题 6）。
  4. 星 › 形状：`clusterGap` 扇面筒距（m，0–20，缺省 0），只在「簇的排法 = 扇面 N 簇」时出现：第 k 簇的出发点在 x =（k − (N − 1)/2）× 筒距（问题 8）。
  5. 星 › 大小（或星头光晕）：`headHaloFrac` 星头光晕占比、`headHaloR` 星头光晕半径（缺省「跟这一层」= 现在：星头、火花共用「光点与曝光」的光晕），设了以后只管星头，火花仍用层的（问题 4、5）。等相机渲染释放光点核文件后做。
- **不改含义**：已有参数含义都不变。问题 7（亮肩按年龄、收尖按离星头距离）不加参数：取景估算补上收尖 / 新参数，面板说明写清各自的口径。
- **类别**：1–4 物理量（只影响烘焙出的贴图）；5 引擎字段（烘进贴图，同 haloFrac）。

## 2026-10-09 · 烘焙器 4.9.53（对话框相机渲染）：加「光晕形状」`haloShape`、「光晕幂律指数」`haloBeta`

- **用户原话**（10-09 18:29）：「为什么你总是强调我看不清你就不把渲染系统做好呢？至少我目前看的预览就完全脱离我想要的效果，在引擎回放也跟预览一样，那我就看不到引擎回放应有的效果；先改正红，然后尾缀是炭金，然后按顺序测试」。「按顺序」指 17:50 诊断方案 P0 → P4 的顺序，P2 就是这一条（方案里写了「先写参数变更记录、你批」，用户这句当作批了，回复里说明）。
- **理由**：实拍星头（64 颗）径向剖面是幂律尾巴（Moffat β 1.8–3.4），烘焙器光点只有「亮核 + 高斯光晕」，高斯尾巴掉得太快，想要光晕看得见就只能把 σ 拉大，结果是一团雾（FC7R）。证据 `analysis/probe/星头光晕诊断_2026-10-09/诊断.md`。
- **加了什么**：`haloShape` 光晕形状（选项：0 高斯（兼容）/ 1 幂律（像真实镜头的点扩散）），缺省 0；`haloBeta` 光晕幂律指数（1.2–6，缺省 2.2，越小尾巴越长），`haloShape` = 1 才出现。放在「光点与曝光」里 `haloR` 后面。
- **含义**：`haloFrac`、`haloR` 含义不变（能量占比；光晕宽度 α = 半径倍数 × 亮核半径）。幂律光晕 = (β − 1) / (π α²) · (1 + r² / α²)^−β，总光量和高斯一样（= 亮核 × 占比 / (1 − 占比)），画到 6α（高斯是 4σ）。
- **类别**：引擎字段（和同一节的 `haloFrac` / `haloR` 一样，发射器表「输出 › 曝光光晕」；会烘进贴图，改了要重烘）。缺省 0 用原来的着色器程序：所有现有效果、导出逐像素不变（基准回归 7 个逐像素相同，`analysis/probe/基准回归_4.9.53/`）。在 FC8R 上试了，不比高斯好，FC8R 没用上。

## 2026-10-07 · 烘焙器 4.9.30（对话框新花型）：加「效果 › 整体调整 › 节奏」1 个参数

- **用户原话**（12:58）：「……有些预设你做出来的我想要一个整体快一些的，我要调好多参数……我总得目的是为了更方便得调整节奏，从而让帧率更可控，我可以更便捷得处理某些效果得节奏快慢」；方案 `协作/方案_节奏_2026-10-07.md` 第 6 节问了 4 条，13:31 回：「1.加；2.推荐用游戏紧凑做默认；3.先看样包；4.OK，按你说的测试；5.现在这个节奏就是我测试进游戏的功能，不能等之后做」。
- **加了什么**：`tempo` 节奏（×，0.3–3，缺省 1 = 原样；> 1 快、< 1 慢），在「效果 › 整体调整」第一行，空中花型才有。下面一行是只读的结果行（`info:tempoInfo`）：整段几秒、这一层几帧几张、平均几 fps，可以直接填「整段想要几秒」，还能试算几档节奏。
  - **含义**：同一朵花放快 / 放慢，大小、形状、颜色、亮度不变。一起换算：时刻、时长 ÷k（燃烧、点火延迟、第二段、火花寿命 / 起止、余烬、子花、辉星 / 爆裂 / 分叉的时间、入点 / 出点 / 淡出段、开花段时长、自定义发射器的时刻 / 寿命），速度 ×k（初速、风、湍流、火花散布、子花 / 爆裂 / 分叉 / 摆动速度），每秒的量 ×k（点灭 / 闪烁 / 摆动频率、火花生成率、线性阻力、转速），重力 ×k²（星、火花、子星、自定义发射器），方向乱飘 ×√k；变色时刻和过渡宽度 ÷k。不变的：终端速度（模拟里是阻力系数 G / vt²，按米算）、按寿命 / 燃烧比例写的量（冷却、淡出比例、点灭开始、各种「× 寿命」）、星数、大小、亮度、曝光、帧率设置。
  - **整个效果一个值**：多层时改任何一层，所有空中层一起换算，层的开始时间也跟着（从最早的那一层算起 ÷k，升空等别的层不动）。同一批星不会错开、接力还接得上。
  - **怎么生效**：和「号数」一样直接改写存的参数（面板上看到的就是实际的数，进 Ctrl+Z 一步），`tempo` 记现在是原样的几倍；改回 1（或双击恢复默认）就换算回原样。模拟 / 烘焙 / 导出代码不动，节奏变了照常重烘，帧按新的整段重新排——所以快了同样的贴图帧率就高、慢了就低。
  - **号数跟着节奏**：已经设了节奏再选号数，号数从花型默认值改写的那几个时间 / 速度按当前节奏换算。
  - **号数带默认节奏「游戏紧凑」（改「号数」的含义，用户 13:31「2.推荐用游戏紧凑做默认」）**：单层右栏选号数时，整段比目标长就把节奏加快到目标（只快不慢）；目标 = 1.4 × 号数表这一号的燃烧 × 花型系数（柳 / 冠 1.6、椰子 / 落叶 1.5、变色 / 千轮 1.3、时差 1.25、点灭 / 分裂 1.2、辉星 1.15，其它 1）。要号数表写实就把节奏改回 1。多层、AI 条目、模板不走这一步。
  - 和多层原来的「时间倍率」（层的位置与时间里，`L.rate`）不同：时间倍率只是播放快慢（贴图不重烘、帧不重排、开始时间不跟着），节奏是重烘重排。时间倍率不动。
- **类别**：物理量（×）。参数宪章第 3 条例外 3：AI 可以用它出「节奏变体」素材（用户 13:31 同意先出快版样包），不拿它拟合参考视频。
- 不改模拟 / 渲染 / 烘焙 / 导出 / 默认值 / OUTPUT_VER；缺省 1 的效果逐位不变（存档里没有这个键 = 1）。名称表 / 发射器表 +2 行（`analysis/scripts/加参数_节奏.py`）。
