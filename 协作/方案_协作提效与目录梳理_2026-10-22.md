## 2. 方案（从省事、低风险到费事排）

### 2.1 证据分三级、过程文件会到期（回应「截图用一次就不要」）

| 级 | 是什么 | 放哪 | 留多久 |
|---|---|---|---|
| ① 交付证据 | `看法.md` + 1–3 张关键对比图 + 小的数据 json | `analysis/results/<目录>/`，进 Git | 永久（被取代后进 `归档/`） |
| ② 过程证据 | 原始截图、读回原始 json、日志、中间渲染 | `analysis/local/<日期>_<对话框>_<任务>/`，不进 Git | 默认 14 天；你验收通过后可以立刻删 |
| ③ 临时文件 | 探针、冒烟、调试图 | 系统 TEMP 或 `analysis/local/_tmp/` | 任务结束就删 |

- 加一个脚本 `analysis/scripts/本机清理.py`：列出超期的 `analysis/local`、`outputs/`、TEMP 残留、没清的副本；默认只列，加 `--apply` 才删。
- 合入门禁加一条提醒：一次提交新增超过 20 张图、或单个文件超过 20 MB，要在提交说明里写理由（不是硬拦）。

### 2.2 记录收束：一件事只写一处

| 记录 | 现在 | 建议 |
|---|---|---|
| `对话记录/<对话框>.md` | 用户原话 + 勾选 | **唯一必写**：做了什么的明细都在这 |
| `协作/状态清单.json` | 状态 + 大段说明 + 共享文件认领 | 只在状态变了时写，一句话；长说明放 `看法.md`；「完成并释放」的认领 3 天后自动挪归档 |
| `交接.md` §5 | 每段工作追加一大段，615 KB | 只在**收工 / 换人**时写一条（3–5 行，指向对话记录）；保留最近 7 天，更早的按月挪 `归档/交接_日志_2026-10.md`（脚本滚动） |
| `更新记录.md` | 待验收 + 需要你做的 | 不变 |
| 看板 6 个文件 | 各对话框也往待同步里写 | 只由总管（21）从状态清单和对话记录汇总；别的对话框不写（CLAUDE.md 已写「别的对话框不用改它」，但实际都在写） |
| 方案文档（如 编排B11.md） | 和对话记录重复写结论 | 只写方案本身和复现命令；过程留在对话记录 |

结果：一次小改动写 对话记录（必写）+ 状态清单（状态变才写）+ 看法.md（有交付才写），最多 3 处。

### 2.3 开工包：只读一页

- 把现在的 `待处理.py` 扩成 `开工包.py --对话框 22`：输出一页——自己的状态条和下一步、等我的事、冻结 / 认领、最近 3 条和我有关的交接、上次没勾完的步骤。
- CLAUDE.md 第 0 节改成「跑开工包 + 读自己的对话记录未完事项」，不再要求完整读交接和状态清单。

### 2.4 目录：旧的不大搬，新的按规则放，一页目录索引

**不挪**（被脚本引用太多，挪了会断）：`协作/状态清单.json`（21 个脚本引用）、`协作/标准.md`（12 个）、`协作/派活队列.json`、看板文件、`analysis/results/`（188 个脚本引用）、`tool/`、`spec/`、`FXtools/`。

**从今天起新文件按这个放**（旧文件原地不动，只在目录页分类列出）：

```
协作/
  规则/      标准、宪章、参数变更记录          （旧的先不搬）
  方案/      方案_*、研究_*、计划_*、复盘_*    文件名 <主题>_<YYYY-MM-DD>.md
  提示词/    给本机 / 夜班 / 其他 AI 的提示词
  编排/      编排B12 起的说明、复核            （编排B01–B11 原地）
analysis/results/<YYYYMMDD>_<主题>/   新结果目录统一这个名字（导出任务回执 NFE-* 照旧）
analysis/local/<YYYYMMDD>_<对话框>_<任务>/   过程证据，见 2.1
```

- `仓库梳理.md`（现在 35 KB、大段文字）重写成**一屏目录**：每个顶层目录一行「放什么 / 谁维护 / 去哪找」，细节链出去。
- 根目录：`design-qa.md` → `docs/`；`research/`、`samples/` 并进 `docs/` 或 `spec/`；`outputs/` 是别的 AI 的本机备份（10-17 GlitterChry 对比、画质五图、金曜菊B 试配），问过负责人后删或挪 `analysis/local/`；`TClaude.bat`、`local_notes_ue_interface.md`、`点灭星_Cascade参数.txt` 没进 Git，像是你自己的文件，不动。
- 结果目录：被取代版本按现有规则挪 `归档/results/`（规则早就有，没执行）；导出任务回执每个效果只留当前版和用户通过版。

### 2.5 Git 瘦身

- **马上可做、安全**：`git gc` 把 5.9 GB 散对象压缩、清掉 0.6 GB 碎片，不丢提交，`.git` 估计降到 4 GB 左右（推断）。
- **发布流程**（要工作台负责人同意）：
  - 离线包 zip 不进 Git，「更新离线工作台」在本机从 HTML 打包；
  - `FXtools/节目/云端最新/` 不再存每版 dfshow 副本（Git 历史里本来就有）；
  - 编排不再把整首音乐嵌进 dfshow / cloud-latest（发布时去掉 `--keep-music`，离线页用同目录 `music.wav`）。
  - 估计每发一版进 Git 的量减少一半左右（推断）。
- **不建议**：改写 Git 历史删旧大文件——要 force push（CLAUDE.md 禁止），所有副本都要重新克隆。

### 2.6 副本规则（上一轮的结论）

- 能不开副本就不开：你工作树有没提交的东西时，只提交自己的文件就行（CLAUDE.md 第 5 节已有）。
- 必须开时用 `git worktree add`，放在固定目录 `F:/FWL-副本/<日期>-<对话框>-<任务>/`，配合只检出需要的目录；开前在状态清单「共享文件」登记路径，推送后 `git worktree remove` 并删登记。

### 2.7 自动守门

`同步体检.py` 加几项提醒：超期的 `analysis/local`、没删的副本、`.git` 散对象超过 2 GB、根目录出现新的散文件、新结果目录名字不合规则。只提醒，不拦。

## 4. 要你定的（都给了推荐）

1. **过程证据留多久**：推荐 14 天，你验收后可以提前删；交付只留 看法.md + 1–3 张关键图进 Git。

6. **阶段 3**：要不要请工作台负责人改发布流程。
