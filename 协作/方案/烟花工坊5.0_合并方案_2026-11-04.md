## 3. 总体做法：一个文件，三个工作区

- **一个文件** `tool/烟花工坊.html`，里面装三块：
  - **制作**：原烘焙器。
  - **导入**：原导入器的烟花部分。
  - **编排**：原编排工作台。
- **三块各放一个页内窗格**：每块都在同一文件里的独立窗格中运行（iframe srcdoc），样式和全局变量互不干扰。
  - 浏览器存储共用：我的效果、节目草稿、导入记录、选过的文件夹。
  - 三块代码不合并成一套。
  - 推断：file 方式打开时，窗格之间能共用存储和文件夹授权，阶段 0 要先验证。不行就退一步，改成同一文档里各自隔离。
- **顶栏一条**：
  - 「烟花工坊 · FireWorksLab 5.0.x」。
  - UE 连接状态：打开就自动连，断了自动重试。
  - 导出文件夹、备份文件夹。
  - 「制作 / 导入 / 编排」三个工作区切换。
  - 三个工具原来各自的产品名和版本标题，在合并版里藏起来。
- **构建**：
  - 仓库里加一个合成脚本，读三份已构建的成品（`FireworkBaker.html`、`烟花编排工作台.html`、导入器成品），拼成一个文件。
  - 合成这一步不需要 npm。编排界面改了以后，仍按原流程构建编排成品。
  - `FireworkBaker.html` 照常生成，仓库里 132 个检查脚本按这个文件名找烘焙器，不受影响。
- **体积**：去掉编排内嵌的音乐（改成用时选音乐文件），约 7–8 MB（推断）。
- **浏览器**：只支持 Chrome / Edge。用别的浏览器打开时，提示「请用 Chrome / Edge」。
- **版本号**：
  - 对外只写 FireWorksLab 5.0.x。
  - 烘焙器的 4.9.x、编排的 16.0.x、导入器的 v2.x 退为内部号，在「关于」里可见。
  - CLAUDE.md 第 10 节「编排每推一次版本号末位 +1」的规则要相应改写，改写稿交用户批。

## 4. 不用本地服务器，怎么导出、导入、备份

### 4.1 导出

- 第一次导出时弹窗选「导出文件夹」（浏览器授权），之后记住。每次重开浏览器，要点一下「允许」。
- 原来由 8034 写的东西改在网页里直接写，格式不变：
  - 版本目录。
  - 索引 `df.firework-resource/1`。
  - 缩略图。
  - 导入回执。
- `fwl.cascade/1`、命名、版本规则都不变。ZIP 照旧保留，作为备选。

### 4.2 导入：把贴图交给 UE

浏览器不告诉网页文件夹的完整路径，而 UE 要从磁盘读贴图。

- **首选：经 UE 传文件，使用者不用填路径。**
  - 网页把这次要导入的文件分块发给 UE。
  - UE 里的 Python 先把文件写到系统临时目录（不在 UE 工程里）。
  - 导入完成后删除临时文件。
- **退路：填一次路径。** 阶段 0 测出 GPUECli 传不动时，改成「选导出文件夹 + 填一次它的完整路径」。网页写一个暗号文件，让 UE 核对两边是同一个文件夹。

### 4.3 预检

- 用烘焙器导出拦截同一套规则（`63_gate.js`）在网页里跑。
- sha256 用浏览器自带的计算。
- 共享贴图登记写在导出文件夹里一个 JSON 文件中。
- 去掉 `python.exe` 和 `delivery-preflight.py` 两处依赖。

### 4.4 备份

- **何时弹窗**：要覆盖 UE 里已有的资产前，第一次弹窗让使用者选「备份存放位置」，之后记住。弹窗写明「不要选 UE 工程里面的目录」。
- **怎么备份**：
  - UE 里的 Python 读出原 uasset，传回网页。
  - 网页把它写进所选文件夹，并核对哈希。
  - 文件存成 `.uasset.bak`：即使误选到工程目录里，UE 也不会把它当成资产读进来。
- **怎么恢复**：沿用导入器原有的「原始 / 更新前」两份备份做法，导入页能从备份里还原。

### 4.5 连 UE

- 打开就自动连 `127.0.0.1:17780`，断了自动重试，顶栏显示连接状态。
- 没有 UE 时，制作、导出、编排照常可用；导入变灰，并写明原因。
- 新版 Chrome 第一次连接时，可能会问一次「允许访问本机设备」。这一点未实测，放在阶段 0 测。
- 同一时间只允许一处写 UE。导入正在写入时，编排里会写 UE 的按钮（导演表、灯光、UE 里预览）先变灰。

## 6. 放进编排：基础模板播放真实效果

### 6.1 流程

1. **勾选入口**：烘焙器的「保存」和「导出」两处，各加一个勾选「同时放进编排（基础模板）」。
2. **生成编排预览包**：勾上以后，烘焙器按「合成一张」同一套逐 tick 合成，把所有层、开花闪光和粒子都算进去，按引擎回放生成一份**编排预览包**，内容有：
   - 黑底帧图集，例如 15 fps、单帧 256–384 px、WebP 格式。帧率和单帧大小由执行对话框按清晰度和体积试定。
   - 时长。
   - 真实尺寸：每像素多少米，按「游戏内大小」那台固定相机换算。
   - 开花点位置。
   - 来源效果和版本指纹。
3. **进入基础模板**：预览包存在浏览器里，和编排共用。编排模板库的「基础模板」立刻出现或更新这一项，播放的是真实效果，不再是简笔画。
4. **绑定 ResourceFX 行名**：
   - 基础模板按 ResourceFX 行名登记。
   - 还没配表的效果，先用英文名占位，标「未进 UE」。导入并配表以后，再绑定正式行名。
   - 现有规则不变：编排导出导演表、在 UE 里预览，仍然要求已配表。
5. **效果改动后更新**：效果改了再保存，基础模板会标「有新版本」，点一下就更新。花型模板和编排模板按 ID 引用基础模板、不复制，所以自动用上新版本。

### 6.2 花型模板、编排模板（5.0 内）

- 预览花型模板（子模板库）和编排模板时，按每一发的位置、角度和时间，把对应基础模板的预览包叠上去。
- 叠加方式是相加混合，黑底不会遮挡。

### 6.3 片段与整场同屏播放（5.0 之后）

- 片段时间轴和整场按时间同屏播放，放到 5.0 之后做。
- 有了预览包以后，这部分比之前估的小：不用在浏览器里重新模拟 Cascade，主要难点在两处：
  - 同时播几十种效果时的内存。
  - 和音乐同步。

### 6.4 边界

- 预览包是浏览器里的近似效果：没有 UE 的 Bloom 和排序，倾角下也不是真实透视。验收仍以 UE 为准。
- 预览包占浏览器空间，推断每个效果约 1–5 MB。
  - 它跟着「我的效果 → 导出全部」一起备份。
  - `.dfshow` 只存引用。
