# PC 3.0 烟花：提亮、爆发、颜色 / 大小随机方案 v2（2026-10-23，LiteHDR，待用户批）

数据（只读）：`analysis/results/20261022_LiteHDR_手游分档/PC随机现状.json`（逐发射器大小 / 颜色现状）、`analysis/local/20261022_LiteHDR_批量修正/pc_brightness.json`（总倍增）、`pc_mi.json`（材质实例参数）。

## 用户约束（不变，10-23 汇总）

- 随机只在颜色和大小上，幅度 ±5%，不扩到别的参数。
- 只有单层的做大小随机；有多层衔接的不做大小，只做轻微颜色随机（用户选 ±5%）。
- 导演层的整朵缩放随机归编排（22）。
- 扇形、尾缀：PC 可以加颜色随机（短彗星、短银尾算扇形单束 / 尾缀，加颜色、不加大小）；小彗星没用在编排里，不加。
- 手游：扇形、尾缀去掉颜色随机，改成亮度随机；其余手游效果保留颜色随机。
- **提亮、爆发都只在粒子里做，不改材质。**

## 关键误区和遗漏（我的判断，依据写在后面）

1. **不能只看倍增数字判断「没体量」**。贴图、Ramp、材质 EmissiveIntensity 都会影响亮度。数字只用来找嫌疑：你调过的主体层总倍增在 25–750，没调过的停在 5–15，中间是断开的。所以我推断 ≤ 15 的是导入默认值、没调过，但最后要在 PC 编辑器里量亮度，不按数字定。
2. **PC 的「体量」很大程度取决于 Bloom 和曝光**。游戏里 PC 的 Bloom 开没开、强度多少还没定（更新记录里挂着）。Bloom 关着的话，倍增调高只会让芯变白，不会多出光晕。验收应该在正式夜景（Dam_Iris_Long3 Night）里看，不用白天的 FXLookDevLevel。
3. **爆发不要和已有的闪光层叠加**。小银菊、短爆裂、银冠菊、爆裂星、两个银彩菊、银白菊、窜天猴爆炸本来就有 Flash / Initial Ignition 层，这就是爆开那一下的亮。再给主体加冲高容易过曝，这些先只评估、不加。
4. **「多点变化」我推断有两层意思**：一是爆开时亮度随时间先冲高再回落（爆发曲线，固定，不随机）；二是每发之间不一样（±5% 颜色 / 亮度随机已经覆盖）。除此之外不加别的随机。
5. **金垂柳马上要换 v3**，这轮提亮、爆发、随机都先不做，合入新版后再一起处理，免得白做（见 `协作/方案/金垂柳v3合入位置_2026-10-23.md`）。
6. `_H` 照 PC：PC 改完把 ColorScale（含爆发曲线）和 alpha 同步到 `_H`。`_M` 保持 LiteHDR 值，爆发默认不加（LiteHDR 下颜色冲高会发白；alpha 已经 ×4–×8，核心饱和，冲不出来）。

## 一、提亮（粒子 ColorScaleOverLife，不碰材质）

嫌疑清单（主体序列层，总倍增 = ColorOverLife × ColorScale × 材质 EmissiveIntensity）：

| 效果 | 层（总倍增） | 备注 |
|---|---|---|
| 爆裂星 Crackle | L1_Main 5 | 单层，有闪光层 |
| 小青柠 Lime | L2 5、L3A / L3B 7（L1 已是 100） | 多层 |
| 金锦菊 GoldRay | L1 5、L2 5 | 多层，**没有 ColorScaleOverLife**，要加这个粒子模块 |
| 金蕊柠 GoldCoreLime | L1 8、L2 9.5、L3 12（L4 已是 325） | 多层，L1 没有 ColorScaleOverLife |
| 金芒菊 GoldRayChry | MainA / MainB 9.4 | 多层 |
| 银彩菊 SilverStrobeChry / _B、银白菊 SilverWhiteChry | 主层 15（材质 EI 只有 1） | 单层 + Glow + 闪光 |
| 窜天猴爆炸 GlitterChry | L1_Main 10 | 多层 |

做法：每个嫌疑效果先在 PC 编辑器同机位、同曝光量出爆开亮度（像手游对照那样减背景求亮度 E），以你调过的同类效果为参照：单层参照小金花 100、银冠菊 50、橙辉星 25；多层参照绿牡丹 L1 150、金曜菊 50。把 ColorScale 调到亮度落进参照范围。多层的内外层按原来的比例一起提，不改层间关系。

## 二、爆发（粒子 ColorScaleOverLife 改成曲线）

- 只加在**没有闪光层**的效果最先出现的主体层上：小金花、小分裂、橙辉星、金裂星、小青柠 L1、绿牡丹 L1、金锦菊 L1、金曜菊 L1、金蕊柠 L1、金芒菊 MainA / B、多重菊 L2。
- 曲线：t = 0 时 ×2，前 0.2 s 内回落到 ×1，之后保持原值。按每层寿命换算成相对时间；倍数、时长是起点，看图再调。
- 点灭星（本身在闪）、扇形 / 尾缀不加。

## 三、随机（±5%）

| 类 | 效果 | 大小 | 颜色 |
|---|---|---|---|
| 单层 | 小金花、小银菊、短爆裂、小分裂、金裂星、银冠菊、爆裂星、橙辉星、两个银彩菊、银白菊 | 主层 ±5%（已有的统一成 ±5%，顺带修掉最小值大于最大值的） | 主层 ±5% |
| 单层 | 点灭星 | 已是 ±5% | 自带随机调色板，不动 |
| 多层 | 小青柠、绿牡丹、金锦菊、金曜菊、金蕊柠、金芒菊、多重菊、窜天猴爆炸 | 不加 | 各主体层 ±5%（闪光 / Glow / GPU 点 / 调色板层不动） |
| 多层 | 大型金芒菊 GoldRayChry_L | **现有 Main ±2.3%、L1_Main ±5% —— 按规则应去掉，待你确认** | Main ±5% |
| 扇形单束 / 尾缀 | 短彗星 Comet_Layers_S、短银尾 Silver_Layers_S | 不加 | ±5% |
| 不做 | 金垂柳（等 v3）、扇形 / 尾缀其余、小彗星、彩千轮、窜天猴非开花类 | — | — |

颜色随机做法同手游：颜色恒定的层加出生定色模块（原色 × 逐通道 U[0.95, 1.05]），停用恒定的 ColorOverLife；颜色是曲线的层先把曲线乘进 ColorScaleOverLife 再加。已知风险：同一组星拆成两层的（MainA / MainB、L3A / L3B）各自随机，相对色差最多约 10%。

## 执行顺序（最简）

1. 你切到 PC 编辑器（PC `_HD` 在手游编辑器里不显示）。
2. 量一遍嫌疑效果和参照效果的爆开亮度，出一张表给你。
3. 试点：爆裂星（单层、暗、有闪光层）、金锦菊（多层、暗、要补 ColorScaleOverLife），提亮 + 爆发 + 随机都做，你看过再铺开。
4. 铺开 → 同步 `_H` → 我拍 3 次对照、量亮度 → 你在夜景里看。
5. 每个包都是 dry → 备份 → 迁出 → 改 → 保存 → 读回；不提交 P4。

## 验收

- 读回：改动值和计划一致；只迁出计划内的包。
- 亮度：嫌疑效果爆开亮度落进参照范围（参照中位数的 0.5–2 倍）；饱和度下降不超过 25%，发白比例增加不超过 15 个百分点。
- 爆发：前 0.2 s 的亮度 ≥ 0.4T 时的 1.5 倍，且不整片发白。
- 随机：同一时刻拍 3 次，单层大小差 ≤ 10%，颜色 / 亮度差 ≤ 10%；多层大小差约 0（只受测量误差影响）。
- 最后你在 Night 编排里看。
