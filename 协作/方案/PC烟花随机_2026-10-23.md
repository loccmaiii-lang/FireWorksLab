# PC 3.0 烟花颜色 / 大小随机方案（2026-10-23，LiteHDR，待用户批）

依据：只读检查 PC ResourceFXTable「跨年烟花3.0_」46 行 → 30 个 `_HD`（去掉扇形、尾缀）逐发射器的大小 / 颜色模块（`analysis/results/20261022_LiteHDR_手游分档/PC随机现状.json`）。

用户约束（10-23）：
- 幅度 ±5%。
- **只有单层的才做大小随机**，有多层衔接的不做；导演层整朵缩放随机（导演表 `EffectScale` + `RandomScaleRatio`）归编排（22）。
- 多层的只做轻微颜色随机。
- 扇形、尾缀可以不弄。

## 做法（都是 Cascade 原生模块，出生时随机一次，不闪）

| 代号 | 适用 | 改法 |
|---|---|---|
| S | 单层主发射器大小 | Initial Size 改成 中心 × U[0.95, 1.05]，锁宽高同比例；已有范围的改成以原中心 ±5%（顺带修掉最小值大于最大值的） |
| C1 | 已有 Initial Color 且是常量 | StartColor 改成 原色 × U[0.95, 1.05] 逐通道 |
| C2 | ColorOverLife 颜色、alpha 都恒定 | 加 Initial Color（原色 × U），停用 ColorOverLife；ColorScaleOverLife 不动，结果等价（手游这轮同样做法） |
| C3 | ColorOverLife 颜色是曲线 | 先把这条曲线乘进 ColorScaleOverLife（逐关键帧乘常数，形状不变），再按 C2；没有 ColorScaleOverLife 的要多加一个模块 |
| — | 闪光 / Glow / GPU 点 / 随机调色板（Color_Seeded） | 不动（闪光短、GPU 点本来就逐颗随机、调色板本来就随机） |

## 三、不做

- 扇形：金锦冠 ×4 行（FanGold）、银星扇（FanSilver）、红彗星（Comet_Layers）。
- 尾缀：6 个 RiseTrail、窜天猴拖尾。
- 彗星 / 长条类，要你定算不算扇形 / 尾缀：短彗星 Comet_Layers_S、短银尾 Silver_Layers_S（单发射器长条，可以只做颜色 C2）；小彗星 Comet_HD（Ribbon 拖尾，建议不做）。
- 彩千轮 PrismWheels：6 个发射器本来就都是逐颗 15–50% 的随机，不动。
- 窜天猴 sku 非开花类：拖尾烟雾、点火引线、喷射焰火、二次加速，本来就是逐颗随机的粒子，不动。

## 执行与验证

- PC `_HD` 是你认可过的正式库：先只改一个单层（小金花）、一个多层（金曜菊）试点，你看过再铺开。
- 流程同手游：dry（现场结构）→ 备份 → P4 迁出 → 改 → 写一次 LOD.bEnabled + EmitterName 重建模块列表 → 保存 → 读回。
- **看效果要在 PC 编辑器里**（PC `_HD` 在手游编辑器里不渲染）；只改值、读回可以在现在的手游编辑器做。
- 手游这边已按同样规则：大小只加在单层上，多层（红彗星）只有颜色。另外：手游的红彗星、银星扇（扇形）和 6 个尾缀这轮加了 ±5% 颜色随机，没加大小。你说扇形和尾缀可以不弄，要撤的话告诉我。
