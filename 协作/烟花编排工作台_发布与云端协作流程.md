## 2. 两条工作流程

### 工具与画面

1. **8025是唯一主开发入口。** 在这里迭代画面、交互和业务功能；保留现有三栏、点位、音乐、模板固定版本和存储。不直接在共享版改出另一套设计。
2. AI完成相应回归、文件往返与界面走查；保存修改前基线、源码版本、影响范围和证据。
3. 用户确认这轮画面可用，或明确要求发布后，生成该基线对应的共享包。未确认的画面只在8025审看。共享版使用同一功能核心，只有示例数据、隐私和本机引擎适配不同。
4. 对既有Site更新，保留Site身份、公开访问范围和空白默认节目。检查私人数据未混入、固定节目文件兼容、Save没有变成下载、三档/编辑/右栏交付可用。
5. 保存源码版本→保存站点版本→发布→确认线上真实编辑。逐项记录这三个完成状态；发布失败时保留上一版URL和有效版本，不写“已更新”。
6. 给本轮发布一个可查版本号、源码提交、对应走查和变更摘要。回滚工具版本不得同时回滚用户个人节目；可能涉及文件格式兼容时先导出个人备份。

### 具体节目的云端修改

节目文件是完整工程JSON，不是三表数组的直接封装。交付时由同版本工具将固定花型版本、片段的有效发射事件和所选档位编译成EffectSubTemplates/EffectTemplates/EffectScheduleGroups；其中去重、单位转换和现场绑定核对属于导出逻辑。节目可供云端检查数据/引用/时序/三档/音乐关联和显式参数异常；要复现导出或页面交互Bug仍需同版本源码与实际页面，资源固有尺度/轨迹和外观仍需UE实测。现场只读核对的临时结果不自动保存在dfshow里。

1. 在8025先**保存节目**，再点右栏的**下载节目版本文件**，取得完整`.dfshow`。保存是浏览器草稿；下载才产生可交给另一任务的文件。
2. 当前格式为`df.workbench-project/1`，payload备份版本6。文件包括节目、段落、点位、固定花型/编排版本、三档点集和已嵌入的音乐/波形信息。已嵌入音乐通常不需要另传一次；旧文件若只引用本机内置音乐，须先重新导入原曲并下载，或另附同一原曲。
3. 向有编排需求的云端任务提供完整文件及修改目标，例如某时间范围的密度、交叠、中心外扩、两翼应答。明确哪些范围可改、哪些音乐/点位/版本需保留。先核实该任务实际能读取文件并测试；拿不到资料不能从共享示例猜资源映射。
4. 云端在副本上修改，保留节目身份、音乐起点、0起点位ID、已固定资源/模板引用及三档关系。产出**新版本完整`.dfshow` + 修改清单 + 检查结果**。仅艺术槽位提案或三张TXT表不是可还原的完整节目文件，应由本机映射后再校验。
5. 本机同步云端进度和文件后，先检查双方是否仍基于同一份节目。当前上传基线在本库协作/编排工作台资料/2026-10-10/manifest.json；公开仓库数据归档与网页发布分别记录。若本机在云端工作期间继续修改，保留两份分支副本，比较后合并；不按日期较新者直接覆盖。
6. 备份当前本机节目，再用右栏**打开节目**导入云端新版本。先校验后原子替换，错误时保持当前节目，成功可撤销。试听、分区预览、三档、模板引用、片段/段落/音乐关联及三表交付都通过后，保存为新的本机节目版本。
7. 用户对艺术节奏的确认和真实UE实播单独记录。网页检查通过不能代替UE高度、花径、轨迹、资源性能与BP/Seq实测。此流程不自动写UE。

## 3. 版本与回传基线

工具版本、节目文件版本和模板固定版本各自独立，不能共用一个“v2”。发布不等于节目同步，保存花型新版本也不得默默重绑旧节目。

每个云端任务附一个独立`handoff.json`；它是协作说明，**不替换、不扩展现有dfshow格式**。至少填写以下真实值：

| 字段 | 用途 |
| --- | --- |
| taskId、owner、status | 哪轮、谁负责、在修改/待回传/待本机验证/待用户确认 |
| programmeId、programmeVersion、programmeFile | 节目身份、输入版本和附件准确名字 |
| baseSha256、resultSha256 | 实际输入/输出文件的校验值；发回前算出结果值 |
| toolSourceCommit、fileFormat、backupVersion | 云端测试所用工具源码提交与文件格式 |
| musicSha256、musicOffsetS、pointSourceSha | 音乐与舞台来源是否相同，避免节拍和坐标错位 |
| editableRanges、keepRequirements | 允许调整范围和保留要求 |
| resultFile、changeList、verification | 新完整文件、修改说明与实际完成的检查 |
| ueVerified、userAccepted | 分别记录；没有验收必须为false |

使用文件SHA核对是第一层防覆盖。后续三方比较按稳定片段ID、段落ID、点位ID和固定模板引用进行；双方改同一对象的同一字段才需要决策。源码用Git整合，节目用结构化比较，不能拿Git文本合并大段嵌入音频JSON。

## 4. 本对话负责的交接

- 每次收到新工作，先读对话框24、状态清单、相关云端编排负责人记录和远端新提交，再记录原话和步骤。编排设计任务的实际负责人仍以状态清单为准，本对话维护工作台与收回落地。
- 每完成一个阶段，记录改了什么、基于哪个工具/节目版本、实际检查、未通过项与下一步，提交并推送记录和该轮明确授权的节目/备份/音乐文件。工程内部命名保留，账户凭据仍排除。结束前核对远端确实含本轮提交；未推上去明确报告。
- 本地接续时安全拉取/整合云端代码与进度，保留未提交工作。若云端只更新了文档，不能称“节目已同步”；节目附件还需取得、核对并导入。
- 云端结果交付位置和文件校验必须写进进度，不能只写“已完成”或本机绝对路径，让另一台机器找不到文件。
- 不宣称对话框可以在休眠时自动监听、上传或导入。每轮执行时同步已到达的结果；后台监控、私有文件服务或多设备同步要作为明确独立功能实现。
