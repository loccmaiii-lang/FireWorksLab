# 烟花编排工作台：离线使用、本机开发与云端协作

更新：2026-10-12（跨年秀（22）：新增「云端只换编排」一节、指纹按 LF 归一）；2026-10-11（新增「版本号与云端最新编排」一节）；2026-10-10 明确取消在线预览需求；以下流程替代此前“公开共享版”的工作方式。旧Site仅是历史v1，本轮未更新或删除，不能作为当前交付入口。

## 唯一源码、两个用途

| 用途 | 入口 | 使用者 |
| --- | --- | --- |
| 日常编排与发给别人 | FXtools/烟花编排工作台/烟花编排工作台.html（旧D路径保留） | 用户和接收者 |
| 开发与浏览器走查 | 127.0.0.1:8025，读取仓库tool/workbench | 本机AI；用户偶尔测试 |
| 最终离线产物走查 | 127.0.0.1:8025/release/，原字节读取tool/烟花编排工作台.html | 本机AI或云端本地浏览器 |
| 协作和版本回传 | Git中的完整源码、固定产物、显式提供的节目文件 | 本机与云端 |

三个入口都是同一业务源码。离线HTML由构建生成，禁止手工维护另一套界面。HTTP是读取方式，不是文件格式；127.0.0.1在每台机器都指向那台机器，不会访问用户的本机。云端要看最新内容，必须取得最新Git提交和需要测试的节目文件。

## 修改工具的闭环

1. 本机或云端安全同步Git，保留他人的未提交修改；只改 `tool/workbench/src` 中的正式业务源码。历史D盘开发目录停止迭代。
2. 在 `tool/workbench` 运行 `npm ci`（首次或锁文件变化时），再 `npm run dev`。本机固定8025，云端可在自己的运行环境打开本地服务；没有公开部署要求。
3. 修复后运行 `npm run release -- --no-deploy`（云端）或 `npm run release`（本机）。执行核心回归、生产编译、单文件检查、存储和节目往返检查；所有检查通过才覆盖HTML/ZIP。
4. 用 `8025/release/` 走查最终产物，补查改动涉及的操作；HTTP响应与最终HTML逐字节一致。仍需将HTTP检查、直接file打开检查、真实UE测试分开记录。
5. 按当前项目提交权限，将源码、锁文件、固定HTML、ZIP、构建清单和进度记录一并提交。不得只改源码而把旧HTML当新版交付。
6. 本机拉取后8025从同一仓库读取新源码；若依赖/配置变动，安装依赖或重启服务。运行 `FXtools/更新离线工作台.cmd`，指纹校验通过后将成品覆盖到用户原固定文件夹，不创建新版本目录。
7. 用户先保存当前节目，再刷新原离线页面；发给别人时让对方在原位置覆盖同名HTML，继续使用同一浏览器配置。旧节目和固定模板版本不随软件更新重绑或清空。

完整命令、文件职责与本机目标目录配置见 [开发与构建说明](../tool/workbench/README.md)。统一查找入口为 `F:/FireWorksLab/FXtools`，唯一源码在本仓库 `tool/workbench`。本机旧兼容目录保留为 `D:/FXTools/DFWorkbench/deliveries/烟花编排工作台/2026-10-10-v12`，目录中的v12只代表历史路径，工具内容目前v16。

## 修改具体节目的闭环

程序代码和个人节目是两类数据。Git不会读取浏览器里的草稿，上传HTML也不会自动包含用户后来编排的内容。

1. 用户在日常离线HTML中保存，再「节目 → 下载节目版本文件」，得到完整 `.dfshow`。已导入音乐随节目文件保存；未导入音乐时，不能把参考波形视为音频。
2. 将需要云端修改的节目文件交到本任务/仓库协作资料，并说明允许修改的时间范围、花型、点位、节奏和要保留的内容。工程内部命名、节目、备份、音乐已有上传授权；凭据仍排除。
3. 云端使用同版本完整源码读取并校验节目；返回新版本 `.dfshow`、修改说明和检查结果。节目身份、点位、固定模板引用、音乐关联、三档必须保持可解释。不把三表TXT冒充可恢复的节目文件。
4. 本机取得文件后，先备份当前节目，再「节目 → 打开节目」。校验成功才替换当前节目；需要时可撤销。云端修改期间本机若也编辑过，先保留双方副本再合并，不能按文件时间直接覆盖。
5. 试听、时间轴、模板引用、三档、交付结果通过后保存新版本。UE资源尺寸、轨迹、BP/Seq和最终艺术效果仍需UE现场验收。

完整节目格式为 `df.workbench-project/1`，包括节目、固定花型/编排模板版本、实际片段/事件、点位、三档、段落和音乐。三张引擎表由同版本工具编译产生，不是节目文件的全部内容。

## 版本号与「云端最新编排」（用户 2026-10-11 14:17，本机同步（8）记录）

用户原话：「以后每更新一次，就上传一个版本，譬如现在是16.0.8，新版本就是09，然后我每次拉新后，本地刷新编排工作台，就是最新的编排」

1. **一次推送一个版本**：改了编排工作台成品，或要交给用户看的编排，每推送一次，`WORKBENCH_VERSION`（`tool/workbench/src/connection.mjs`）末位 +1：16.0.8 → 16.0.9 → 16.0.10。不跳号、不复用、不回退。推送前先 fetch，按 main 上的最新号 +1；rebase 时版本号冲突就重新 +1。只改记录或文档的提交不升号。
2. **同一个号贯穿**：工作台界面、构建清单、本版编排文件名、提交说明、`更新记录.md` 标题都写这个号，比如「编排工作台 16.0.9：B01 长冈式」，用户一眼能对上。
3. **编排随版本一起发**：在 `tool/workbench` 运行 `npm run publish-show -- --programme <节目.dfshow> --name <编排名> --note "<一句说明>"`。脚本会：
   - 先用工作台自带的 preflightProject 校验节目；
   - 去掉内嵌音乐，只留 sha256（B01 从 82 MB 变成 1.4 MB）；
   - 写 `public/data/cloud-latest.json`（工作台读的就是它）；
   - 存一份历史 `FXtools/节目/云端最新/<版本>-<编排名>.dfshow`，并在同目录 `版本记录.md` 追加一行；
   - 把 `WORKBENCH_VERSION` 末位 +1。不给 `--version` 就自动 +1；同一个号已发布过会拒绝。
   - 要附对比版（比如密度 D1 / D3）就加 `--also <节目.dfshow>::<编排名>`，可以重复。对比版只存进云端最新目录、写进版本记录，刷新不会自动载入，用户在「节目 → 打开节目」里选（16.0.12 起）。

   接着照常 `npm run release`（云端加 `-- --no-deploy`），把源码、成品、`cloud-latest.json`、历史文件和记录一起提交推送。只改工具、不换编排时，手动把版本号 +1 再 release。
4. **刷新就是最新**：工作台启动时读 `./data/cloud-latest.json`（release 产物里内嵌同一份，file 页也能用）。这份编排没在这个浏览器载入过（按 programmeSha256 判断），就整场载入、写进草稿。底部常驻提示「已载入云端编排 16.0.9 · B01长冈式（329 片段 / 2166 次播放）」，底栏写「导演编排 16.0.9 · B01长冈式」。同一份只载入一次，之后自己改的刷新不会丢。
5. **不丢用户的改动**：载入前，当前节目写进原「切换前节目」恢复槽，另按版本存一份。找回：节目 → 备份与恢复 → 恢复切换前节目。音乐：草稿里已导入同一首（sha256 相同）就沿用；8025 开发页和 `/release/` 直接用仓库音乐；本机 file 页由「更新离线工作台」在 HTML 旁放一份 `music.wav`（16.0.10 起，已有同名文件不覆盖）。别人拿 ZIP 没有原曲时，按无音乐继续播，并提示在「节目」里导入。
6. **哪些入口拉取后刷新就生效**：8025 开发页直接读仓库，拉取后刷新即可。`8025/release/` 也读仓库成品，拉取后刷新即可。`FXtools/烟花编排工作台/` 下的 file 副本不在 Git 里，拉取后要运行一次「更新离线工作台」再刷新（要不要拉取时自动复制，由用户定）。

**现状**：16.0.9（2026-10-11，本机同步（8））已实现第 3–5 条，并把跨年秀（22）的 B01 长冈式（含托底扇，329 片段 / 2166 次播放）发布成第一份云端最新编排。检查：工作台核心 150 项（新增 8 项）、打包 38 项、Python 5 项通过，8025 / `/release/` / file 页实测走查 16 项通过（`analysis/results/WORKBENCH_CLOUD_1609/`）。没在 UE 里播过。跨年秀（22）之后每出一版编排（D1、D3、金垂柳主角两版……），编完 dfshow 就 `publish-show` + `release`，各占一个号。

## 云端只换编排（--data-only，2026-10-12 跨年秀（22））

用户 10-12 20:56：「之前不是说一套源码可以维护一套离线版和本机版吗？……你只要更新源码，之前的离线版和烘培器是一样的，可以先查查这个问题并且解决吗？」

**查到的两个卡点**

1. 云端会话的网络策略拦了 npm 源（`registry.npmjs.org`），`npm ci` 装不上 vite / esbuild / react / 图标库，`npm run release` 在云端跑不起来。烘焙器是 `python3 tool/build.py` 纯拼接，不要 npm，所以云端能直接出成品；工作台是 React + JSX，要打包器。
2. 成品的源码指纹按构建机磁盘上的文本算。16.0.18 在 Windows 上构建，有 7 个源文件是 CRLF、4 个混合换行，云端 LF 检出算出来对不上，`verify_artifact`、打包检查第 28 项在云端必失败；反过来云端构建的成品拿到 CRLF 工作区也会被「更新离线工作台」拒绝。

**解决**

- **指纹按 LF 归一**：`build.mjs` 写 `fingerprint: sha256-lf`；`release.py` 和打包检查按清单的方案核对，旧清单仍按原字节（或整篇 CRLF）认。本机 CRLF、云端 LF 都对得上同一份成品。
- **出新编排不用重编界面**：成品里的云端编排只是一块内嵌 JSON。在 `tool/workbench`：
  1. `node scripts/publish-show.mjs --data-only --programme <节目.dfshow> --name <编排名> --note "<一句说明>"`：和原来一样校验节目、去音乐、写 `public/data/cloud-latest.json` 和 `FXtools/节目/云端最新/` 历史；不改 `WORKBENCH_VERSION`；编排版本号 = 工具版本和上一份云端编排里较大的号末位 +1；记 `publishMode: data-only`、`appVersion`。
  2. `python3 release.py --data-only --no-deploy`：用 Git 确认界面源码自上一次成品提交后没改（只许 `cloud-latest.json` 变），核对成品和清单、源码指纹；只换成品 HTML 数据块里的 `cloud-latest`（`tool/offline-workbench/patch-data.mjs`，先确认数据块能原样重建、其余六份数据与源码一致，数据块以外字节不动）；清单更新 HTML 指纹、`cloudLatest`、指纹改 LF 方案，`dataPatches` 记一笔（前一版 HTML 指纹、成品提交、哪些源码按指纹核对、哪些只靠 Git）；跑打包检查全套、重打 ZIP，全过才覆盖。
  3. 源码（`cloud-latest.json`）、成品 HTML / 清单 / ZIP、历史 dfshow 和版本记录一起提交推送。
- **用户这边不变**：拉取后 8025 和 `/release/` 刷新即载入；file 副本照旧运行一次「更新离线工作台」再刷新。顶栏写「云端编排 16.0.19 · 编排名」，底栏「导演编排 16.0.18 · 云端 16.0.19 …」（工具本身没变，所以工具号不动）。
- **版本号不撞**：只换编排占用的号，下一次改工具必须更大。`publish-show` 普通模式也按「两者较大 +1」；手动改 `WORKBENCH_VERSION` 后完整构建时，`release.py` 发现不比只换编排用过的号新就拦下。

**仍做不到**：云端改界面源码（`src/`）还是要本机完整构建（`npm run release`），因为云端没有依赖。界面改动照旧排给本机同步（8），或由本机 AI 做。`--data-only` 发现界面源码改过会直接拒绝，不会把旧界面当新版发出去。

**首次使用**：16.0.19 = B02长冈式（182 片段 / 982 次播放；手游 149 / 135 / 119），云端只换编排发布；file 页无头浏览器实测自动载入、刷新不重复载入、PC / 手游 × 高中低计数与 B02 表一致。

## 数据与历史保护

- 离线数据库和v1草稿键保持不变，已有个人节目优先于内置测试节目。
- 覆盖工具文件不覆盖个人dfshow、音乐；失败时回滚已经替换的工具文件。
- file页面、8025开发页、8025/release/的草稿相互隔离；换入口用节目文件导入，不能称自动双向同步。
- 同一路径和浏览器有助于继续读取本机草稿，但清理浏览器数据/换浏览器后仍需独立节目备份恢复。会话撤销不是永久修改历史。
- 测试节目保留252片段、1689事件、18个花型固定版本、3个未绑定的预置编排框架。库中的三个框架不是数量上限，也不是252个片段的自动映射。
- [原节目与音乐归档](编排工作台资料/2026-10-10/README.md)保留原件；构建使用不带音频的fixture，不改归档。
