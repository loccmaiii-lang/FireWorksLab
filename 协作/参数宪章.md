## 1. 五条规矩

1. **每个参数三选一**：
   - 物理量：有单位、有范围、有物理解释；
   - 引擎字段：能指出它写到 cascade.json 的哪一项，或贴图的哪个属性；
   - 预览设置：不进导出。

   三样都不是的参数，不得存在。

   **4.9.5 起进构建**（宪章遗漏 2，用户 10-06 09:40「按推荐」）：
   - `analysis/命名/发射器表.json` 每行写「类别」和「单位」。类别是物理量、引擎字段、预览设置三选一。
   - 另有两类过渡的：「旧（待删）」是面板标「旧」、第 2 条要删的；「只读」是说明行、算出来的显示行，不是参数。
   - 物理量必须写单位：无量纲写 1，倍数写 ×，百分比写 %，下拉写「选项」。
   - 引擎字段要在参数名称表的「UE 对应」（ue）列写明写到 cascade.json 的哪一项，或贴图的哪个属性。
   - `静态核对.py` 在构建时查：没类别、类别不对、物理量没单位、引擎字段没写去处、面板标「旧」但类别不是旧（待删），都报错，构建不过。
   - 现有 510 行按 `协作/筛查/参数清单_分类结果.csv` 分好（`analysis/scripts/参数类别_4.9.5.py`）：物理量 317、引擎字段 98、预览设置 5、旧（待删）82、只读 8。新参数由 `加参数_4.6.py` 写类别和单位，默认物理量。
   - 4.9.11（用户 10-06 14:24）：空中花型 14 项改回物理量（见第 3 条后面的例外），现在物理量 331、旧（待删）68。
   - 4.9.21（用户 10-06 21:51）：加「效果 › 整体调整」6 个倍数（物理量）、删「放大的中心」（旧）；现在物理量 344、引擎字段 100、预览设置 5、旧（待删）65、只读 8。
2. **一个现象只有一种实现。** 没有「旧 / 新」「兼容」选项。底层改法变了就升版本、重导，不留分支。
3. **拟合只改数值。** 不加功能、不加倍数、不加形状旋钮。参考视频决定数值，不决定模型。
   - 例外（用户 10-06 14:24「整体调粗细，头部这些，这些都是归一化操作，我认为是可以保留的，而且很有用」）：已有的归一化整体旋钮——尾迹粗细、星头端 / 尾端收尖、最粗处位置、大小随机、亮肩、线间底光 / 底光半径、星头前段亮度 / 前段结束、泪滴形、末段寿命、余烬熄灭时刻 / 随星淡出——是正式参数，不删。它们和「大小 / 亮度随寿命」曲线并存、相乘（旋钮按尾迹长度或时间归一化，曲线按单颗粒子寿命），不算第 2 条说的「两种实现」。这条不放开以后为拟合再加旋钮。
   - 例外 2（用户 10-06 21:51「就按照之前的全局风格帮我加回去，放在效果层里，类似一个最后的全局调整」，选「每层一份」）：「效果 › 整体调整」6 个倍数（尾长、尾缀粗细、尾缀散布、星头大小、火花亮度、闪烁，4.9.21）。一个旋钮同时乘几个发射器的同一类量（尾长 = 火花 + 余烬寿命），存的原值不动、模拟前才乘，不算第 2 条的「两种实现」。只给人手调：AI 拟合、配方、模板一律保持 1，拟合要改就改原值。
4. **物理给默认值，每个值都能改（Q1）**：
   - 由别的量算出来的值（例：火花寿命、阻力 ← 粒径）用灰字显示「算出来是多少」，旁边有链条图标。
   - 你直接改了就断开联动，点链条可以接回去。
   - 参数表里写「合并到 ××」的条目都按这条执行：合并的是默认值的来源，不是拿走这个值。
5. **每个发射器同一套模块**：
   - 9 个标准模块：生成 / 形状 / 初速 / 受力 / 寿命 / 大小 / 颜色 / 亮度 / 闪烁。每个模块都能用「数值 + 随机 + 按寿命曲线（几行 时刻:值）」三种方式填。
   - 物理上没有的模块（例：小闪不受力），面板照样写出这个模块和「跟谁」或「为什么没有」：4.9.8 起在发射器末尾合成一块灰字，原因相同的合一行，不再一个个占位（用户 10-06 12:30）。
   - 颜色：一层输出只有一条颜色（灰度贴图 + Ramp + Color Over Life）。同一层里的发射器颜色跟这一层走；要不同颜色，就拆成另一层。

## 2. 冻结

- `analysis/命名/发射器表.json` 是唯一清单。面板上的每个参数都必须在里面，构建时由 `界面状态检查.py` N3 和 `静态核对.py` 校验。
- 要加、删参数，或改参数含义：先在 `协作/参数变更记录.md` 写一条（日期、理由、你的原话），你批了才能动。
- 以前写死的数改成参数，且默认值和原来逐位相同（画面不变）的，按第 1 条第 5 款算你已经批过（20:22 原话），但同样要记一条。
