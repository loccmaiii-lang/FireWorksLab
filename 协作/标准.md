# FireWorksLab 标准 v1（2026-09-30 用户同意采用；2026-10-01 按用户实测填入数值）

> 这份文件是**判断「做完没做完」的唯一依据**。凡是本文件列出的项目，都由脚本 `标准检查.py` 自动检查（第 4 节），在烘焙器左栏每个条目旁显示 ✅ / ❌。
> 没过就不能进「待我验收」，也不能说「做完了」。不再靠「用户说了才做」。
> 标准本身要改，只能由用户决定。AI 可以提出修改建议，写在文末「待定」一节。

## 1. 条目标准：每个条目都一样齐

条目包括花型库模板、正式库、迭代中的候选、单层、多层组合、尾缀。每一个都必须有下面 6 样东西，而且**由同一套代码生成，不按效果手做**：

| # | 必须有 | 说明 |
| --- | --- | --- |
| 1 | **实时模拟** | 用来调参，可以拖时间轴、慢放 |
| 2 | **引擎回放 + 游戏内大小** | 把导出的贴图按 `cascade.json` 播放：引擎 30 fps 按 tick 取帧、组合层按各自延迟叠加。**所有条目都要有「游戏内大小」显示和观察距离滑杆**（默认 1000 m，范围 800–1200 m；用户 2026-10-01 要求：这个功能好用，但以前只有部分产物有）。PC / 手机可切换。**验收只看这个画面** |
| 3 | **贴图 + 流转动画** | 每一层的整张贴图；流转动画要同时显示放大的当前格、在整张贴图上移动的格子框、帧号曲线 |
| 4 | **完整参数** | 右栏能调该条目用到的全部参数。多层条目可以切层，每层的参数都在同一页调，不跳到别的页面 |
| 5 | **导出** | 一键导出素材包（贴图、Ramp、Cutout、`cascade.json` PC + 手机）；多层效果导出**一个**包，里面每层一个发射器，写明各自的延迟 |
| 6 | **实拍对照**（有参考时） | 和实拍按「开花后同一秒」并排，可以关掉 |

- 多层效果是「一个配方里有几层」，和单层条目走**同一个查看器**。不再有单独的「组合页」代码路径。
- 条目缺哪一样，左栏直接标 ❌ 并写出缺什么。

## 2. 画质标准：可以自动量出来的及格线

所有及格线都在**导出贴图**上量，不在实时模拟上量。先用 `analysis/scripts/烘焙器探针.py` 量（格子、显示帧、放大、尺寸下限），`标准检查.py` 建好后由它统一判。

### 2.1 游戏里的观看条件（用户 2026-10-01 实测，所有数值从这里推）

- 引擎按 **30 fps** 跑。
- 最佳观察距离 **800–1200 m**。这时**四尺玉约占屏幕高的 1/3**（中景）。按 1080p 算，花径约 360 px；面片比花径大（留边、拖尾），约 380–400 px。
- 其他号数没有单独实测：没写就按「花径 = 屏幕高的 1/3」这个最严的情况算。条目里可以写 `screenFrac` 覆盖。
- 用户自己的单帧贴图用 1024，觉得足够清晰。

### 2.2 贴图规格（用户定）

| 平台 | 单格下限 | 贴图 | 说明 |
| --- | --- | --- | --- |
| PC | **512 px** | 2048×2048，大效果最多 4×4 格 × RGBA = 64 帧 / 张 | 远处看「勉强够用」，不能再小。帧不够就分段（多张贴图，`form: segments`），**不能靠缩小格子换帧数** |
| 手机 | **256 px** | 按帧数选 1024 或 2048 | 细节不多的前提下勉强能看 |
| 母版 | — | 可以另出 4096 | 引擎里用的贴图最大 2048，4K 是给用户自己压缩的高质量来源，不是交付规格 |
| 单帧 | 1024 | — | 静态部件 / 手机单帧 |

### 2.3 及格线

| 项 | 及格线 | 为什么 |
| --- | --- | --- |
| 单格 | PC ≥ 512 px，手机 ≥ 256 px | 用户定的下限 |
| 屏幕放大 | PC：面片在屏幕上的像素 ÷ 单格像素 ≤ 1（按 2.1 的条件） | 放大超过 1 就开始糊；四尺玉约 400 px 对 512 格正好不放大 |
| 能显示的帧 | 引擎 30 fps 下 ≥ 90% 的帧会被显示；任何时段帧密度不超过 30 fps | 帧很金贵（64 帧 / 张），一帧都不能浪费在引擎看不到的地方 |
| 最低帧率 | 燃烧段（从开花到 85% 时长）有效帧率 ≥ 12 fps；淡出段 ≥ 8 fps。**这两个是 AI 提议的起点**，4.0 做出样片后请用户在引擎里看了再定 | 不顿挫；达不到就加贴图张数（分段） |
| 空帧 / 暗帧 | 0 帧（首尾自动裁掉，延时写进发射器的 delay） | 帧预算只花在看得见的地方 |
| 裁切 | 格子内圈（留边以内 2 像素）的亮度占比 < 0.5% | 不被切边 |
| 相邻帧中心跳变 | ≤ 3 像素（格子像素） | 不抖 |
| 过曝 | 顶到 255 的像素 ≤ 2% | 保留层次 |
| 参数有效 | 每个尺寸参数 ≥ 该分辨率下的最小有效尺寸（探针会算） | 没有「调了没反应」的滑杆 |
| 点灭 / 闪烁 | 点灭频率 ≤ 0.4 × 该段帧率，否则改用粒子 | 不混叠 |
| 版本一致 | 导出的版本指纹 = 条目当前的完整参数 + 烘焙器版本 | 看到的就是导出的 |

- 手机版单独量，不直接复制 PC 版。RGBA 接力在手机压缩格式（ETC2 / ASTC）下可能串帧：先做 UE 实测再定手机用不用接力。
- 引擎相关的假设（自发光倍数、色调映射、BC7 串扰、曲线查找表、视角）以 UE 实测为准，记录在 `spec/UE实测.md`。没测过的，结果写「未经 UE 验证」。
- 3.7 基线（2026-10-01 探针实测，`analysis/probe/基线_3.7_2026-10-01/`）：所有大面片都是 8×8×4、单格 256 px，屏幕放大约 1.5 倍，30 fps 下只显示 38–86% 的帧；鸿巢、片贝小于 2.2–2.8 m 的光点尺寸没有区别。**全部不及格**，这是 4.0 要解决的。

## 3. 代码标准：不再缝缝补补

1. **分层，每层只做一件事**：
   - **配方**：完整参数 JSON，默认值展开后参与版本指纹。
   - **模拟核**：确定性的；同一配方永远得到同一结果；改一个参数不打乱无关的随机数。
   - **渲染核**：实时模拟、引擎回放、定帧、对照图、拟合都调用**同一个**渲染核，同一套光点、快门、曝光规则。
   - **产物**：贴图、`cascade.json`、检查报告。
   - **界面**：一个条目查看器。
2. **能力通用化**：为某个效果补的能力，必须对所有花型可用，默认关，写进参数表和说明。
   - **不许**为单个效果写特殊分支（例如「永丰专用」）。
   - **不许**只在某一类条目上有某个功能（例如只有尾缀有流转动画）。
3. **每次改底层都要**：
   - 升版本号（3.7 → 3.8 …，大改 → 4.0），在 `tool/CHANGELOG.md` 写「改了什么、哪些画面会变」；
   - 跑回归（基准条目逐像素对比 + 标准检查）；
   - 画面有变的，在更新记录里写明。
4. **已通过的东西锁版本**：正式库条目记录通过时的烘焙器版本。底层升级后，要么用兼容开关保持逐像素不变，要么明确标「需要重新验收」，交给用户决定。
5. **修 bug 先写能复现的检查**：先让检查失败，再修到通过，检查留在 `标准检查.py` 里，防止回退。

## 4. 标准检查（`analysis/scripts/标准检查.py`，待实现）

- 输入：一个条目（或全部条目）。
- 输出：`tool/data/standard.js`（烘焙器左栏读）+ 每个条目的检查报告。
- 内容：第 1 节的 6 样东西是否都有；第 2 节每条及格线的数值和 ✅ / ❌；第 3 节的回归结果（基准条目有没有变）。
- 什么时候跑：每次导出、每次改底层、每次提交前。
- 「待我验收」只收全部 ✅ 的条目。
- 脚本实现前（4.0-d 之前）：交付时按本文件逐条人工检查，在说明里列出每条的结果。
