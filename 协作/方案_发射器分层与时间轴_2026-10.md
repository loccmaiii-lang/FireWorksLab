## 1. 先回答 1–4：都不是你看错

### 1.1 菊的星像是长出来的，不是爆开的（引菊层 HN2-O）

不是眼睛的问题。这一层有三个设定叠在一起，开花后头 0.3 s 几乎看不到在动的东西：

| 设定 | 值 | 作用 |
|---|---|---|
| 星头亮度 `headBright` | **0** | 星头本身不画，只看得到火花连成的线 |
| 火花烧旺时间 `sparkRise` | **0.35 s** | 每颗火花离开星以后亮度按 `1 − e^(−年龄/0.35)` 慢慢升起（`40_gl.js:215`），刚出来的是 0 |
| 星的速度 | 初速 250、终端速度 20 | 开花后 0.3 s 星已经飞到 43 m（最终 90 m 的一半），之后很快变慢 |

算出来（同一层参数，`ln(1+k·v0·t)/k`）：

| 开花后 | 0.1 s | 0.2 s | 0.3 s | 0.5 s | 1.0 s |
|---|---|---|---|---|---|
| 星实际飞到 | 19.5 m | 32.6 m | 42.6 m | 57.2 m | 80.1 m |
| 「亮过一半」的线头到 | 0 | 0 | 12.3 m | 38.6 m | 70.6 m |
| 整条线的总光量（比不烧旺） | 13 % | 24 % | 33 % | 47 % | 67 % |

星最快的那 0.3 s 正好是线最暗的时候，等线亮起来，星已经慢下来了，所以看起来是一条线从中心慢慢「长」出去。开花闪光（柔光、0.1 s 内消失）只会让开头更像「从光里长出来」，不是主因。

- 这是 HN2 这个效果的参数（负责：对话框7），不是烘焙器 bug。`sparkRise` 是 4.2.0 给引菊颜色纯度加的，0.35 s 对这么快的开花偏长。
- 建议对话框7 用 `时刻对照.py` 在开花后 0.1 / 0.2 / 0.3 s 和实拍比：大概率要把烧旺缩到约 0.1 s，再给星头一点亮度（0.2–0.3）。已经排进它的「下一步」。
- 菊模板本身没有这个问题：初速 150、终端速度 18、星头亮度 1、不烧旺，开花后 0.1 s 已经有 12 m 的亮线，星头一直亮着，约 0.55 s 到最终半径（约 83 m）的一半，看起来是炸开的。

### 1.2 火花不是老的先灭，而是一条线上随机灭

也不是同时播放了很多。原因是两条规则叠在一起：

1. **寿命随机很宽**：火花寿命随机是对数正态。菊模板 45 % → 90 % 的火花寿命落在中值的 0.48–2.1 倍（0.26–1.15 s）。
2. **冷却按「寿命的百分比」算**：`T = T0 × (1 − 冷却 × 年龄 / 寿命)`（`20_sim.js:396`，GPU 核同式）。

结果是：一颗寿命长的老火花在 50 % 寿命时还很亮，旁边一颗寿命短的年轻火花已经灭了。亮度和「离开星多久」几乎无关，所以整条线上随机熄灭，看不出从里到外的渐变。

真实炭火花是**按实际经过的时间降温**（越老越红越暗），寿命只决定最后哪一刻灭，所以整体是「老的先暗」，边上带一点参差。

改法（会改观感，要你选）：
- (a) 颜色和亮度改按绝对年龄算，寿命只决定熄灭点，最后一小段收掉。
- (b) 寿命随机收窄，比如 ±15 %，再留一条短的长尾。
- 先出对照图给你选再定默认。

注意：UE 里 GPU 粒子的 Color Over Life 只认「寿命百分比」，所以 RT5 那 ≤800 颗 GPU 火花要靠 (b) 收窄寿命随机，才能做到老的先暗。

### 1.3 火花还没灭完就被切掉

两个原因：

1. **自动序列时长没算火花的长尾**：现在的公式是「燃烧时间 × 1.15 + 0.5」（`15_replica.js:43`），另一条结束时刻算法也没算寿命随机。
2. **序列最后 0.3 s 强制整体淡出**（`48_render40.js:60` `frameFade40`）：不管火花还剩多少，最后 0.3 s 全体一起压暗，看起来就是「切掉」。

实测：

| 层 | 序列时长 | 按中值寿命估的最后熄灭 | 算上寿命随机（约 98 %） |
|---|---|---|---|
| 菊模板 | 3.2 s | 3.05 s | 4.15 s |
| HN2-G 锦 | 7.5 s | 7.88 s | 10.69 s |
| HN2-O 引菊 | 3.4 s | 2.88 s | 3.72 s |
| JM4-40 | 4.56 s | 3.59 s | 5.22 s |

改法：
- 自动时长 = 星、火花、余烬中最晚那批的约 98 % 熄灭时刻。
- 去掉强制淡出：只有你手动把时长设短时才切，并且在时间轴上标红。
- 这会改产物，受影响的条目要重导。

### 1.4 「燃烧时间」变成「寿命」

这是我的错。10-03 你只要求英文改成 Burning Lifetime，我做 4.3 用词统一时连中文一起改成了「寿命」。

- 改回中文「燃烧时间」，英文保持 Burning Lifetime；不改产物。
- 在第 3 节的新结构里，星这个发射器的「寿命」模块里那一项就叫「燃烧时间」。其它发射器（火花、余烬）叫「寿命」，因为它们不是在「燃烧」的星。

### 根因：一个「图层」干了三件事

现在的「图层」同时是：

1. **一套模拟**：星和它所有的子级，平铺在一张表里。
2. **一个时间片**：多阶段的同一批星（比如 HN2 引菊 → 锦）拆成几层，再靠「同一批星联动 / 接力胶水」把种子、星数、初速锁在一起。
3. **一张输出贴图**：一条颜色曲线、一套帧预算、一个 Cascade 发射器。

Niagara 的层级是「系统 → 发射器 → 模块 → 渲染器」，模拟和输出分开。我们只学了模块顺序（4.3 面板是按 Niagara 模块顺序排的），没有建立发射器这一级，也没有把输出分出去。

所以方向不算错，是只做了一半，剩下那一半正好是你现在卡住的地方。

## 3. 新结构：效果 = 系统，下面是发射器树；输出单独一栏

```
效果（System）            号数、序列时长、种子、爆点 / 玉体运动、环境（风、湍流）、水面倒影
├─ 开花闪光               生成：爆点时；亮度、大小；子花开花时也可以各自闪
└─ 星 ×N（父级）          生成 / 形状 / 初速 / 受力 / 寿命（燃烧时间）/ 外观 / 行为（点灭、飘落、蜂）
   ├─ 火花（跟随父级）     生成率 + 生成窗（相对星：开始、停止、起势）/ 寿命 / 继承速度 / 受力 / 温度与冷却 / 大小 / 亮度 / 行为（辉星、松叶分叉）
   ├─ 余烬（跟随父级）     生成 = 火花 × 比例 / 寿命 / 大小 / 亮度 / 熄灭方式
   ├─ 爆裂（父级死亡时）   数量 / 延迟 / 范围 / 速度
   └─ 子花（父级到时或死亡时）= 一个完整的「星」发射器（同样的模块，可以再挂自己的火花）
输出（Render / Bake）      每个输出层：哪些发射器、哪段时间、颜色曲线、贴图规格、PC / 手机、或者「GPU 粒子 ≤ 800」
```

### 3.1 每个发射器同一套模块、同一套名字

模块栈从上到下，和 Niagara 的 Emitter / Particle Spawn / Particle Update / Render 顺序对应：

| 模块 | 字段（每个发射器都一样，没有的就不显示） |
|---|---|
| 生成 Spawn | 数量 或 生成率；生成方式：爆点时 / 跟随父级（生成窗）/ 父级死亡时 / 父级到某时刻 |
| 形状 Shape | 起始半径、图案、倾斜…（星才有） |
| 初速 Velocity | 初速、继承父级速度、速度随机、方向随机 |
| 受力 Forces | 终端速度（阻力）、重力倍率、受环境风 / 湍流影响 |
| 寿命 Lifetime | 寿命（星里叫「燃烧时间」）、寿命随机、第二段 |
| 颜色 Color | 温度、冷却（**按绝对年龄**，见 1.2）、颜色随时间 |
| 大小 Size | 大小、大小随机、随寿命变化（尾迹粗细、收尖都在这里） |
| 亮度 Brightness | 亮度、每颗亮度随机、闪烁、熄灭前闪亮、渐隐 |
| 行为 Behaviours | 点灭、辉星、分叉、飘落、蜂、烧旺……按发射器适用 |
| 输出 Render | 进哪个输出层 / GPU 粒子 / 不输出 |

搜索和说明条写全路径，比如「火花 › 寿命」，这样同名字段不会混。

### 3.2 子级怎么触发（对应 Niagara 的 Event / Spawn Rate）

| 方式 | Niagara 里对应 | 我们的例子 | 时间轴上怎么画 |
|---|---|---|---|
| 跟随父级持续生成 | Spawn Rate / Spawn Per Unit（子发射器读父级位置） | 火花、余烬 | 父级寿命带下面一条「生成窗」，两端可拖 |
| 父级死亡时 | Death Event → Event Handler | 爆裂、千轮 / 分裂的子花 | 从父级熄灭的那一片（带随机范围）画箭头到子级 |
| 父级到某时刻 | Location Event 加时间条件 | 松叶分叉、定时开的子花 | 父级寿命带上一个可拖的菱形 |
| 继承 | Inherit Velocity / Color | 继承速度、继承颜色 | 子级模块里一行「继承 xx %」 |

子级的每个字段默认「跟父级一样」（灰字，标「同星」）。改了才变成它自己的值，和 Niagara 的继承 / 覆盖一样。

| 现在的模块 | 去哪 |

## 4. 时间轴：画因果，不只画输出

Niagara 自己的时间轴很弱：只有发射器起止，看不到事件、生成窗和寿命分布。我们可以做得比它好，因为烟花的因果很固定。

```
时间 →          0     0.5    1.0    1.5    2.0    2.5    3.0    3.5 ┃ 序列 3.4 s
效果   ◆开花  ✶闪光
▾ 星 ×293       ◆━━━━━━━━━━━━━░░            燃烧时间 1.3 s ±4 %
   ├ 火花        ┣━━━━━━━━━━━━━┫▒▒▒▒▒▒▒▒▒▒▒▒░░░▌✂   生成窗 0–1.3 s，最后一颗约 3.7 s 灭（被切 0.3 s）
   ├ 余烬        ┣━━━━━━━━━━━━━┫▒▒▒▒▒▒░░
   └ 爆裂 ⚡      ·  ·  ·  · 死亡时 ↘ ◆▒▒░
输出
   A 引菊（金）  [━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━]  入点 0  出点 3.4  14 帧/页 ×2
   B 锦（白→金）            [━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━→
```

图例：
- ◆ 生成时刻
- ━ 中值寿命
- ░ 寿命随机的长尾（中值到约 98 %）
- ┣━┫ 子级生成窗（相对父级）
- ▒ 子级粒子还活着
- ✂ 序列结束把粒子切掉了（红）

操作：
- 拖父级寿命带的末端 = 改燃烧时间；按住 Alt 拖 = 改寿命随机。
- 拖生成窗两端 = 改火花开始 / 停止，吸附到父级的事件点（点火、前段结束、熄灭）。
- 拖事件菱形 = 改延迟（分叉时刻、子花开花时刻）。
- 悬停显示数值，每条轨道淡淡画一条「同时活着多少颗」的曲线（预算一眼可见）。
- 每条轨道：眼睛（独看 / 静音，只影响观察）、输出徽标（进了哪个输出层）、粒子数。
- 输出那几行单独在下面，只管入点、出点、帧预算，和上面的因果分开。现在的「拖绿点改出现时间」就是上面星轨道的 ◆。

结尾被切（1.3）在这个时间轴上一眼就看得到。自动时长按「最晚那批的约 98 %」来定。

## 5. 输出映射：一次做效果，输出另外决定

- 每个发射器的「输出」模块选进哪个输出层。默认：星 + 火花 + 余烬 → 一层，开花闪光进同一层的星头通道。
- **颜色规则自动检查**：Cascade 一个发射器只有一条 Color Over Life。同一输出层里的发射器颜色曲线不同时，提示「要拆层」，一键拆。
- **多阶段同一批星**（HN2 引菊 → 锦）：只有一个星发射器，在它的寿命上切两段时间分给两个输出层。不需要胶水，「改一处几层一起变」自然成立，因为本来就只有一处。
- **贴图 + GPU 粒子**（RT5 的思路）：火花发射器可以设「x % 烘进贴图，其余 ≤ 800 颗做 GPU 粒子」，旁边显示同屏粒子预算。
- **两条引擎限制写在界面上**（UE 4.24 Cascade）：
  - GPU 发射器不能收事件（Event Receiver 只在 CPU 发射器上能用，未在本项目实测），所以「跟随单颗星」的子级只能烘进贴图，GPU 部分只能是独立发射器近似。
  - GPU Sprite 不支持 Acceleration（10-04 实测）。

## 6. 分阶段

| 阶段 | 做什么 | 改不改产物 | 验收 |
