## 1 长冈排布逻辑，拆成能执行的 7 条

截图只给了几个瞬间，所以只取**规律**，不取时间点和高度。

| # | 长冈怎么排 | 落到我们这里 |
|---|---|---|
| R1 整排波 | 不是零星放，是整排 8–9 发（或 17 点一点一发）同一小节起一波，一波只有一种花 | 一小节一波，P0–P8 九点或 17 点（P + B）；98 / 129 个小节有波 |
| R2 三代同屏 | 上一波的尾在落、这一波在炸、下一波的尾已经在升 | 起飞时间 = 开花时刻 − 尾缀上升时间，所以下一波的尾缀在这一波开花时必然已经在升；110 个整排波全部满足 |
| R3 叠层 | 顶排大花 + 二排小花 + 低排 / 扇，同一时刻三层高低 | 顶排 M / L 在 P 点；二排 S 在 B 点，低 75 m；扇铺底。dz 每波不同，不做固定台阶 |
| R4 A / B 一点一发 | 过渡段用 17 个点（P 与 B 交错）一点一发，一波里两种花隔点交替 | `zig17`；③ 环形排 = 金曜菊与金蕊青柠星隔点交替 |
| R5 领 / 接 / 插 | 每段一个领奏种类，一个接，偶尔插；同一种不连续超过 2 波；每种花都当过一次领 | 15 种球花各领至少一整排（体检 `leadMissing` 为空）；相邻同种违规 0；墙（⑧ ⑨ 白墙）刻意连波 |
| R6 段首最大 | 进新段先是全段最大的一波，再 1–2 个余震；大段之前留一个空小节 | ② 10.0 s、⑥ 112.2 s、⑧ 175.4 s、⑨ 196.5 s 都是段内最大一波；第 41 / 65 / 96 小节没有任何爆点，尾缀在黑里升 |
| R7 强度台阶 | S → M → L 逐段加码，终章 L 墙，金 → 白 | ①–④ 以 S / M 为主；⑤ 起 L 城垛；⑥ 主角；⑧ 三主角垂柳墙；186.8–194.9 s 金墙三波；196.5 s 白墙；之后白墙每小节一波 9→9→7→7→5→5→3 逐波收窄跟音乐渐弱 |

## 4 纰漏清单（我自己找的，按风险排）

1. **没有在 UE 里放过。** 对位、同屏数、GPU 数都是我的模型；浏览器回放不是 UE 实测。导入后第一件事是看 UE 实际播放。
2. **B 点上的球花未验证（536 个事件 / 67 个条目，最早 7.5 s 起飞）。** 数据模型和编译都合法，但目前只有扇在 B 组验证过；二排小银菊整排、高潮 II 的铺低层都依赖它。若 UE 里 B 点球花起飞异常，这些要改。
3. **起爆高度比目标高。** 照原资产，实际起爆 +190 / +265 / +410 m，宪章目标 +150 / +210 / +330 m（高约 25%）；你说先用原资产，所以没缩。看着偏高要在资源侧改，编排层不动。
4. **金垂柳用了 56 个，不只是 5 个主角。** 主角 5 个（⑥ ×1、⑧ ×3、余韵 ×1，用的是未缩放的 230 m 版，不是宪章的 280 m 主角版——那个要资源侧先做），另有 51 个是终章金墙 / 城垛——L 级金色只有它。金垂柳每个 6 个 CPU 发射器，寿命 9.7 s，同屏最多 32 个（195.5 s），示意图里下垂线叠得很重，UE 里可能糊成一片金。要不要把金墙改成金垂柳 + 金曜菊混排，看你的意见。
5. **GPU 预算是暂定模型。** 由 24 的一次测试（234 干净、312 截断）推出，峰值 198 紧贴软线 200，且出现在 162.5 s——全曲最响的一小节，最怕被截断。每个资源同时在场的并发能否撑住也没测（导演不受 MaxInstanceNum 限制，不代表 UE 不卡）。
6. **扇只有 B 点、只有银 / 红。** 没有金扇子模板、P 点扇没测，所以金墙时刻没有扇铺底；P4 等中间位置的低层只能靠球花补。
7. **可能偏满。** 129 个小节里 98 个有整排波，空小节只有 41 / 65 / 96。长冈本身也密，但我们 3:30 里留白少、没有"喘一口"的长段；D1 / D3 要回答的就是这个。
8. **音乐落点没试听。** 段落入口来自小节网格 + 响度分析；112.2 s（你的 1:47）按「高潮 II 回归入口」处理；终章是不是主高潮、196.5 s 终和弦是不是白墙该来的位置，要你听。
9. **手机档是机械规则。** 中档去最外两点、低档隔点留，没有按手机画面单独设计；手机粒子 ≤ 50 由固定子模板决定，这版没有逐个核对。
10. **风格像不像只能看。** 体检只能证明「我写下的规则被遵守了」，不能证明像长冈；这是需要你用眼睛判断的部分。
11. **倒计时前 4 s 的红彗星单束**是我加的预热（B0+B7 往里），你没明确要过；不喜欢就删。
