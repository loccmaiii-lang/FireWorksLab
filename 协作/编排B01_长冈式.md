## 2b 扇形编排（10-11 14:08 新增）

**上一版为什么少**：扇都是在花开的那一刻才放（`fan_H=0` 取了开花时刻），而长冈是中大花**起飞**时底座就有扇；而且只在叠层波和少数扇组里放，176 个。这一版改成：

**① 托底扇（88 个 cue / 523 个扇，跟着 M / L 波走）**
- 每一波 M / L 球花（P 点）起飞的那一刻，B 点同时打一排扇。B_k 在 P_k 与 P_k+1 之间，取这两个 P 点里挂了最大一级球的起飞时刻，所以扇和尾缀逐点同发（对位误差 ≤ 0.1 s，网格量化）。城垛波按 L 的起飞时刻走（L 尾缀早 3 s，扇跟着最大的那一排）。
- **方向四种都有**（托底 88 组里：左→右 26、右→左 21、外→里 21、里→外 18、齐发 2）：这一波自己是定向的（左→右 / 右→左 / 外→里）扇就跟着走；这一波是从中心往外的、或没有方向的，扇的方向按「里→外、左→右、外→里、右→左」轮换，这样看起来扇和尾缀有时同向、有时对着走；主角（≤3 点的大花）扇齐发、托得最重。换了方向的扇从这一波第一支尾缀起飞的时刻开始、0.1 s 一把，最晚一把比对应尾缀晚 0.7 s。
- **束型随方向挑**：左→右用红彗星九束左扫（束内也是从左往右出），右→左用九束右扫，里→外用银星九束展开（每把中心束先、两边后）或五束窄扇，外→里和齐发用银星五束 / 十三束 / 红彗星五束。
- **力度**：这一波有大花、或所在小节响度 ≥ −8.5 dB 算重，排重束型；轻的波红 / 银隔波轮换。
- **GPU 预算逐波裁**：先给大花这一波、再给中花；每一波先试最重的束型，放不下就一级级降（银九束 → 银五束 → 银五束只放 4 把 → 红五束 → 红五束 4 把 → 2 把 → 单束），同时保证同时在场的扇束 GPU 发射器 ≤ 234。结果：红彗星 415 个、银扇 108 个（银扇每束 3 个 GPU，红彗星 1 个，所以多半是红的）。
- 空小节（41 / 65 / 96）里不放扇，只留尾缀在黑里升。托底扇是叠层（`extra`），低档不出，中档去最外两点。

**② 扇组（42 个 cue / 158 个扇，单独放在段落入口和整排之间）**——R04 的几种扇组 + 外→里：
| 扇组 | 做法 | 次数 |
|---|---|---|
| 左右追逐 | 偶数 B 点红彗星九束左→右扫，隔一拍奇数 B 点九束右→左扫，两组对着穿过中间 | 5 |
| 向心合拢（外→里） | 左翼 B0–B2 左→右扫、右翼 B5–B7 右→左扫，同时往中间收 | 3 |
| 中心涟漪（里→外） | 银星九束，点序从中心往两边，两端红彗星五束收尾 | 5 |
| 外→里合拢 | 红彗星五束，从两端 B0 B7 往中间 B3 B4 一把把点 | 4 |
| 其余 | 倒计时红彗星 / 银扇预告（5 个 cue）、第 27 小节银九束右→左、第 56 小节红九束右扫、第 61 / 64 小节收窄时的银 / 红五束、第 81 / 117 / 118 小节银十三束（预算所限只放 B3 B4 两把） | 7 + 5 |

**总数**：扇 681 个（上一版 176）、高档同屏扇束最多 234 个发射器；中档 571、低档 58。

**这一版做不到的**：没有金扇子模板（金扇不在 20 个基础资源里）；单把扇内部的「外→里」束型没有现成子模板（要做的话是用同一个 FanSilver 资源、把九束的出筒顺序倒过来的新子模板，不新增资源）；外→里目前只做到点序。

## 4 纰漏清单（我自己找的，按风险排）

1. **没有在 UE 里放过。** 对位、同屏数、GPU 数都是我的模型；浏览器回放不是 UE 实测。导入后第一件事是看 UE 实际播放。
2. **B 点上的球花未验证（536 个事件 / 67 个条目，最早 7.5 s 起飞）。** 数据模型和编译都合法，但目前只有扇在 B 组验证过；二排小银菊整排、高潮 II 的铺低层都依赖它。若 UE 里 B 点球花起飞异常，这些要改。
3. **起爆高度比目标高。** 照原资产，实际起爆 +190 / +265 / +410 m，宪章目标 +150 / +210 / +330 m（高约 25%）；你说先用原资产，所以没缩。看着偏高要在资源侧改，编排层不动。
4. **金垂柳用了 56 个，不只是 5 个主角。** 主角 5 个（⑥ ×1、⑧ ×3、余韵 ×1，用的是未缩放的 230 m 版，不是宪章的 280 m 主角版——那个要资源侧先做），另有 51 个是终章金墙 / 城垛——L 级金色只有它。金垂柳每个 6 个 CPU 发射器，寿命 9.7 s，同屏最多 32 个（195.5 s），示意图里下垂线叠得很重，UE 里可能糊成一片金。要不要把金墙改成金垂柳 + 金曜菊混排，看你的意见。
5. **GPU 预算是暂定模型。** 由 24 的一次测试（234 干净、312 截断）推出：高档同秒新起 GPU 发射器峰值 199 紧贴软线 200，同时在场的扇束 GPU 发射器峰值 234 贴着 24 实测干净的上限。托底扇是在这个模型里逐波降级排出来的，把预算用满了：高档有 13 处（49.2、58.2、61.2、109.0、114.3、121.5、128.9、154.4、162.8、167.9、172.7、182.2 s 等）贴着 190–199，中档只有 1 处 ≥ 190（109.0 s）；模型一旦偏乐观，这些地方最先被截断。模型本身没在 UE 里对过，每个资源同时在场的并发能否撑住也没测（导演不受 MaxInstanceNum 限制，不代表 UE 不卡）。
6. **扇只有 B 点、只有银 / 红，而且以红为主。** 没有金扇子模板、P 点扇没测，所以金墙时刻的托底是红 / 银扇，不是金扇；银扇每束 3 个 GPU，预算放不下，托底扇里红彗星 415 个、银扇 108 个；P4 等中间位置的低层只能靠球花补。托底扇里 3 组没放（空小节 1 组、预算 2 组），预算紧的波只剩 2–4 把红扇。
6b. **托底扇的次序不一定和尾缀一致。** 为了四种方向都出现，不是定向的波按轮换给方向，换了方向的扇最晚一把比对应尾缀晚 0.7 s；看着「不同步」是这个设计，不喜欢可以改成逐点严格对齐。另外「左扫 / 右扫」的方向按子模板命名和角度推的（九束左扫 = 束角从 −45° 到 +45°、出筒偏移递增），没在 UE 里看过。
6c. **规模变大。** 父模板 102 → 144、槽位 238 → 329；编译和展开检查通过，但导入器 / UE 对这个量没测过。
7. **可能偏满。** 129 个小节里 98 个有整排波，空小节只有 41 / 65 / 96。长冈本身也密，但我们 3:30 里留白少、没有"喘一口"的长段；D1 / D3 要回答的就是这个。
8. **音乐落点没试听。** 段落入口来自小节网格 + 响度分析；112.2 s（你的 1:47）按「高潮 II 回归入口」处理；终章是不是主高潮、196.5 s 终和弦是不是白墙该来的位置，要你听。
9. **手机档是机械规则。** 中档去最外两点、低档隔点留，没有按手机画面单独设计；手机粒子 ≤ 50 由固定子模板决定，这版没有逐个核对。
10. **风格像不像只能看。** 体检只能证明「我写下的规则被遵守了」，不能证明像长冈；这是需要你用眼睛判断的部分。
11. **倒计时前 4 s 的红彗星单束**是我加的预热（B0+B7 往里），你没明确要过；不喜欢就删。
