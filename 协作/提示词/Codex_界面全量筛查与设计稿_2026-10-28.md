# 给本机 Codex：烘焙器界面全量筛查 + 设计稿

> 对话框9 写，2026-10-28，给本机 Codex 用。先读方案全文：`协作/方案/界面筛查与统一组件库_2026-10-28.md`（用户原话在方案开头）。
> 方案第 11 节有几项等用户定；没定的按「我的推荐」做，并在报告开头写明按的是哪一项推荐。

## 任务

做方案的第 0–4 步：冻结表 → 界面清单 → 全量筛查 → 分类 → 设计稿。**不改产品源码。**

## 开工

1. 按 CLAUDE.md §0 开工。读 `协作/交互宪章.md` 的 §0、§4、§8 和「4.9.125 V5」一节，以及 `tool/design-system/README.md`。
2. 基线：分支 `v5-4.9.125`（c045f46a 或更新）。**不是 main**，main 还是 4.9.124 的布局。报告里写基线提交号。
3. 本机打开页面：`python -X utf8 tool/local_http/preflight.py --tool baker --start`，用它返回的 HTTP 地址，不用 `file://`。浏览器或权限拒绝就停下报告，不换入口绕过。
4. 环境：Edge 和 Chrome（当前稳定版，写版本号）× 2560 × 1440 @150%、1920 × 1080 @100%、1366 × 768 @100%。

## 只许做 / 禁止

- 只许新建这些：
  - `analysis/results/20261028_界面筛查/`：问题清单.csv、生成点.csv、界面清单.json、覆盖率.md、冻结表.md、看法.md、1–3 张关键图；
  - `analysis/local/20261028_Codex_界面筛查/`：全部截图和过程数据（不进 Git）；
  - `analysis/scripts/界面规则筛查.py`：规则脚本，本机和云端都能跑（云端用 Chromium，参数传地址、分辨率、缩放）；
  - `tool/design-system/drafts/v1/`：设计稿（HTML 原型 + PNG）。
- 禁止：
  - 改 `tool/src/`、`tool/FireworkBaker.html`、`tool/design-system/` 里已有的文件、参数表、宪章；
  - 改画风冻结项（颜色、圆角、选中 / 悬停 / 按下 / 焦点的样子）。要改只能单列成「画风变更提议」，附对比图；
  - 照展示型网站（Awwwards 一类）的风格设计；
  - 推 main；`git add -A`。只加自己的文件，推送前过合入门禁（hook 会自动跑）。

## 第 0 步：冻结表

从基线页面的实际计算样式（不是只看 tokens）抽出所有颜色、圆角、选中 / 悬停 / 按下 / 焦点样式，每个值带用量和出现位置。几乎一样的值（色差很小、圆角差 1 px）列成「合并提议」，附对比图；用户没定之前全部原样保留。

## 第 1 步：界面清单（方案第 3 节）

1. 静态扫描：`tool/src/body.html` 和 `tool/src/js/*.js` 里所有生成控件的地方（HTML 模板、`createElement`、SCHEMA 生成器、`confirm` / `alert` / `prompt`、内联 style）→ `生成点.csv`（文件:行、生成什么控件、出现在哪个界面、建议归哪个组件）。
2. 运行时枚举：41 个类型、39 个库效果、多层 / 尾缀 / 粒子图 / 火焰 / 地面循环 / 仙女棒的代表，加上我的效果、模板、正式库条目；每个发射器标签、折叠全开、每个菜单和弹窗、每个视图 → `界面清单.json`，每个状态一张截图。
3. 补脚本到不了的状态（方案第 3.3 节）。

完成：生成点 100% 有归属；每个生成点至少在一张截图里出现；没覆盖到的写进 `覆盖率.md` 并写原因。

## 第 2 步：筛查（方案第 4 节）

- A–G 能自动的全部写进 `界面规则筛查.py`，每条规则输出：命中元素、截图局部、生成点。
- 半自动的规则：脚本标候选，你看截图确认。
- H 维度：每个代表页面每个维度打 1–5 分，附截图和一句理由；对标专业工具的属性面板（Blender、UE Details / Niagara、Houdini、Resolve / AE 效果控件）。
- 校准集：方案第 4 节表格「例子」一栏的问题必须全部抓到。漏了就补规则再跑，不能手工补进清单了事。

## 第 3 步：分类（方案第 5 节）

`问题清单.csv` 字段按方案第 5.1 节；严重度按第 5.2 节。同一根因的合成问题组，写实例数。

## 第 4 步：设计稿（方案第 6 节）

- 基础规范、组件规格卡、模式、页面模板四层都要。
- 组件按方案第 6.3 节的初步清单，按实际清单增删，写清每个组件对应哪些问题组。
- 格式按第 6.4 节：HTML 引用 `tool/design-system/tokens.css`，数值写 token 名；每页注明用了哪些组件；关键页面三档屏幕加 150%；Chrome、Edge 各一张；每张配「现在 vs 设计稿」对比图。
- 字阶 / 密度出紧凑、常规两档给用户挑。

## 报告（写在 `analysis/results/20261028_界面筛查/看法.md`）

开头一屏：基线提交号；浏览器版本和环境；覆盖率；校准集结果（抓到几条 / 共几条）；问题数（严重度 × 类别）；问题组数；组件数；要用户定的事。
