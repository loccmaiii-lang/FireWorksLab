# 烘焙器 4.0 开工说明（给 4.0 负责人）

> 用户在新对话里只需要说：「按 `协作/4.0开工说明.md` 开工」。

1. **开工三件事**：按 `CLAUDE.md` 第 0 节做。
2. **读**：
   - `交接.md` 第 1 节
   - `协作/标准.md`（完成标准）
   - `协作/渲染基础问题清单.md`（要修什么，带位置和证据）
   - `归档/提示词改动说明_2026-09-30.md` 第 5 节（4.0 分阶段 a–f）
3. **认领**：在 `协作/状态清单.json` 的「共享文件 → 4.0 期间只由 4.0 负责人改」旁写上自己的对话名，推送。`对话记录/` 里新建自己的对话记录。
4. **顺序**：
   1. 先修问题清单里的 P0 小 bug（F0 切换条目串格子、F1 烘焙失败无限重试）。
   2. 再按 4.0-a → f 顺序做。
5. **每一阶段都要做**：
   1. 先写能复现问题的检查（以后放进 `标准检查.py`）；
   2. 修；
   3. 对基准条目（`标准.md` 第 5 节）出改前 / 改后同一帧对照，并跑回归；
   4. 升版本号（3.8 …），写 `tool/CHANGELOG.md`；
   5. build；
   6. 写交接日志、推送；
   7. 把对照发给用户看。
6. **已通过的 JM4、尾缀 V5**：用兼容开关保持逐像素不变；4.0 完成后在新渲染核下重新渲染一次，再交用户验收（用户 2026-09-30 定）。
7. **及格线数值**：以 `协作/标准.md` 第 2 节为准。里面的「目标观看距离 / 屏幕大小 / 引擎帧率」等用户回答后填（对话框 2 在问）。
8. **云端没有显卡**：浏览器走软件渲染，2K 烘焙一次约 4–5 分钟。重的回归可以写成本机任务，或请 Codex 在用户电脑的真显卡上跑；**Codex 在 4.0 期间只做验证，不改 `tool/src/`**。
