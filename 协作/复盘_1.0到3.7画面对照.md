# 复盘：1.0 到 3.7 同参数画面对照（2026-10-01，云端 Claude 对话框 1）

> 起因：用户问「1.0 很惊艳，后面越来越不行，为什么」。完整复盘（含提示词、10+3 条规则、多角色分析）在云端文档「烘焙器 1.0 到 4.0 复盘与提示词」。本文件只留 4.0 执行者需要的事实和数字。
> 方法：无头浏览器软件渲染，取各提交的 `tool/FireworkBaker.html`，用它自己的默认菊，暂停在 t=0.8 / 1.5 s 截图。脚本和图在 `analysis/复盘/`。

## 结论

1. **观感的断崖在 1.0 → 1.1（09-27 11:18 同一分钟入库），不是逐步变差。** 1.1 之后各版本都在同一水平。
2. 1.0 默认菊：红→绿变色、带光晕的亮星头、很密的金色尾迹；导出效果和实时模拟几乎一样。1.1 起默认是单色金、细、暗；3.7 的导出效果还比它自己的实时模拟更小更暗。
3. 1.0 导出两张贴图（Head / Tail，各 4×4×4，单格 512 px，分别定曝光），用自己生成的 HLSL 材质（头 ColA→ColB，尾 TailHot/TailCool）。1.1 为对齐项目材质（一张灰度贴图 + Ramp + Color Over Life）改成合并输出、默认 8×8×4（单格 256 px）。**对齐是对的，但没有量损失，也没有补偿。**
4. 「看到的 ≠ 导出的」里的快门按帧间隔算、整张 99.8 分位自动曝光、光点最小 σ 0.55 px，1.0 就有；encGamma 是 1.1 加的。

- 对照控制：把 3.7 的颜色、fade、burnJit 改成 1.0 的，红绿变色能复现，星头仍小暗、尾迹仍稀。
- 尾缀曝光只有 1.0 的 1/3，**原因没定位**：已排除开花闪光（flash=0）和末段闪光（lastFlare=0），尾缀曝光仍是 0.113；`expoMode=frames` 把星头曝光从 1.35 拉到 3.57，尾缀只到 0.123。候选：格子减半后火花在贴图上的像素数、光点核与 0.55 px 下限、头尾合并后共用一个曝光值。
- 局限：软件渲染，每版本测一次；只测了默认菊。

## 给 4.0 的建议

1. 把 1.0 的 html（`git show fccb46b:tool/FireworkBaker.html`）存进 `analysis/golden/v1.0.html`，做同参数回归：默认菊亮部像素 ≥ 1.0 的 80%，PC 单格 ≥ 512，尾缀曝光 ≥ 0.25。
2. 先定位尾缀曝光差，再重写渲染核。
3. 用「头层 + 尾层」两层（各自 Ramp / Color Over Life）在项目材质里复现 1.0 的红→绿变色和尾缀色，先在 UE 里实测。
4. 凡是对齐 / 约束类改动（材质、格子、帧率、距离）前后，必须同参数出对比图并写明亮部像素比。
