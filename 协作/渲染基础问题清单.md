# 渲染基础问题清单（2026-09-30 晚，云端 Claude 对话框 2）

> **状态（2026-10-02 标注）：** 写于 09-30，烘焙器 4.0 已据此修了主要问题；没有逐条核对每项是否关闭，引用某条前先查 `tool/CHANGELOG.md`。

> 起因：用户反馈「调粒子大小不生效、放大变糊、序列帧还在抖」，并且对着参考做的效果反而不如 3.7 花型库符合直觉。
> 做法：只读代码和已经导出的结果，没有改代码。分五块并行排查：GPU 渲染与烘焙、导出与 UE 对接、模拟、界面与审阅管线、协作流程。关键结论用导出数据复算或读代码核实过。
> 证据强度：**实测** = 用仓库代码或导出数据算过；**代码** = 读代码确认；**待 UE** = 按引擎 / 压缩格式原理推断，要在 UE 里测一次。
> 优先级：**P0** = 看到的和导出的不一样，或素材本身是错的；**P1** = 明显影响画面、稳定性或调参体验；**P2** = 小问题或边界情况。

---

## 一句话结论

问题大多不在单个效果，而在工具底层：

1. **你审的画面不是引擎里会播放的画面。** 实时模拟、导出效果、拟合对照图三处，分辨率、运动模糊、曝光各算各的。
2. **一批滑杆在导出分辨率下没有作用，或者被自动曝光抵消。**
3. **帧预算按「贴图里每帧移动几像素」分配，没按引擎的播放帧率和屏幕放大倍数分配。** 所以一边在开花段浪费帧，一边在后段卡顿。
4. **引擎对接有几处和素材包对不上：** 组合层时序、手机版、导入设置。
5. **自检工具没有及格线**，这些问题一直没被拦下。

在这些问题修好之前继续拟合效果，每一轮都在错误的尺子上量。

## 流程上的原因（不是代码 bug，但一样要改）

1. **判断标准错位。** 「像不像」看的是按视频分辨率、加相机模糊的对照图和拟合分数，不是引擎回放。3.7 花型库是在烘焙器里用眼睛调出来的，没有经过这一层偏差，所以更符合直觉。
2. **反馈太慢，而且在坏尺子上加速。** 一天 89 个任务、98 个结果，通过的只有接显卡之前的金芒菊和尾缀 V5。定时接续会话每 3 小时在同一套有问题的底层上接着迭代。
3. **没有 UE 实测回路。** 预览的 ×4 自发光、色调、BC7、曲线查找表、Ramp 过滤，一直没在引擎里对过一次。
4. **记录太多、规则互相打架**（见 `协作/提示词草案/改动说明.md`）。每一步要改 5 处记录；多个对话和 Codex 同时推。

## 建议的修复顺序

> 修的时候：已通过的东西（JM4、尾缀 V5）用版本开关保持逐像素不变，或者由用户决定重新渲染后再验收一次。

**第 0 步 · 冻结（半天）**
- 暂停定时接续会话和新的拟合任务。
- 定一组基准：3.7 花型库的菊、牡丹、锦冠、千轮 + JM4 + V5，作为每次改底层后的回归对照。

**第 1 步 · 一个画面说了算（A1–A7、C2、F3）**
- 新增「引擎回放」视图：按导出贴图、目标屏幕尺寸、30 / 60 fps 按 tick 取帧、引擎的曝光假设来播放。待验收只看它；实时模拟只用来调参。
- 光点改成「亮核 + 光晕」，尺寸按米计算，在任何分辨率下都有效。新条目默认用精细档。
- 快门统一成秒，三处共用。
- 加曝光锁。

**第 2 步 · 时间和帧预算（B1–B7、E5、E6）**
- 帧密度按引擎帧率封顶，快门按显示间隔算。
- 首尾空帧 / 暗帧自动裁掉。
- 按「屏幕放大 ≤ 2 倍」和「30 fps 能显示的帧 ≥ 90%」自动选格子（例：5×5×4、6×6×4）或分段。
- 点灭、闪烁防混叠。

**第 3 步 · 自检有及格线（G1、G2、B6）**
- 回放检查按 tick 模拟、读 `delay_s`，裁切改测内圈。
- 不及格就不能进「待我验收」。

**第 4 步 · 引擎对接（D1–D7）**
- 组合导出成一个多发射器的 `cascade.json`（带每层延迟）。
- 做出真正的手机版（单通道 / 1K / LDR 标定）。
- 补全导入设置。
- 出一份 UE 实测包（帧号测试图、BC7 串扰图、曝光标定），请用户在引擎里跑一次。

**第 5 步 · 模拟稳定（E1–E4、E7–E11、F1、F2、F4–F6）**
- 随机数和参数脱钩；GPU 死亡时刻；NaN 保护；上限报警。
- 烘焙失败处理、主线程卡顿、组合审阅、版本指纹。

**之后**：用新的底层重做正在进行的效果；拟合只调少数、在有效区内的连续量。
