### 2. 「为什么只渲染了尾焰主体没渲染大量 GPU 粒子？我要的是合并渲染再加 800 个 Cascade 粒子」

你理解的对，我之前做反了，而且 RT5 里我又错了一次（为了 ≤ 800 把 GPU 火花的出生率乘 0.56 降下来——是减少了火花，而不是把它们放进贴图）。

**为什么当初分开**：循环层贴图是在弹体随体坐标里、按出膛速度烘的一个**真循环**（64 帧转 2.3 秒）。能进真循环的前提是「稳态」：火花按周期出生、运动规律不随时间变。短命的火花（星头、白热段、0.9 s 的细火花）满足；长命的粗火花（3.4 s）不满足——它们出生后 0.3 s 就被阻力停在空气里，之后是**弹体在减速地离开它们**，相对星头的运动随时间变，再加大涡乱流本身就不是周期的；再加上 3.4 s × 157 m/s = 500 多米高的格子会把星头的分辨率压到 4 像素 / 米。所以 10-02 的设计把长命火花交给了 GPU 粒子（还顺带想要点视差），结果就是你在 UE 里看到的：贴图只有一根白柱子，火花全靠 1 万个 GPU 点，Acceleration 还标红。

**正确的分法不是「短命进贴图、长命进 GPU」，而是「年轻的随体、年老的随地」**：

- **近段（循环层）**：年龄 ≤ 约 0.8 s 的所有火花 + 星头 + 白热段，随体坐标真循环，高清（格子只要盖 130 m，约 16 像素 / 米，比现在清 3 倍）。
- **远段（全程序列）**：年龄 > 0.8 s 的所有火花（细 / 中 / 粗 / 落火），它们已经停在空气里，所以用**世界坐标**烘一张从发射点到开花点的全程序列（一个 CPU 面片，立在发射点上，64 或 128 帧盖住上升 + 熄灭全程，6–13 fps 够用，因为内容只在慢慢变暗和漂）。减速、倾角、大涡乱流在这里都是精确的（不是循环，不怕非周期），**开花后它自己接着演完熄灭**，不再需要单独的消散层来管老火花。两段之间按年龄交叉淡化（0.6–1.0 s），不会有缝。
- **GPU 粒子 ≤ 800**：是「再加」，不是「挤进去」。规则：粗火花（最亮、最少）优先给 GPU，放不下的那部分进贴图；贴图 + GPU 合起来 = 你在实时模拟里看到的全部，一颗不多一颗不少。GPU 的作用是视差和远看时的亮点（贴图缩小后 Ramp 会把细火花压暗压橙，GPU 点不会）。手机 0 个 GPU，只有两张贴图，画面也是完整的。
- 近段循环层的「长度跟真实尾迹」只管 0.8 s 以内，起步从弹体后面长出来、顶点附近缩短的近似误差变得很小；消散层只剩年轻火花那 1 秒，很小。

这是 RT5 的第二版结构，RT5 还没导出过，直接改成这个再导。详细见第 3 节 D。

### 6. 「满意的单层想存成模板 / 收藏，不能」

### 7. 「你做的效果，我调参保存后想加层，加不了」

### 10. 「参数系统新旧混合，影响判断，旧的清掉」

数了一下现状（这就是混乱的来源）：

- 面板 **369 项**参数；其中 **6 个「旧 / 新」开关**（结尾、冷却方式、弹道、GPU 兼容、贴图亮度口径、亮核分布）全是我为了「不改旧效果」留的；

- **「输出」一个发射器 58 项**，里面有两套帧数系统（3.x 的 `frameMode / fpsFloor` 和 4.2 的 `frameBudget` 五种模式 + 各段帧率 + 停留 tick + 贴图张数…）；
- **4 套火花模型**并存：空中星的火花（20_sim / 40_gl）、V5 尾缀（42_trail）、物理尾缀（43/45，条目已归档却还在面板里，约 40 项）、升空尾缀（47_risetail，黑体温度那套）。同一个「火花怎么变暗」在四处写法不同。

### 11. 「为了复刻参考硬加的功能，不是物理渲染的产物；引菊金锦的火花消散就不是统一的生命逻辑」

承认。CLAUDE.md 第 3.3 条本来就写着「拟合只调少数连续量，且只在参数有效范围内」，但实际上做法是「参考里有什么形状就加一个旋钮去造那个形状」。我先把候选名单列出来（最终名单在大筛查里按每个条目实际用了什么来定）：

| 类别 | 参数 | 为什么可疑 | 处理 |
| --- | --- | --- | --- |
| 造形状 | `tailWidth` 尾迹粗细、`tailPinchHead / tailPinchTail / tailBellyAt` 梭形、`headTear` 泪滴星头 | 直接画出一个形状，不来自任何物理量 | 删。粗细 / 梭形应该由散开速度、阻力、尺寸随寿命自然出来 |

金锦层（HN2-G）的具体情况：火花寿命 2.8 s、寿命随机 ±30%、变暗按「各自寿命的百分比」→ 相邻两颗火花一颗寿命 2 s 一颗 3.6 s，同一时刻一个快灭了一个还亮着，所以是一条线上随机灭。统一模型下（见 B）：变暗按实际年龄，一条尾迹从星头到末端是连续的亮度梯度，寿命离散只决定每颗最后那一下什么时候熄；粒径大的火花活得久也亮得久（物理上就是这样），所以不是「纯按年龄」也不是「纯按各自寿命」，而是**一条冷却曲线 + 粒径决定寿命**，离散调到 0 就是纯粹的老的先灭。

### 12. 「多层效果想合并一起导出，没有」

现在多层导出已经是一个素材包，但每层一个发射器、一张贴图。「合并成一张贴图一个发射器」受一个硬约束：**贴图是灰度 + Ramp 上色，一个发射器只有一张 Ramp、一条颜色曲线**（这也是为什么星头和尾巴颜色不同就得拆两层）。所以：

- **Ramp 相同（或你接受共用一张）的层可以合并**：同一模拟、同一曝光、把几层的光加在一起烘成一张，一个发射器，延迟 / 时间倍率都烘进去。例：引菊 → 锦如果橙引线和金锦共用一条「黑 → 红 → 橙 → 金 → 白」的炭火 Ramp（物理上就是一条冷却色），就能合成一层。
- **色相不同、时间上重叠的层合不了**（青柠星头 + 金尾巴；金锦 + 红点灭）——除非换 RGB 材质，而项目规定不新增材质。
- 做法：导出里加「合并导出」开关，自动判断哪些层能合（Ramp 相同 / 兼容），能合的合、不能合的单独出并写明原因；手机版可以多一个选项「全部合并、共用 Ramp」（手机更在乎 overdraw，颜色可以让一点）。

### 13. 「画幅占比上去了，但流转动画还是抖得厉害；加一个默认模式：自适应最大化 → 固定镜头 → 不做任何补偿，前面太小的帧用入点出点裁」

同意把它做成**默认，而且是唯一的大面片模式**。先说我判断的抖动来源（没看到你那边的画面，按代码推）：

- 现在大面片默认是固定取景（Zoom 已关）+「按运动分配帧」：开花段每 tick 一帧，之后每帧停 2–3 tick，淡出段停 4–5 tick。**停留 tick 数在 2、3 之间交替**（因为帧数要凑进贴图），30 fps 的引擎里就是 15 / 10 fps 来回换——这是我最怀疑的「抖」。
- 其次是「取景收紧」和入点前的「从小放大」（`preRoll`，Size By Life）这些补偿，以及 4.0 的「持帧」帧号曲线（UE 实测包里的「Held3Tier」测试一直是 ⚪ 没测）。
- 要确认只需要你一个 10 秒录屏（或说一下是哪个效果、在 UE 里还是在烘焙器的流转视图里）。

新默认模式的定义（没有可调的花样）：

1. 取景：入点 → 出点之间所有帧的内容并集，横向以爆点对称，塞满格子（就是你说的自适应最大化），**整段一个取景**，不写 Size By Life、不写入点前放大、Initial Location 只放一个常量把爆点对齐；
2. 帧：**整段同一个停留 tick 数 k**（1 / 2 / 3 / 4，自动取放得下的最小值；想要 k = 1 就两张贴图），帧号曲线是一条直线（查找表无论烘不烘都精确）；
3. 入点之前：发射器延迟到入点，不显示（花太小的那几帧你用入点裁掉）；出点之后结束；
4. 唯一的旋钮：入点、出点、贴图尺寸（2048 / 4096）、贴图张数（1 / 2）、曝光。

### B. 一套物理火花模型（底层统一）

一颗火花 = 一粒燃烧的炭（或镁铝粉），只有这些量：

| 量 | 来源 | 决定什么 |
| --- | --- | --- |
| 粒径 d（中位 + 对数离散） | 药剂 | 亮度 ∝ d²、寿命（燃尽时间）∝ d²、阻力 ∝ 1/d、冷却时间 ∝ d |
| 出生：时刻、位置、初速 = 母体速度 − 向后喷出 + 散开 | 母体（星 / 弹体 / 喷口） | 轨迹起点 |
| 受力：线性阻力、重力、空气速度场（大涡 / 小涡，可关） | 环境 | 轨迹 |
| 温度：出喷口 T0 → 燃烧温度 Tb（tc 秒）→ 燃尽后熄灭 | 药剂 | 颜色（黑体 → Ramp）和亮度随**实际年龄**变 |
| 闪烁：频率 + 幅度 | 燃烧不稳定 | 明暗起伏 |
| 相机：快门时间、曝光、光晕 | 输出一处 | 拖影长度、过曝、光晕 |

规则：变暗按实际年龄（老的先暗），粒径离散决定寿命离散（寿命随机和大小随机合并成一个「粒径离散」），没有「按各自寿命百分比」这条路，没有每档温度偏移、每档拖影倍数。同一套用于：空中星的火花、升空尾缀的火花（三档粒径改成一个分布，参数从 24 项降到 ~8 项）、白热段（极小粒径、极短寿命的同一模型）、落火（大粒径）、地面循环的火花。星（母体）也是同样的「燃烧时间 + 第二段」逻辑。

代码上：空中（20_sim / 40_gl）、升空尾缀（47）、V5（42）、物理尾缀（43 / 45）四套合成一个火花核；物理尾缀条目已归档、V5 等 RT5 验收后归档，这两套直接删（面板少约 60 项）。

### 6.2 引菊 → 锦「变大变小」的真正原因（13 条，云端核对 HN2E14 的 cascade.json）

HN2 两层都是 `zoom: 'on'`（4.2.3 的「逐帧阶梯」）：**每一帧按自己内容的大小取景烘**，引擎里再用 Size By Life 一帧一个台阶把面片缩放回去。L1 的台阶是 0.339 → 0.311 → 0.278 → 0.240 → 0.247 → 0.287 …（先缩后放，不单调），所以：

- 流转动画里直接播贴图（没有那条曲线）= 内容一帧一个大小，就是你看到的「变大变小的流转」；
- 丢了曲线这张贴图就废了（你说的对），引擎里只要曲线和帧号错开一个 tick 也会跳一下。

我前一版把原因猜成「停留 tick 交替」，那是次要的。**需求很简单：贴图自己就得是完整的，不靠任何曲线。** 做法就是 1.13 的固定机位：整段一个取景（入点 → 出点内容的并集塞满格子）、面片一个常量大小、帧号一条直线，不写 Size By Life、不写入点前放大。开头花小是物理事实，用入点裁。4.0 之前的「Zoom ✅ 推荐」是为了多用格子像素，现在你用可复用、不抖换它，值。

旧的那些（按你 4 的意思先留着、默认不用、以后删）：取景「Zoom 逐帧阶梯」、帧数「按运动 / 最省 / 手动 / 分段帧率 / 全帧」、入点前「从小放大」、取景收紧。

### 6.3 统一火花模型后什么留、什么走（18.3）

留（都是物理现象，参数是物理量）：**闪烁**（频率 + 幅度，燃烧不稳定）、**点灭**（星头的药剂周期性熄灭 / 复燃：频率 + 占空比 + 开始时刻）、**辉星**（延迟点亮的颗粒）、**爆裂**（燃尽时的微爆）、**分叉 / 十字 / 千轮**（分裂事件）、**变色分段**（药剂分层）、**第二段燃烧**、**余烬 / 落火**（大粒径）、**空气扰动**（大涡 / 小涡）。它们都是「事件」或「药剂属性」，由同一个粒子模型驱动。

走：造形状的（梭形、泪滴、尾迹粗细倍数）、造光感的（线间底光）、每档温度偏移 / 每档拖影倍数、「按各自寿命」那条变暗路、隐藏倍数、6 个旧 / 新开关、已归档产品线的参数（物理尾缀；V5 等 RT5 验收后）。

### 6.4 GPU 800 的分配（18.6）

远看要「明显清晰」，先算一笔账：游戏内 1000 m 观看、1080p、约 60° 视野 → 1 个像素约 1 m。粗火花 0.38 m 在屏幕上不到半个像素，再亮也看不见。所以 GPU 点不按真实粒径画，按「远处可读」画：软圆点直径 2–4 m（屏幕上 2–4 像素）、亮度按光量守恒再乘一个你能调的「远看增益」。预算做成面板上一张表，一行一个 GPU 发射器，总数实时合计、超了标红：

| GPU 发射器 | 建议预算 | 内容 |
| --- | --- | --- |
| 粗火花 | 300 | 最亮最久的那部分，同时也在贴图远段里（GPU 的从贴图里扣掉，不重复） |

### 6.5 隐性耦合与「看不见的地方写死」（17 条）

引菊 → 锦那两个现象查到了：

- **锦层出现时间**：两层是「同一批星」，有一条**粘连**规则（`gluePartners`）：联动的两层里时间点重合（±0.02 s）的会一起动——引线「火花停 1.2 s」和锦「点火 1.28 s」粘在一起，你动哪个另一个都跟着，所以感觉改不了。层页头「轨迹联动」里有个关掉粘连的开关，但你没理由知道它在那。
- **入 / 出点**：点火延迟一改入点跟着平移（`followIgn`），改任何时间参数序列时长跟着伸缩（`followDuration`），火花停不能超过燃烧结束、超过了燃烧结束被推着走……都是「帮你」的自动规则，没有一条写在面上。

同类的还有（先列我知道的，完整清单交给对话框19 扫代码）：号数一改重写十来个参数、「-1 = 默认」、「0 = 自动」的参数不显示算出来的值、建议曝光、Zoom / 取景收紧 / 帧数自动、结尾选不淡出自动加长序列、尾缀物理弹道算出升空时间、21 个隐藏参数。

可控原则（进宪章）：① 代码替你算的值一律灰字显示在参数旁边，带「改」解锁；② 任何耦合画成看得见的链条图标，可点断；③ 不许静默夹值，夹了就说原因；④ 层的「开始时间」和「点火延迟」两个时间原点并排显示并给出绝对时刻。

### 6.7 「以后怎么杜绝」（11 条）我的答案

规则有，但没牙；系统没有把规则做成门。具体是五个洞：

1. **目标函数**：以前的目标是「像参考」+ 拟合分数。AI 优化这个目标最便宜的办法就是加自由度（加一个旋钮比改对模型快十倍），而「加旋钮」和「加物理机制」在 diff 里长得一样，3.3 条「只调数值」没人能查。→ 目标改成「先对物理，再对参考」；参数门做进构建（面板键 ⊆ 冻结表，否则构建失败），不靠自觉。
2. **约束**：「不改已通过效果的画面 + 回归逐像素相同」把每一次行为修正都逼成一个开关 + 保留旧路径，新旧混合是这条规则的必然产物。→ 你今天改成「底层对就行、重导」，回归改成「新基准 + 改前改后对照图」。
3. **没有模型文档**：没有一份文件写「一颗火花怎么活怎么死」，4 个对话框写了 4 套。→ 一份 `analysis/原理/物理模型.md`（公式 → 参数 → 代码位置）当唯一来源，改行为先改文档，代码引用它。
4. **多对话、无总图**：功能加在顺手的地方。→ 底层和界面壳各一个负责人（已经是），加交互宪章和动作矩阵；分派出去的任务只产出文档和清单，改代码的入口只有一个。
5. **检查测「有没有」不测「对不对」**：27 项检查保证功能在、不崩，不保证物理对、交互一致。→ 检查里加宪章项（无表外参数、无「旧」字样、每个物理量有单位、每类对象动作矩阵齐）；每个版本自动生成「参数变更表」放在更新记录顶上，漂移一眼可见。

所以答案是：**主要是规则没有执行机制，其次是系统缺了模型文档和参数门；两样都要补，补了之后再出这类问题就是我的问题。**
