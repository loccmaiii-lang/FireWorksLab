## 2. 5.0 是什么样子（一句话）

**一个效果 = 一棵发射器树。每个发射器（星、火花、余烬、爆裂、子花、开花闪光……）都是同一种东西：同一套模块、参数一样全，由事件挂在父发射器上。底层物理只有一套，输出默认固定机位，界面按交互宪章重排。**

```
效果
├─ 星（父）               生成 / 形状 / 初速 / 受力 / 寿命 / 大小 / 颜色 / 亮度 / 闪烁
│   ├─ 火花（燃烧时沿路）  同一套模块，全的
│   ├─ 余烬（燃烧时沿路）  同一套模块，全的
│   ├─ 爆裂（熄灭时）      同一套模块，全的（大小、亮度、时长都能调）
│   └─ 子花（定时 / 熄灭时）→ 它自己又是一个「星」，下面还能挂
├─ 开花闪光（开花那一刻）
└─ ＋ 加发射器 / ＋ 加模块
```

- **事件**：出生时、燃烧时沿路、熄灭时、到某个时刻。正好对应 Cascade 的 Event Generator / EventReceiver Spawn 和「跟随」。要注意一点：Cascade 里发出事件的发射器只能是 CPU，导出时会照这条分 CPU / GPU。
- **模块的参数一样全**：每个模块都有「数值 + 随机 + 按寿命变化的曲线」三种填法。曲线就是 Cascade 的 Over Life，只放有变化的几个点。
- **默认值 = 现在写死的数**：旧效果打开时画面一样。5.0 统一物理的那几处除外，见第 3 节「画面会变」那几行。

### 7.1 「粒径 → 火花寿命 / 阻力」为什么还没接上（10-06 01:10）

- 物理上：寿命 ∝ 粒径²、阻力 ∝ 1 / 粒径，所以「寿命 × 阻力²」对一种药应该是同一个数。
- 现在的花型模板：菊 / 牡丹等 2.7，冠菊 2.5，蜂 3.2，爆裂星 1.5，锦冠 4.8，**椰子 12.6，柳 20**。差 14 倍，一个粒径配不出来。柳为了下垂调了大阻力，物理上大颗粒反而阻力小。你自己的金曜菊-A 两层也一样（6.1 例 1）。
- 所以按 Q1（物理给默认、每个值都能改）接上粒径，结果是：所有模板的寿命 / 阻力都是「你填的」（链条断开），拖粒径什么都不变，只多一个看起来没用的滑杆。
- 两条路：
  - A：先不加粒径。Q1 的「每个值都能改」已经满足（寿命、阻力本来就能直接改），联动的都有链条（4.9.0）。**推荐**。
  - B：加粒径，同时把模板改成按粒径算（柳、椰子的画面会变，要重新拟合）。只有你要「一种药一个粒径」的物理统一时才值得做。
- **用户 10-06 07:56 定 A**：「按你的建议先不接粒径到火花寿命与阻力」。参数表「合并」那些项按 Q1 读成「每个值都能直接改」，不再加新物理量。
