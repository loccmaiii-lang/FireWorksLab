# 彩千轮3.0 实施计划

> **当前有效范围（修订2）**：用户已将三种改为环形＋球形四种，现有PRISM3整体和A/B/C原ID继续迭代、增加D；其余CPU事件、两固定色族/一随机色族、只PC约束仍有效。详见`analysis/results/PRISM3R2_20261016/制作计划.md`、`验收单.md`和`交付说明.md`。下面三组件/禁环形是修订前的候选思路，已被本轮明确指示替代，不作为当前限制。

**目标**：在现有彩千轮上迭代，交付三种小割序列及 CPU 事件链 Cascade 包，实际 UE 导入由用户执行。

**架构**：CPU 闪光与三组飞行星头；每组星头死亡时发出独立命名事件，对应一种小割序列，接收器每事件只生成一颗面片。三种造型使用现有牡丹模拟核和统一导出，颜色两组固定、一组沿用库内点灭星随机方法。

**技术**：现有 JavaScript 烘焙器、fwl.cascade/1、Python 图像测量、Cascade CPU Sprite。

## 范围和验收

- 本次必须：原资产发射器参数、事件逻辑与点灭星随机参数记录；A/B 参考逐帧时刻；三种小割；CPU 闪光/星头与事件位置连续；PC产物；真实出口检查与五步复核。用户本轮澄清“手游没有彩千轮”，不新增手游。
- 可后做：用户实际导入后按项目曝光做亮度标定。
- 暂不建议：烟雾层、音效、额外造型、新材质、用整团面片代替事件链。
- 不把燃烧论文的统计寿命当成本视频的实测配方；视频定时，文献只交叉检验物理量级。不会推断未知化学配比。
- 初选固定粉红、绿色，随机组沿点灭星颜色范围；这是工作假设，不是用户已确认的颜色。
- 三造型保持参考的小牡丹语汇，以星数、径向层次和排布区分，不擅自改成环形/心形。
- 已有用户修改保留；提交前依用户本轮 AGENTS 指示确认。

## 已确认误区

1. 现有 PrismWheels 的 Main/Dark 是 Spawn 事件，位置球半径 8000 cm；不是飞行结束触发。Sparks Cloud 的 UsePSysLocation=true 会回系统原点，不可照抄。
2. 三个接收器监听同一个事件会同时产生三朵，不等于随机选一朵。采用三组源/三个事件名避免增量膨胀。
3. 点灭星实际库使用 Initial Color Seeded，而仓库根的点灭星参数文本只是旧模板说明，不能混用。
4. 初查交换模块表与私有导入器没有事件模块；仅手写新 JSON 字段不构成可导入交付。本轮已补齐并验证离线计划，仍不能冒充UE实测。
5. 参考 A 全长 3.5 s、B 全长 3.3 s，均 30 fps。整段长度包含星头飞行，不能直接写成单朵燃烧时间。
