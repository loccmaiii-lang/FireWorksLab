## 已实现

1. **2K / 4K / 8K 实验母版**：保持相同 256 帧时，8×8 布局的单帧分别为 256×256、512×512、1024×1024。2K 引擎输出仍可选择，4K / 8K 明确标为实验母版。
2. **可选 2×2、4×4、8×8 空间采样**：在浮点、线性亮度域汇总全部样本，再编码为素材。空间采样不替代最终单格分辨率。
3. **300 / 960 / 1920 Hz 快门采样目标**：分别最多 16 / 64 / 128 个子样本，具体数量由该帧的快门时长决定。物理步长保持原有 1/480 秒，不把时间采样频率宣称为物理精度。
4. **像素覆盖积分光点**：对光点在像素内的覆盖做积分，降低小火星跨像素移动时的亮度起伏；提供原版光点开关。
5. **亮核控制**：在归一化的光点分布中调整窄亮核占比。星头使用完整设置，火星使用较低占比；并未凭空增加粒子或修改烟花轨迹。
6. **高精度预览**：屏幕像素倍率 1× / 2× / 3×，最高 4096×4096；可保存 4K 当前画面。导出视图依然忠实显示序列素材的单格限制。
7. **检查工具**：光晕强度、灰度亮度检查、4× 局部像素放大镜、实际画布尺寸、单格尺寸、采样和缓冲预算。未上色的原始通道在「贴图 → 流转动画」查看。
8. **完整 2K 组合库**：取消组合母版默认 1K 缩减。切换普通花型时保留当前高精度尺寸与采样配置。
9. **素材页按原始尺寸读取**：保留矩形格子的实际宽高，按需生成当前帧，单发射器最多缓存 16 帧或约 64 MiB。
10. **RGBA 接力读取修正**：直接读取未预乘的 RGBA 数据，避免 A 通道为零时普通透明画布丢掉 RGB 帧内容。
11. **长任务控制**：暂停实时绘制以避免共享 GPU 状态互相干扰；支持取消，保留上一份结果；取消、失败时释放新建缓冲。分段与尾缀失败时清理已经生成的前段。
12. **8K 内存管理**：自动曝光按条带读取，避免单次创建约 1 GiB 的浮点数组；估算临时 GPU 缓冲并限制到 1536 MiB，实际整页还包括旧结果和 CPU 缓存。

## 建议试用顺序

1. 在对照页比较 2K 原版采样与 8K 高精结果，再切换「2K · 只改采样」隔离算法影响。
2. 在实验烘焙器中保持当前参数，先播放实时模拟，再播放导出效果。
3. 关闭光晕，开启放大镜，观察细尾、亮核和火星间隙；再恢复适当光晕看整体观感。
4. 一般先使用 4K + 4×4。8K 同样保留帧数，但贴图、读取、分析和导出成本更高。
5. 需要放回现有 UE 流程时选择 2048 尺寸，重新烘焙和导出。不要把缩小后的素材仍当成 8K 的单格细节。

8K + 8×8 在默认 256 帧配置下超过本实验版缓冲预算，会明确拒绝；可选 8K + 4×4 或 4K + 8×8。任何质量档都不会偷偷降低最终尺寸。

## 证据与结果

- `results/verification.json`：相同随机种子 42、取景、时刻、快门和锁定曝光下的完整烘焙记录。
- `results/regressions.json`：正常启动、UI 取消、完整尾缀消散、8×8 采样、内容取帧、原始矩形帧检查。
- `results/integrity.json`：原文件哈希校验、原版与基准的像素差异、4K 图像和 ZIP 内容校验。
- `results/实测说明.md`：便于阅读的实际尺寸、时间与测试边界。
- `results/Kiku_ULTRA_4K.zip`：通过界面真实导出的 4K 示例，含贴图、参数、曲线等。
- `results/*-atlas.png`：完整 2K / 4K / 8K 序列贴图；RGBA 是接力帧数据，普通图片查看器可能按透明度解释 A 通道，外观不能作为缺帧依据。

对照页的左侧是本实验版的原版参数路径；已经与冻结的原版 3.6 独立烘焙结果比较，只有少量灰度值相差 1/255，具体数值见完整性记录。

## 当前边界

- 这是画质基础与数据读取升级。方向火星、连续细带、新的近景分层花型、美术参数重新校准尚未加入，默认大星头仍保留原有世界尺寸。
- 改善静帧细节容量和亚像素采样，不等于所有花型都更接近实拍。对照图没有更改相机、曝光或增加粒子数量来掩盖差异。
- 保留项目现有 8 位灰度 RGBA / PNG 输出、材质上色方式和帧号取整；没有新增 EXR / 16 位交付格式或帧间混合。
- 素材页保留原有 Canvas2D 合成方式，读取精度已经修正，但并不等价于 UE HDR、曝光和后处理。
- 菊、千轮、尾缀、喷泉已在浏览器检查；完整尾缀 30 / 20 fps 消散均通过接力测试。UE 4.24 的实际播放与性能仍需引擎验证。
- 烘焙计时会受驱动、首次着色器编译、浏览器状态影响，记录是该次运行，不是稳定帧率或性能保证。

## 维护

源码在本目录 `tool/src/`，运行 `python tool/build.py` 只生成实验目录中的 HTML。

验证入口：`tests/verify.cjs`、`tests/regressions.cjs`。使用本机已配好的 Playwright 和 Chrome；脚本里的运行库路径属于本机环境。`tests/upgrade*.py` 是首次从 3.6 建立副本的迁移记录，不应对已修改副本重复执行。

原始 HTML 在 `baseline/`，原项目文件的 SHA256 在 `baseline/original-hashes.json`。建立本地实验时没有提交、推送或合并原项目的其他改动；当前 `ultra` 分支仅发布上文列出的源码、配置和文档范围。
