## 背景（为什么做这件事）

烘焙器（`tool/FireworkBaker.html`，源码 `tool/src/js`）是一个 WebGL 烟花模拟 + 烘焙序列帧 + 导出 UE4 Cascade 素材包的工具。面板上有 369 个参数，另有 21 个不在面板上的隐藏参数和 8 个材质字段，一共 398 行。用户 2026-10-05 的判断：参数系统新旧混合、有很多「为了像参考视频硬加的旋钮」、有四套各自为政的火花模型，他没法推理「调这个会发生什么」。他要**参数宪章**：

1. 每个参数三选一：**物理量**（有单位、有物理解释、出现在模型公式里）/ **引擎字段**（能指出写进 `cascade.json` 的哪个模块字段，或贴图的哪个属性）/ **预览设置**（只影响工具里的显示，不进导出）。三者都不是，不得存在。
2. 一个现象只有一种实现，**没有「旧 / 新」「兼容」选项**；底层改法变了就升版本、重导旧效果，不留分支。
3. 拟合只改物理量的**数值**，不加功能、不加倍数、不加形状旋钮。参考视频决定数值，不决定模型。
4. 参数表冻结，加 / 删 / 改含义要用户批准。

## 怎么判（每一行都走一遍）

1. **先看代码再下结论**。`代码位置 / check` 给了行号（可能有偏移，按函数名找）。确认这个参数**实际**做什么——名称表的说明可能过时，和代码不一致的要在理由里写出来。
2. **类别**六选一：
   - `物理量`：有单位、能说出是哪个物理量、出现在模型公式里。例：火花寿命（s）、燃烧温度（K）、阻力（1/s）、粒径（m）。
   - `引擎字段`：直接对应 cascade.json 的某个模块字段或贴图属性。例：贴图尺寸、入点 / 出点、Pivot、格子留边。
   - `预览设置`：只影响工具里怎么看，不进导出。例：显示曝光、预览光晕、构图网格。
   - `拟合旋钮`：为了把画面调得像参考而加的、不对应物理量的形状 / 光感 / 倍数。例：梭形、泪滴星头、线间底光、每档温度偏移、每档拖影倍数、隐藏的曝光比。
   - `兼容开关`：「旧 / 新」「兼容」或 `0 = 以前的做法` 的选项，或者两套帧数 / 取景系统并存里旧的那套。
   - `死代码`：没有效果用（`条目用到` = 0）且代码里不再起作用，或所属产品线已归档（物理尾缀 `ph*`、`trPhys`）。
   - 一行同时像两类（例：既是物理量又带兼容选项）填两个，用「/」隔开，建议里写清楚怎么拆。
3. **建议**：`留` / `删` / `合并到 <key>`（写明合并后的名字、单位、换算）/ `改成常量 <值>` / `上面板` / `改名为 <名>` / `拆成 <a>+<b>`。
4. **理由**：一两句，必须能让没看代码的人信服；引用代码行或条目编号。
5. **画面影响**：`无` / `变：<哪些效果或哪类效果，怎么变>`。判断依据：`条目用到` 列和代码里的默认分支。
6. **四套火花模型的重复概念**要单独找出来合并：同一个物理量在 `cooling / T0 / twinkle`（空中）、`trCool / trIgnite`（V5）、`phBT0 / phBTb / phBTc / phBTend`（物理尾缀）、`rtT0 / rtTb / rtTc / rtTend / rtTw`（升空尾缀）里各有一份——每组给一个统一名、单位、默认值和换算关系。
7. **不要客气**：用户要的是一张能直接执行的表。模棱两可的行最多留 30 行，单独列成「有争议」并写出两边的理由。
8. 不许做的事：不改 `tool/src`、不改 `analysis/命名/*`、不改条目、不改 `协作/状态清单.json` 里别人的字段、不 force push。
